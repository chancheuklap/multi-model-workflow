# 可视化解释

先完整读取用户要求解释的方案、文档或回复。根据当前对话确定要解释的范围。

可视化解释必须完整覆盖用户要求解释的内容。沿用其中的术语和表达，不创造新术语、缩写或代号。内容涉及仓库时使用领域上下文中的 canonical 术语；存在冲突时显示冲突。

以图、表和交互为主，只使用必要的标签、短说明和出处。让读者尽量不打开要解释的内容也能看懂。

## 路线一：完整 HTML

这是默认路线。生成完整 HTML。要解释的内容已经落盘时，本地 HTML 与它放在同一目录并使用同名 `.html`；内容只在对话中时，把内容和本地 HTML 一起保存在同一个文件夹。

**宿主动作待实现：`publish-visual-explanation`。**当前宿主保留本地 HTML，并明确报告 Sites 发布尚未实现。

这条路线完成时，本地 HTML 已保存并能打开，同一个 Sites 网站已经保存本次更新的新版本。发布失败时保留本地 HTML，并明确报告 Sites 未完成。

## 路线二：对话内可视化

只有用户要求解释的范围非常精确、非常小，而且一个紧凑的图或表可以完整讲清时，才使用这条路线。

**宿主动作待实现：`render-inline-visual-explanation`。**当前宿主明确报告对话内可视化尚未实现。

这条路线完成时，HTML fragment 已在对话内显示，并完整覆盖用户要求解释的范围。
