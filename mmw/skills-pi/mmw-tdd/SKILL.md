TDD 就是 red → green 这个循环。本技能是让这个循环产出值得留下的测试的那份规矩：什么算一个好测试、测试放在哪、哪些写法不能要、循环本身的规矩。**每一节在每一轮循环上都适用**——在循环之前和循环之中查阅它们，不是循环之后。

探索代码时先运行 `mmw domain path`，按它返回的领域文档形态读取本次范围。测试名和 interface 用词必须与项目领域语言一致。还要遵守本次范围内的 ADR。

## 三层合起来才是全套

关于测试的要求分三层，写一个测试之前三层都要在手上。

| 层 | 在哪 | 装什么 |
| --- | --- | --- |
| 怎么写 | 本技能，加 [tests.md](tests.md)、[mocking.md](mocking.md) | 什么算好测试、哪些写法不能要、边界上怎么 mock。带代码例子，任何仓库都适用 |
| 够不够格进仓库 | [quality-bar.md](quality-bar.md) | 一条一条的资格线、禁止形态表、准入问题。这是关卡，不是建议 |
| 这个仓库的事实 | 目标仓库根的 `TESTING.md` | 测试目录怎么分层、哪些边界算外部因而允许打桩、值的唯一事实来源在哪、整套测试怎么跑 |

**仓库的事实只补事实，不覆盖前两层**：`TESTING.md` 不能豁免一条资格线，也不能放行一种禁止形态。

**开工前先把 `TESTING.md` 读出来。** 它不在仓库根，就先读目标仓库自动加载的 `AGENTS.md` 或 `CLAUDE.md`——测试治理文档可能被指到别的位置。**不要因为根目录没有这个文件名，就当作这个仓库没有测试规则**；找不到才按前两层做，并在报告里说一句这个仓库缺第三层。

## 什么算一个好测试

测试通过公开接口验证**行为**，不验证实现细节。代码可以整个换掉，测试不应该跟着变。一个好测试读起来像一份规格说明——「用户带着有效购物车能结账」一句话就说清了存在什么能力——而且它能活过重构，因为它不关心内部结构。

例子见 [tests.md](tests.md)，打桩的界限见 [mocking.md](mocking.md)，一个测试要够到哪条线才允许进仓库见 [quality-bar.md](quality-bar.md)。

## seam —— 测试放在哪

**seam** 是你下断言的那个公开边界：在这个接口上观察行为，不伸手进内部。测试住在 seam 上，绝不对着内部写。

**只在事先谈定的 seam 上写测试。** seam 在 spec 里跟用户谈定，在任何代码存在之前——`/mmw-to-spec` 第 3 步就是干这个的。从那里读出来，就在那些 seam 上测。没有人同意过的 seam 上不写测试。

没有 spec——你是被直接叫来做一个具体行为的——就把你要测的 seam 写下来，跟用户确认过再写测试。问他：「公开接口是哪个，我们该在哪几个 seam 上测？」

seam 已经谈定，但这次的活需要一个 spec 没写到的，**停下来说明**。不要在写的过程中自己发明一个 seam。派出去的 `worker` 没有人可问，在这里同样要停。

interface 的形状本身还没定时，完整读取 `/mmw-codebase-design`，使用它的 module、interface、depth、seam 和 adapter 词汇澄清边界。它是词汇与判据 reference，不是让 TDD 另开设计流程。Spec 已经确认 interface 和 seam 时，直接执行该决定，不在 TDD 中重新设计。

## 不能要的三种写法

| 写法 | 识别方法 | 正确做法 |
| --- | --- | --- |
| 跟实现绑死 | 给内部协作者打桩、测私有方法或从侧面验证，例如绕过 interface 查数据库；重构后测试失败但行为未变 | 通过公开 interface 验证行为 |
| 同义反复 | 断言按代码的同一种算法重算预期值，例如 `expect(add(a, b)).toBe(a + b)`、按相同算法生成快照、断言常量等于自身 | 预期值来自已知正确字面量、手工样例或 spec |
| 横切 | 先写全部测试，再写全部实现；测试会固定想象中的结构，而非用户行为 | 竖切：一个测试、一份最小实现，再进入下一轮；每个测试是一颗 tracer bullet |

## 循环的规矩

- **先红后绿。** 先写那个失败的测试，然后只写刚好够它通过的代码。不要预判后面的测试，不要加还没人要的功能。
- **一次一片。** 一个 seam、一个测试、一份最小实现，构成一轮。
- **重构不属于这个循环。** 它归审查（见 `/mmw-review`），不在 red → green 这轮里。

下表准备移交下一技能时，先读 [`../mmw-start/phase-boundaries.md`](../mmw-start/phase-boundaries.md)，按顺序判断是否留在当前会话。自己继续和因 blocker 停下不触发阶段边界判断。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 这一片走完了 red 到 green，还有下一片 | **自己继续**：回本文「循环的规矩」一节，取下一个 seam |
| 这次的活全部走完 | **移交**：回到把你叫起来的那个技能，由它决定验收和发起审查 |
| 这次的活需要一个 spec 没写到的 seam | **停**：说清楚缺的是哪个 seam、你本来打算断言什么。派出去的 `worker` 在这里同样要停，把这件事写进完工报告，不要自己发明一个 |
