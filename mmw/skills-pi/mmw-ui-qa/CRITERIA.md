# 判据与判拒

## 判据五种，生产方各不相同

| # | 判据 | 形态 | 谁生产 | 供给哪几种判拒 |
| --- | --- | --- | --- | --- |
| 1 | 阈值表 | JSON，仓库一份 | 界面 QA。intake 问卷建立，裁决结果追加 | A1 |
| 2 | 可用性判据 | Markdown，每个产品一份 | 界面 QA。问卷、从共同理解与 spec 抽取、裁决结果回流 | B5 |
| 3 | 设计系统 | 标准格式的文件 | **目标仓库**。技能只读 | A3、B1 |
| 4 | 可访问性规则集 | 规则引擎自带 | 规则引擎 | A2 |
| 5 | 方法判据 | 写在 [SEMANTIC.md](SEMANTIC.md) 正文里 | 本技能自带 | B2、B3、B4 |

第 5 种不是目标仓库的配置，任何装了 MMW 的仓库直接具备。

**设计系统是只读边界。** 界面 QA 读它，不写它，所有权属于目标仓库。唯一的例外是它不存在时建一次，见下。

## 两类九种判拒

分类依据是**判定性质**，不是判据载体：确定性检查的结果是事实，模型判断的结果是候选。九种是封闭集合。

**A 类 —— 确定性检查，产出违规项，直接修改，不占用用户时间**

| 编号 | 判什么 | 判据来源 |
| --- | --- | --- |
| A1 | 数值越过阈值表的下限或上限 | 阈值表 |
| A2 | 可访问性规则引擎报出的违规 | 规则引擎自带规则集 |
| A3 | 元素用的 token 不在设计系统**声明**的集合里 | 设计系统的机器可读部分 |
| A4 | 渲染进程控制台里的运行时错误 | 无，报错本身就是事实 |

**B 类 —— 模型判断，产出 finding，只报告，等用户裁决**

| 编号 | 判什么 | 判据来源 |
| --- | --- | --- |
| B1 | 违反设计系统正文里的具名规则 | 设计系统的散文部分 |
| B2 | 认知走查四问任一答不出 | 方法判据 |
| B3 | 困惑分偏高 | 方法判据 |
| B4 | Trunk Test 六问任一答不出 | 方法判据 |
| B5 | 违反该产品的可用性判据 | 可用性判据 |

**三类报告项不是判拒**：覆盖报告、判据自检结果、声明与实现不一致。它们是确定的事实，但没有界面上的修复目标，因此不进用户裁决，也不驱动修改。

产生新的确定性事实但没有界面修复目标时，加成报告项，不加成判拒。

## A3 判的是声明层

设计系统文件是**声明**（人写下的意图），运行时的 CSS 变量是**实现**（实际生效的）。A3 这条判拒叫「设计系统 token 越界」，它判的就必须是「元素用的值在不在设计系统声明的集合里」。

改用实现层会让它名不副实：实现层多出一个设计系统没声明的 token 时，用这个 token 的元素反而通过 A3，而那恰恰是越界。

**实现层照样要读，用途是判断判据可不可信。** 两组键值对比一比，成本几乎为零：

| 对比结果 | 怎么处理 |
| --- | --- |
| 实现层有、声明层没有 | 这个 token 未经声明。作为报告项报一条（**按 token 报一条，不按使用它的元素逐个报**）。用到它的元素同时被 A3 判为越界，因为它确实不在声明集合里 |
| 声明层有、实现层没有 | 声明已经过时。作为报告项报一条 |

**不一致的条目多到一定程度时，报告必须写出「A3 的结果可能失真」。** 把脱节暴露给用户，不要偷偷换一个判据来源。

报告中同时给出一条建议：设计系统的官方命令行工具支持把 token 导出成构建配置能直接用的形式，目标仓库改成从声明生成实现之后，这类不一致不会再出现。**这只是建议，不替目标仓库改构建流程。**

## A2 的实际覆盖面

规则引擎覆盖对比度、ARIA 误用、缺 label、缺 alt、`tabindex` 取值、`aria-hidden` 元素可聚焦、嵌套交互控件、可滚动区域可达性、跳过链接。

**它不验证实际键盘遍历顺序。** 引擎里与焦点顺序同名的那条规则是实验规则、默认关闭，而且只检查已在焦点序列中的元素角色是否适合交互内容，不追踪按 Tab 时焦点实际走的次序。**必须在报告中声明这一点**，不得让用户以为焦点顺序已被覆盖。

## 建立模式：intake 问卷

**只问技能查不到的，七个问题一次问完。**

技能自己能查到的不问：设计系统文件在不在、声明了什么组件规格、应用怎么启动（构建配置里的脚本）、界面有哪些（代码抽取建全图）、用户在 `/mmw-grilling` 和 spec 里说过的可用性要求。

| # | 问什么 | 技能先做什么，好让用户少打字 |
| --- | --- | --- |
| 1 | 这个产品给谁用、在什么场景下用 | 从 spec 或共同理解抽一段草稿，用户改 |
| 2 | 哪几条是核心流程 | 列出全图里从主窗口出发的可达路径，用户挑 |
| 3 | 哪些元素是刻意做小的展示型元素 | 扫出所有小于通用下限的元素列成候选，用户勾 |
| 4 | 启动方式对不对 | 从构建配置读出候选命令，用户确认或改 |
| 5 | 这个产品跑在哪个环境：本机起的服务，还是真实服务器上的测试账号 | 无法预填。**两个选项二选一，没有第三个** |
| 6 | 登录态与测试数据怎么准备 | 无法预填。答不上来记为空，相关状态进覆盖报告 |
| 7 | Windows 远程调试端口 | 给默认值，用户改或留空 |

第 5 问是数据安全的唯一保障。项目落地后跑 QA 时，走查任务是完整用户路径且至少含一条失败路径，会真的点下去——真的新建、真的提交、真的触发错误。本地服务器和测试账号都与生产数据隔离，所以**不需要禁止操作清单，也不需要为不可逆操作逐个停下来问用户**。

**从共同理解与 spec 抽取的可用性判据一次性展示，默认全部接受，用户划掉不要的。** 不逐条确认——那是「一项一项盯」。也不静默采用——抽取是模型判断，抽错的条目会变成长期判据，每轮都拿它判 B5。抽取结果跟着问卷一起给用户看，不额外增加一次交互。

## 四份缺失的性质不同

| 缺哪一份 | 性质 | 用户拒绝建立时 |
| --- | --- | --- |
| 阈值表 | 必须建 | **停止**。A1 没有判据，而它是最基础的一层 |
| 该产品的可用性判据 | 必须建 | **停止**。B5 没有判据，而这一层承载「贴合真实工作流」这个核心目标 |
| 该产品的接线文件 | 必须建 | **停止**。应用启动不了，九种判拒一种也跑不了 |
| 设计系统 | **提议建** | **继续**。跳过 A3 与 B1，其余七种照常运行，报告顶部声明跳过原因 |

设计系统单独一档，因为缺了它只影响两种判拒，而缺前三份中任何一份技能都跑不起来。

**建设计系统的三条硬约束：**

1. 用标准格式写。
2. 内容来自 intake 问卷与 MMW 已有产物，**不从运行页面提取当前值**——那是逆向抽取，会把当前的缺陷固化成标准。
3. 建完立刻转只读，此后永不再写它。

## 三份跨边界数据的字段

三份都必须带 `version` 整数字段：格式变化时据此认出旧文件并说明，而不是静默误读。界面全图不在其列——它在进程内构建，不跨边界。

`version` 的处理：认识的版本号写在本文；读到更大的版本号时停止并说明文件由更新版本的技能写成；读到更小的按当前版本读取，并在报告中留一行提示。文件损坏或不是合法 JSON 时停止，写出解析器的原始错误，不猜测内容。

**未知内容按设计系统格式规范给出的那张消费者行为表处理**，不另立一套：未知的段落保留、不报错；未知的键，值合法就接受；未知的属性接受但在报告中留一行提示；重复的同名段落报错并拒绝该文件。这四条不是我们发明的容错规则，是我们已经依赖的那份规范自己定义的消费者行为。

### 接线文件 · 归属方是目标仓库

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `version` | 整数 | 是 | 格式版本 |
| `product` | 字符串 | 是 | 产品标识。小写字母、数字与连字符，与可用性判据的文件名一致 |
| `launch` | 对象 | 是 | 见下 |
| `mainWindow` | 对象 | 是 | 见下 |
| `environment` | 对象 | 落地后那一档必填 | 见下 |
| `prepare` | 对象 | 否 | 见下。缺失时相关状态进覆盖报告 |
| `designSystem` | 字符串 | 否 | 设计系统文件的仓库相对路径。缺失时跳过 A3 与 B1 |
| `windows` | 对象 | 否 | 见下。只在 Windows 侧运行时需要 |

五个对象的内部字段：

| 对象 | 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `launch` | `command` | 字符串数组 | 是 | 启动命令与参数，逐个元素一项，不是待解析的整行 |
| `launch` | `cwd` | 字符串 | 否 | 仓库相对路径。缺省为仓库根 |
| `launch` | `env` | 字符串到字符串的映射 | 否 | 启动环境变量。值可以是凭证引用 |
| `launch` | `readyTimeoutMs` | 整数 | 否 | 等待主窗口出现的上限。缺省 30000 |
| `mainWindow` | `titlePattern` | 字符串 | 二选一必填 | 匹配窗口标题的正则 |
| `mainWindow` | `urlPattern` | 字符串 | 二选一必填 | 匹配渲染进程地址的正则 |
| `environment` | `kind` | 枚举 | 是 | `local-server` 或 `test-account` |
| `environment` | `endpoint` | 字符串 | 是 | 本地服务器地址，或真实服务器地址 |
| `environment` | `account` | 对象 | `kind` 为 `test-account` 时必填 | 测试账号的标识与凭证引用 |
| `prepare` | `steps` | 对象数组 | 否 | 每项含 `name` 与 `command`（字符串数组），按顺序执行 |
| `windows` | `debugPort` | 整数 | 是 | 远程调试端口 |
| `windows` | `host` | 字符串 | 否 | 缺省 `127.0.0.1` |

`environment` 缺失或 `kind` 不是这两个值时，落地后那一档停止并说明。prototype 阶段那一档不要求这个字段——那时检查的是 mockup 或开发模式启动的应用，本来就不连生产。

**凭证只存引用，不存明文。** 引用的结构是固定前缀加名字：`env:<环境变量名>` 或 `keychain:<条目名>`。运行时按前缀取值。**写成其他形态的一律当作明文拒绝，并停止运行。** 必填字段缺失时按主文件的下一步表处理，不填默认值。

### 阈值表 · 归属方是界面 QA

仓库一份。除 `version` 外，顶层是阈值项的映射，每项四个字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `value` | 数值 | 是 | 阈值 |
| `unit` | 枚举 | 是 | `px` 或 `ratio`。不接受无单位裸数 |
| `appliesTo` | 枚举 | 是 | `interactive`（可点击元素）或 `presentational`（展示型元素） |
| `compare` | 枚举 | 是 | `min` 或 `max`。决定「小于算违规」还是「大于算违规」 |

后两项不能省。`appliesTo` 区分可点击与展示型，`compare` 说明比较方向——同一个数值在缺少比较方向时无法判定。

**初始值必须与目标仓库既有组件规格对齐，不照搬通用值。** 项目里常有高度低于常见触控下限的展示型组件，直接套用通用下限会把它们误判成违规。

### 可用性判据 · 归属方是界面 QA

每个产品一份。每条判据六项：

| 字段 | 必填 | 内容 |
| --- | --- | --- |
| 编号 | 是 | 条目标识 |
| 正文 | 是 | 判据内容 |
| 来源 | 是 | 从哪次讨论、哪份 spec 或哪次界面 QA 来 |
| 状态 | 是 | 「已确认」「已裁决不成立」「已搁置」之一，对应用户裁决结果 |
| 指纹 | 由裁决产生的条目必填 | [VERDICTS.md](VERDICTS.md) 四种形态之一。技能自动生成 |
| 最后命中 | 由裁决产生的条目必填 | 这条最近一次被第 1 级或第 2 级匹配命中的日期 |
