开始前按 `/mmw-domain-modeling` 的「读领域文档」读取领域文档，并使用其中的术语。

prototype 用持续迭代的可运行资产回答只靠讨论无法判定的问题。每轮只回答一个可走查的问题，并原地改进同一份 prototype。

## 1. 确定本轮问题

从用户任务、现有讨论或 prototype 提炼一个初始问题。读取相关材料后，把最终验证问题写入 `README.md`。

| 当前情况 | 处理 |
| --- | --- |
| 问题还不能走查 | 移交 `/mmw-grilling`，谈清后返回 |
| 要验证外部系统的真实表现 | 移交 `/mmw-research`，并传递 `产物目录` |
| 必须运行我们要写的资产才能回答 | 继续第 2 节 |

## 2. 确定资产位置

| 调用方式 | `prototype 产物路径` | `scratch 路径` |
| --- | --- | --- |
| 普通任务 | `docs/prototypes/<产物目录>/` | `.scratch/<产物目录>/` |
| Wayfinder decision ticket | `docs/prototypes/<产物目录>/issue-<编号>/` | `.scratch/<产物目录>/issue-<编号>/` |

`产物目录` 使用调用方提供的值或当前任务 slug。它必须是单个安全路径段。当前没有任务时停止。

写文件前运行 `mmw task state`：

| 状态 | 动作 |
| --- | --- |
| `bound` | 继续使用当前任务 worktree |
| `detached` | 运行 `mmw task bind <分支名> "<用户原话>"` |
| `local` 或 `outside` | 运行 `mmw task new <slug> "<用户原话>"`，再切换到返回路径 |

命令失败或工作区不干净时停止。

`prototype 产物路径` 使用以下结构。目录有资产时再建立：

```text
<prototype 产物路径>/
├── README.md              运行方式、逐轮问题、用户走查结论、选中产物和精确对应关系
├── logic/                 后端脚本、接口合同、可移植逻辑和 Logic HTML
└── mockup/
    ├── current/           当前选中并持续优化的 UI mockup
    ├── variants/
    │   └── <问题 slug>/
    │       ├── preview/   这一组变体的运行入口和切换器
    │       └── <变体 key>/ 完整变体或局部变体
    └── assets/            current 与变体确实共用的资源；没有时不建立
```

过程截图、DOM、console、录屏和中间物写入 `scratch 路径`，不进 Git。`README.md` 记录问题、运行方式、走查结论和选中资产。

## 3. 选择工作面

每轮只选择当前问题需要的工作面：

| 当前问题 | 处理 |
| --- | --- |
| 查看一次数据、接口或转换输出就能判断 | 在 `logic/` 中编写最小可运行脚本、合同样例或样例数据 |
| 必须由用户用按钮驱动状态模型，而且没有合适产品界面 | 完整读取 [LOGIC.md](LOGIC.md) |
| 涉及页面、操作流程或 UI/UX | 完整读取 [UI.md](UI.md)，按 UI mockup 工作面执行 |
| 同时需要多个工作面 | 先完成最能回答当前问题的一个；需要用户决定时再询问 |

后端 prototype 提供输入和输出，并覆盖与问题相关的失败、空值和边界输入。

## 4. 共同规则

1. **标明 prototype。** 在文件名、页面标题或路由中显示其身份。
2. **写明运行方式。** 把精确命令和入口写进 `README.md`。
3. **默认把状态保存在内存。** 当前问题涉及持久化时，才接临时数据库或明确标记的本地文件。
4. **只做当前问题。** 不补测试、无关错误处理或抽象。
5. **呈现完整相关状态。** 每次逻辑动作、界面状态变化或变体切换后，都显示用户判断当前问题所需的完整状态。
6. **原地迭代。** 后续轮次修改同一份 prototype，保留已经确认的状态、交互和文案。
7. **保存问题和答案。** 用户反馈后读取 [capture.md](capture.md)。

## 5. 用户走查

把可运行资产交给用户操作。每个变体 key 使用一个独立 URL。

| 当前宿主能力 | 打开方式 |
| --- | --- |
| 宿主提供内置浏览器 | 用内置浏览器打开并保留全部页面 |
| 宿主没有内置浏览器 | 用 Playwright 打开；`playwright-cli` 先用 `open`，其余 URL 用 `tab-new` |
| 两者都不能留下用户可操作页面 | 停止并说明缺少可用浏览器 |

主 agent 先确认页面已加载，并把截图写入 `scratch 路径`。保留用户可操作页面；收到反馈后读取 [capture.md](capture.md)，没有反馈时停止等待。
