需求理解到能起个名字就建树，深入的对话放进第一个阶段做。

## 怎么做

1. 从需求提炼一个短横线连写的任务名，只用小写字母、数字和短横线。名字要能一眼认出这是哪件事。
2. 把 `.mmw/` 加进主仓库的忽略清单并提交（已有就跳过）。
3. 建工作树：`git worktree add .mmw/worktrees/<任务名> -b <任务名>`，从当前 HEAD 分叉。
4. 在新工作树里写 `.mmw/task.json`：

```json
{ "task": "<任务名>", "phase": "wayfind", "base": "<分叉时的完整 sha>", "note": "", "design_approved": null }
```

5. 同目录建空的 `.mmw/sidelines.md`：往后任何一个阶段撞到本次范围外的问题，就往里记一行——现象、位置、为什么这次不做。收尾那个阶段摊开它挑哪些开成 issue。
6. 告诉用户任务名、工作树在哪、现在停在探路阶段，接着读 `mmw-wayfind`；小到不用探路的改动，让他敲 `/mmw-next <阶段>` 直接跳过去。

---

## 线下 · 不是技能内容

**忽略清单为什么必须在建树之前提交**：工作树若从一个还没忽略 `.mmw/` 的提交分叉，状态文件会以未跟踪身份出现在工人的改动里，收工核越界时分不清哪些是工人改的。

**为什么催着建树**：状态文件没地方存之前，聊多少轮都在盘外，关掉会话就没了。

### 施工单

- **来源**：`plugin/scripts/prepare.sh`、`plugin/state-schema/routes.json` 的 entry_policy
- **保留**：建工作树、起名、写状态、分支从父 HEAD 分叉
- **删除**：入口能力判定那六种治理能力与「须给用户原话当证据」；场景预设选择；三十九字段任务档案
