把需求变成任务名，建工作树与状态文件，落在查清现状那一格。尽快建树，不在无状态区久留——建树之前的对话全在盘外。

## 怎么做

1. 从需求提炼一个短横线连写的任务名，只用小写字母、数字和短横线。名字要能一眼认出这是哪件事。
2. 先把 `.mmw/` 加进主仓库的忽略清单并提交（已有就跳过）。工作树与状态都住在这里面，不能进版本库。**这一步必须在建树之前**：否则工作树从一个还没忽略 `.mmw/` 的提交分叉，状态文件会以未跟踪身份出现在工人的改动里，收工核越界时分不清。
3. 建工作树：`git worktree add .mmw/worktrees/<任务名> -b <任务名>`，从当前 HEAD 分叉。
4. 在新工作树里写 `.mmw/task.json`：

```json
{ "task": "<任务名>", "phase": "investigate", "base": "<分叉时的完整 sha>", "note": "", "design_approved": null }
```

5. 同目录建空的 `.mmw/sidelines.md`。
6. 告诉用户任务名、工作树在哪、现在停在查清现状那一格，接着读 `mmw-investigate`。

**尽快建树**。理解到能起个名字就动手，深入的对话进第一格再做——建树之前的每一轮都在盘外，关掉会话就没了。

## 施工单

- **来源**：`plugin/scripts/prepare.sh`、`plugin/state-schema/routes.json` 的 entry_policy
- **保留**：建工作树、起名、写状态、分支从父 HEAD 分叉
- **删除**：入口能力判定那六种治理能力与「须给用户原话当证据」；场景预设选择；三十九字段任务档案
