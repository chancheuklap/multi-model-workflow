需求聊到能起出任务名就建树，深入的对话放进第一个阶段做——建树之前聊的每一轮都在盘外，关掉会话就没了。

## 怎么做

1. **拆参数**：第一个词是阶段名就当起点，其余全是需求；第一个词不是阶段名，整串都是需求，起点用 `mmw-wayfind`。
2. **起任务名**：动作加对象，短横线连写，只用小写字母、数字和短横线，像 `fix-payment-retry`、`add-oauth-login`。`update`、`refactor`、`task-1` 这类泛称隔一个月认不出是哪件事。
3. **建树之前把任务名与起点念给用户，等他改或者点头。**这两样建了树就写进分支名与状态文件，再改要拆掉重来。

   用户没给起点时，说明这次默认开在探路，再摆出另外两种常见起法：修一个已知的 bug、要先找根因，开在查清现状；改哪、怎么改都已经清楚，开在落地。
4. 回主仓库跑这一句，起点填那个阶段技能的名字：

   ```bash
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/task.sh" new <任务名> <起点技能名>
   ```

   忽略清单、工作树、`.mmw/task.json`、`.mmw/sidelines.md` 由它一次落齐，输出头四行是任务名、工作树路径、分叉点、起点。
5. `EnterWorktree({ path: "<上一步回的工作树路径>" })`。这个任务往后每一步都在那棵树里干：状态、旁路清单、代码改动都在那儿，留在主仓库下一份技能读不到状态。
6. 把用户的需求原话，连同这次开在哪个阶段、为什么，写进 `.mmw/task.json` 的 `note`。需求原话没有别的地方存得下，新会话敲 `/mmw` 只念得出这一句。
7. 读起点那个阶段的技能，接着干。

## 线下 · 不是技能内容

**`${CLAUDE_PLUGIN_ROOT}` 在技能正文里会被换成插件的安装目录**（官方插件参考的替换表：Skill and agent content — anywhere the placeholder appears）。旧插件那段读 `installed_plugins.json` 找激活安装位的定位块因此不搬，命令直接写绝对路径。

**来源**：`plugin/scripts/prepare.sh`（315 行）——建工作树、从当前 HEAD 分叉、回执点名 `EnterWorktree` 照它；它第 8 行「路由由 LLM 当场判，不在本脚本」与这里脚本只校验拼写的分工一致。

**起点是个参数，不是一套判断**：用户给什么脚本写什么，脚本只校验拼写。补全提示只列三个开得了工的——其余六个各自要有上一阶段的产物才成立，一棵刚建好的树里没有。默认探路对新做一件东西成立，对修 bug 与小改动不成立，那两类靠建树前那一句改口。

**没搬的**：入口能力判定那六种治理能力与「须给用户原话当证据」——敲了这个命令就是要用；三十九字段任务档案；`routes.json` 的场景预设——起点是一个阶段的名字，不是一串预定的阶段序列。
