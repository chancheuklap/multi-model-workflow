工作树已经建好，`phase` 是 `mmw-fix`，用户要做的事写在 `.mmw/task.json` 的 `note` 里。

这条路上你自己写代码，不派 `executor`，也不做设计、不切片、不写计划。

## 步骤

1. **先查清楚。**这次要查的是：坏行为的根因在哪里，或者要改的是哪一处、动了它谁会跟着变。怎么查、复现不了怎么办，读 `mmw-evidence`。

   范围窄（就一个函数、一个已知文件）你自己查完。要追的线索有好几条、彼此不依赖，就派 `scout` 去查，怎么派读 `mmw-dispatch`。

   这一步只读代码，不动手改。

2. **修的是 bug，而只读那几招没造出会变红的信号**：这条路上工作树是你的，还能往下走一层。

   - 写一条会为这个 bug 变红的测试，或者搭一个一次性的最小环境，把出 bug 那条路径单独跑起来。
   - bug 是在两个已知状态之间冒出来的，切到旧版本跑同一个输入、diff 两边的输出；两头都清楚就把「切到状态 X，跑一次，看结果」写成一条命令交给 `git bisect run`。
   - 非得有人点鼠标才出得来的，把 `scripts/hitl-loop.template.sh` 复制一份、改成这次要用户走的步骤，让他跟着提示做，脚本会把他的回答按 `键=值` 打出来给你接着用。人当手，你当脑。

   拿到红信号就回第 1 步，照 `mmw-evidence` 接着提假设、逐个排除。这几招也拿不到，照 `mmw-evidence` 向用户要那三样。

3. **查完先分岔。**

   - 确实只是一处小事 → 往下做第 4 步。
   - 是系统性的问题（要重做设计，或者要拆成好几件活）→ 告诉用户一句这不是改一处能了结的事，然后自己调 `mmw-back` 回探路。回去之前在 `note` 里写明你查到了什么、为什么要回去。工作树不用重开，已经查到的事实留着接着用。

4. **动手之前把三样念给用户，等他回一句你再改**：你查到了什么、打算怎么改、影响面到哪里。这是这条路上唯一一次停下来等人。

5. **改。**第 2 步已经有一条会红的测试就直接用它；还没有就先写一条——修 bug 就是按根因写一条复现测试——再用最小的改动把它转绿，然后提交。改动跨好几个文件的话，自己先写一份计划把活理清楚再逐条做，不派 `plan-writer`，也不进计划审。路上撞到的、这次范围之外的问题记进 `.mmw/sidelines.md`，不顺手修。

6. **请用户敲 `/mmw-review 落地` 起终审。**终审要他自己起，你不代敲。这句话里的「落地」要念给他听——审查认的是主干阶段的名字，`mmw-fix` 不在那张表上，他不点名就对不上。

7. **终审过了，请用户敲 `/mmw-next 出包`。**那一份带着他跑开发模式下的功能测试和装完之后的测试。这个仓库没有安装包可出，就请他敲 `/mmw-next 收尾`。

## 线下 · 不是技能内容

**为什么这不是一个入口**：用户只敲 `/mmw-start`，`fix` 写在需求前面，路由由那一份做完。再给它一个斜杠入口，等于要用户先自己判断这件事够不够小——那正是这一份第 1 步查完才知道的事。

**`phase` 存 `mmw-fix` 而不是某个主干阶段**：这条路整程都在这一份底下——查、确认、改、起终审，中间不换阶段。存成落地那一格的话，新会话读到的是「派工人写码」那套，与这条路要干的事对不上。

**修一个 bug 与改一处已知的地方是同一条路**：动作是同一串——先查清、再确认、再最小改动转绿。差别只在第 1 步查的是根因还是改动面，而怎么查整份在 `mmw-evidence` 里，分成两条只是把同一串步骤抄两遍。

**来源**：旧插件 `plugin/skills/orchestrate/references/scenario/bug.md` 与 `small-change.md`（各 88 行，其中三分之二是四份场景共享的引擎锚点块；两条各自专属的只有开头那几行加动手前那一次轻确认）。

**要写盘、要动工作树的那几招为什么归这一份**：`mmw-evidence` 是只读的调查手艺，`scout` 写不了盘也切不了分支，切旧版本 diff、`git bisect run`、请用户按提示操作，它一样都做不了。这条路上主线程握着自己的工作树，是唯一既在查 bug 又能动手的地方。`mmw-investigate` 不接这一层：查现状撞到复现不了就照实写进报告，深挖到要搭 `git bisect` 的程度已经不是摸清现状，该开一条 `fix`。`scripts/hitl-loop.template.sh` 原样搬自上游 `vendor/mattpocock-skills/skills/engineering/diagnosing-bugs/scripts/`。

**没搬的**：场景预设的阶段序列与强制走完；`--entry-capability` 那六种治理能力与原话取证；`mmw task escalate --to develop` 这条升级命令——回上游走 `mmw-back` 就是了，不另立一个动词；值守档与它带来的「afk 也要停这一次」的说法。
