# 取证原型

另外三条 branch 验的是**我们自己要写的东西**——那套状态模型、那个界面、那份数据形状。这一条验的是**我们要依赖的外部系统**：它在我们的负载、我们的数据、我们的账号下实际表现如何。

适合的问题长这样：

- 「那个服务撑得住我们的并发吗？」
- 「这三个候选哪个扛得住？」
- 「这个第三方接口实际返回什么，跟文档说的一样吗？」
- 「这个方案的延迟能压到多少？」

问题是我们自己那套东西成不成立，就走错了，回 [LOGIC.md](LOGIC.md) 或 [UI.md](UI.md)。

## 先判要不要做这一轮

| 走 | 什么时候 | 例子 |
| --- | --- | --- |
| 本文第 1 步到第 5 步 | 要真实运行、要比几个候选、要多轮测量，而且有决定被它卡住 | 选哪个供应商、并发上限定多少、这个第三方接口的实际合同是什么 |
| `/mmw-research` | 读文档、读源码、读规范就能答 | 这个接口支不支持游标分页、这个字段的类型是什么 |
| 自己跑一条命令 | 一次运行就得到答案 | 这个包的实际版本号、这个命令的退出码 |

**只在决定真的被卡住时开。** 不确定就先按 `/mmw-research` 查一轮，查不出来再升级。

## 1. 冻结

把待验证的那条假设，和它卡住的那个决定，写进 spec 的 `## Open Decisions`（还没有 spec 就先记在对话里）。

**只暂停依赖这条事实的分支。** 其余的接着谈、接着做。

## 2. 立计划

写 `docs/evidence/<slug>/<日期>-<对象>-test-plan.md`，四栏：

| 栏 | 写什么 |
| --- | --- |
| 对象 | 测哪几个候选，各是什么版本、什么配置 |
| 口径 | 测什么指标，怎么测，跑几轮，用什么输入 |
| 通过判据 | 什么结果算它通过。**先写判据再跑** |
| 真实环境需求 | 要什么账号、凭证、数据量、网络位置 |

## 3. 真实跑

探测脚本和原始产物落 `docs/evidence/<slug>/runs/<战役名>/`。浏览器上的验证用 `/playwright-cli`。

**这几件事动手之前先问用户**：要用真实凭证、要连生产环境、要在真机上跑、会产生费用、会写入外部系统的数据。他点头再动。

多候选、多轮时：一个对象一个 subagent。只读探测：四栏表后
[[mmw-launch:investigator:none]]
要改探测脚本：四栏表后
[[mmw-launch:worker:worktree]]
收回后按 `/mmw-verifying-agent-output` 验证。只有一两个对象则自己跑。

## 4. 记台账

结论写 `docs/evidence/<slug>/<日期>-<主题>.md`，逐条标证据等级：

| 等级 | 是什么 |
| --- | --- |
| 一手实测 | 你自己跑出来的，指得到 `runs/` 下的原始产物 |
| 官方文档 | 第一方文档或源码写着的 |
| 二手 | 别人的测评、博客、问答 |

**引不出原始产物的结论标「待验」**，不当结论用。

被否掉的候选也留一条：它是什么、为什么否、证据在哪。

台账正文只写结论和指向 `runs/` 的路径，长输出不内联。

## 5. 回填，解冻

结论写进 spec 对应的那条决定，末尾标台账路径。然后从 `## Open Decisions` 里划掉这一条，回到被冻结的那个分支接着谈。

每确定一个结论提交一次。

## 落点

```
docs/evidence/<slug>/
├── <日期>-<对象>-test-plan.md    第 2 步的计划
├── <日期>-<主题>.md              第 4 步的台账
└── runs/<战役名>/                探测脚本与原始产物
```

**这个目录不随 spec 删。** 它记的是外部世界的表现，spec 归档之后仍然成立，而且重测要花钱花时间。

另外三条 branch 的产物落 `docs/prototypes/<slug>/`，两边不混：测出来的数据不塞进原型目录，走查用的界面变体不塞进台账。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 台账记完、结论回填、`## Open Decisions` 里那条划掉了 | **移交**：回到把你叫起来的那个技能 |
| 第 3 步要用真实凭证、连生产环境、上真机、产生费用，或者写入外部系统 | **停**：说清要做什么、影响什么、花多少，等用户点头 |
| 跑完发现候选全都不满足通过判据 | **停**：报测了哪几个、各自卡在哪条判据上，不要自己放宽判据 |
| 测出来的结果要用户走查一套状态模型或者几个界面候选 | **自己继续**：回 [SKILL.md](SKILL.md) 的「一轮只回答一个问题」一节开新一轮，走 [LOGIC.md](LOGIC.md) 或 [UI.md](UI.md)，带上台账里的相关结论 |
| 第 1 步发现卡住的其实不止一个决定，而且互相牵连 | **停**：报是哪几个决定、它们怎么互相牵连，让用户定先解哪一个 |
| 读文档就能答，不需要真跑 | **移交**：`/mmw-research` |
