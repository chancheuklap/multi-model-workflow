开工读三份文档，逐个 Task Pack 严格测试先行，每个 Pack 一次提交，收工回结构化报告。

## 派发这个角色

主线程读这一节，被派的工人读下面的方法论。两档共用这一份方法论，差别只有模型与思考档：

| 档 | 模型 / 思考档 | 什么时候用 |
| --- | --- | --- |
| 标准 | `gpt-5.6-terra` / high | 多数计划 |
| 强 | `gpt-5.6-sol` / medium | 计划自己在复杂度那一行标了要强档：计费、权限、数据迁移这类改错了代价高的活 |

选档不由派活的人临时拍，读计划里那一行。

当前命令行：`codex exec -C <工作树> --sandbox workspace-write --add-dir <主仓库 git 公共目录> -m <模型> -c model_reasoning_effort="<档>"`，提示词走标准输入。放行 git 公共目录是因为不放行工作树里跑不了 git。

派发前先确认这份技能已装进第二模型的技能根，传给工人的文档真实存在——缺装备当场报错，不让工人开工后才发现。

可写范围：计划声明的改动范围内的源码，文档目录禁碰。收工时比对起点提交，越界当场判失败。

派发时另外交代：落哪份计划、设计文档在哪、切片文档在哪、工作树在哪、从哪个提交起算。验收吃跑测试与读 diff 的实证，不吃工人自述。

换宿主时改的是这张表和上面那行命令，方法论不动。

## 施工单

- **来源**：`plugin/skills/worktree-build/SKILL.md`、`references/discipline.md`、`references/when-stuck.md`
- **保留**：落地纪律（不实现计划没写的、跨模块边界传正式契约类型、新增可被外部引用之物按项目机制登记、数据迁移上下对称、遇到目录级覆盖规则先读、改的文件要落在该 Pack 声明的范围内）；卡住协议（同一动作第三次不通就停下报完整尝试历史、计划与现实冲突不自己猜方向、缺输入不填默认值硬上）
- **删除**：与执行账本步账的耦合；派发与续跑的引擎回执格式
