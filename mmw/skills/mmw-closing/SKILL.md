代码已经落地，终审过了。这一步把设计文档搬到它的长期落点，再把工作区收干净。

**Wiki 是这份 spec 之后唯一的唯一事实来源。** 完整约定在 `docs/agents/wiki.md`。本文写这次收尾按什么顺序做。

## 前置条件

四件事必须满足，缺一件就停下说清是哪一件。

| 检查 | 怎么查 |
| --- | --- |
| 你在任务 worktree 里 | `git rev-parse --show-toplevel` 以 `.worktrees/<slug>` 结尾 |
| 终审跑过，采信的 findings 都修完并复审通过 | `.reviews/` 里有终审报告；采信项各自有对应的修复提交 |
| 工作区干净 | `git status --porcelain` 是空的 |
| Wiki 已初始化 | 按 `docs/agents/wiki.md` 的检测命令查。没初始化就停，只能由用户去仓库的 `/wiki` 页手建一页 |

没有 spec 的任务不走这一步。

## 1. 取 Wiki 的工作副本

按 `docs/agents/wiki.md` 的「落点」一节 clone 或 pull 到 `.worktrees/.wiki/`。

## 2. 写这一页

文件名 `Spec-<slug>.md`，抬头、落地信息、spec 正文、计划章节、相关决定这五段各写什么，按 `docs/agents/wiki.md` 的「一页放什么」一节那张表。

内容从这个分支上取：`docs/specs/<slug>/` 的定稿进 spec 正文，`docs/plans/<slug>/` 的每一份进计划章节，一张 ticket 一节。

落地信息这一段写父 spec issue 的链接、这条任务分支的名字、归档日期。**合并的 PR 这时候通常还不存在**，先写分支名，合并之后再补。

相关决定那一段只放指回仓库 `docs/adr/` 的完整链接，绝不把 ADR 复制进来。

slug 相同的那一页已经存在，就是同一份 spec 的演进：覆盖它，在页尾追加一条修订记录。

## 3. 重新生成两个导航文件

`Home.md` 和 `_Sidebar.md` 每次写入后都要重新生成，跟这一页一起提交。

条目从 `.worktrees/.wiki/` 下现有的 `Spec-*.md` 全量取，不要只往旧文件上追加一行。每一页的一句话和落地日期从它自己的抬头和落地信息那两段读。

**页数多的时候把取证派出去**（`/mmw-verifying-agent-output` 的「取证可以派，判定不可以」一节）：给它 `.worktrees/.wiki/` 下的 `Spec-*.md` 清单，让它打开每一页抄回文件名、那句话和落地日期，交回来的是一张表，直接排版进两个导航文件。

## 4. 给用户看，等他点头

**推送到 Wiki 是对外发布的动作。** 把 `git -C .worktrees/.wiki diff` 给他看，等他明确同意再推。

## 5. 推送，验证

推送之后跑 `docs/agents/wiki.md` 的「验证」一节那份清单。**每一条都过才允许往下走**，任何一条不过就停下报告。

## 6. 删本地文档，提交

「验证」一节那份清单全过之后，在任务分支上删掉 `docs/specs/<slug>/` 与 `docs/plans/<slug>/` 并提交。

**`docs/prototypes/<slug>/` 与 `docs/evidence/<slug>/` 不删。**

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 六步都做完 | **停**：用业务语言交代现在什么能用了、什么证明它能用、这份 spec 归档到了哪一页、什么搁置了搁到哪里。分支可以合并了，合并和清理 worktree 由用户批准 |
| 第 4 步用户不同意推送 | **停**：问清他要改哪里，改完重走第 2 步 |
| 第 5 步的验证清单有一条不过 | **停**：报是哪一条、看到的是什么。**不要删本地文档**，也不要重推一遍指望它自己好 |
| Wiki 还没初始化 | **停**：告诉用户去仓库的 `/wiki` 页建一页任意内容。没有 API 能替他建，不要试着绕 |
| 终审还没跑，或者还有采信的 findings 没修完 | **停**：说清缺哪一样。回 `/mmw-implement` 第 7 步发起终审，或者按 `/mmw-review` 第 8 步复审 |
