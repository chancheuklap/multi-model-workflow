# 接入、验证、出错

## 1. 接入一个仓库

配置在仓库根 `.mmw.json` 的 `retrieval.graph` 一节。每一项都可以不写，不写就是不算对应那一类边。

| 项 | 写什么 | 不写会怎样 |
| --- | --- | --- |
| `services` | 后端服务各自的目录，一行一个。服务名取目录名 | 不算请求到接口那类边 |
| `shells` | 桌面壳各自的目录，一行一个 | 不算进程间调用那类边 |
| `topics` | 消息主题的生产方与消费方各在哪个文件的哪个常量里 | 不算消息那类边 |
| `route_probe` | 一个脚本路径，它把本仓库全部路由输出成 JSON | 改用源码扫描。装饰器上写着的路径能拿到，跨多层前缀拼出来的路由可能不全 |

排除哪些路径不在这里配，走仓库根的 `.graphifyignore`，那是检索工具自己的机制。**任务 worktree 的目录必须排除**——每棵 worktree 是一整份代码副本，不排除的话图会翻好几倍，而且全是重复节点。

`route_probe` 输出的每条路由要有六项：服务名、请求方法、完整路径、处理函数名、源文件、行号。它在仓库自己的运行环境里被调起来，不能碰真实用户数据。

## 2. 验证接对了

```bash
mmw graph verify
```

它报每一类边各算出来多少条、路由桥接了多少个、有没有算不出来的。

**判据不是数量本身，是每一类都不能是零。** 某一类是零，说明配置里对应那一项跟代码结构对不上，而不是这个仓库没有那种关系。

再抽查一条：挑一个装饰器注册的接口，用结构查询问它的调用方，应该能走到前端发起调用的位置。走不到就是路由桥没接上。

## 3. 建不出来

| 报的是什么 | 做什么 |
| --- | --- |
| 语言解析器缺失 | 装上它再建。这时的图是残缺的，宁可没有也不要错的 |
| 某一类跨语言边算不出来 | 看第 1 节那张表，对应那一项的配置跟当前代码结构对不上了 |
| 路由桥出现多个候选 | 代码里有同名处理函数。这是真实的歧义，不猜，去看那几处源码 |
| 正在被别的进程建 | 等它，或者直接 `Grep`、`Read` 往下做 |
| 建到一半工作树变了 | 重建一次。中途改动会让图跟代码对不上 |

**任何一种都不是任务的阻塞点。** 记下原因，回文本检索继续做事，在报告里写明这次没用图。

## 4. 任务 worktree

新建的任务 worktree 跟主仓库内容相同时，直接复用主仓库那份图，不重建。内容一旦不同就自己建一份。

worktree 里的图不进版本库，也不同步到别的机器——它是本机派生物，几十兆。
