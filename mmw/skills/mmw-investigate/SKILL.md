把现状查清，产出一份带引用的报告，给后面的方案与设计扎根。**取证不判定**：只摆证据和出处，方案、路线、设计结论都留给 `mmw-propose` 与 `mmw-design`。

全程只读。几路查完、逐条亲验过，主线程才写盘。

## 定题目

跑过 `mmw-wayfind` 的，题目清单在 `docs/design/<任务名>/wayfind/map.md` 末尾「交给 mmw-investigate」那节，照它走。那些决策文件里已经查证过的事实带着出处直接引用，不重派；不够用的当新题目派。没跑过探路就当场定题目。

**一个题目一个 `scout`**，几个一起派还是串着派照 `mmw-dispatch` 的并行判据。窄到一个点（一个函数、一个已知文件）自己 `Read`、`Grep` 查完。

两个方向分开定题，题目不混：

| 方向 | 查什么 | 派的时候多交代什么 |
| --- | --- | --- |
| 内部 | 模块边界、接缝、数据流、根因 | 不用多交代，手艺在 `scout` 已装的 `mmw-evidence` 里 |
| 外部（非必做） | 现有库、已有实现、最佳实践 | 库文档走 context7，其余用 web 检索 |

题目定完先落盘：照 [现状报告的骨架](references/investigation.md) 建出 `docs/design/<任务名>/investigation.md`，只填题目那节，结论留空。**把这一版念给用户**，等他批一句或者改题目再派。方向错了白烧。

## 派与收

派活的提示词只写这次的活：查哪个问题、从哪个角度切。回什么由 `scout` 已装的 `mmw-evidence` 定。

回执收回来怎么筛、怎么亲验，读 `mmw-evidence`。

## 收口

亲验过的事实回填 `investigation.md`，一个题目一节，缺口与丢掉的同时填齐。领域文档归 `mmw-design` 维护，这里不碰。

落盘后告诉用户三样：查了几个题目、报告落在哪、缺口有几个并逐条念出来。缺口里有必须他拍板才能往下的，当场问。

撞到的本次范围外的东西记进 `.mmw/sidelines.md`，不顺手修。

**查着查着发现题目本身问错了**——要决定什么都还说不准、题目答完也定不了任何事——告诉用户敲 `/mmw-back 探路`，别把一份答非所问的报告交下去。

查 bug 收口有两种诚实写法，照实情选一种：

- `scout` 回「没能复现」：把它列的复现路径转给用户，向他要下面三样里的一样——一个能复现的环境；一份捕获的产物（HAR、日志转储、core dump、带时间戳的录屏）；往生产环境加临时埋点的许可。**这个阶段不为了复现去写测试、切版本**，这里全程只读。三样都要不到而这个 bug 又非查清不可，告诉用户这得单开一个任务：敲 `/mmw-start fix <那个 bug>`。
- 复现了但定不到根因：报告里列出已排除的假设与各自的证据，问用户接着排哪一条。

## 线下 · 不是技能内容

**取证手艺为什么不在这份里**：探路解一个查证类决策、`mmw-fix` 定一个根因，用的是同一门手艺。写在这个阶段里，另外两处要用就得跨阶段引用。手艺整份住 `mmw-evidence`，三处平级点它的名字，内部谁读哪一份由它自己分。

**来源**：旧插件 `plugin/skills/orchestrate/references/investigate.md`（60 行，骨架、两个方向、亮计划、亲验与两种诚实收口照它）；`investigate-internal.workflow.js` 与 `investigate-external.workflow.js`（272 行，只取取证过滤这条机械规则）。

**没搬的**：两个 workflow 的编排脚本——并行就是连着派几个 `scout`；检索候选的六字段 JSON 传输合同（方法论里没有任何一步指示谁生成那份数据）；`handoff` 引擎调用与结论词；值守档 attended / afk 的分野，改成一律亮给用户等一句。

**题目清单为什么先落盘再念给用户**：它就是报告的第一版，不另写一份只给用户看的清单。批完直接往里填，关了会话也还在。

**待接的断口**：`mmw-propose` 还没说它读的「现状」就是这份 `investigation.md`，填那份技能时接上。
