# merge：把一条完成的分支并进主线

一条分支已经完成、终审过了，走这一份把它并进主线。解冲突的三条方法论在 `/mmw-integrate` 第 3 步，这里只写 merge 自己的机械。

## 开始

```bash
git merge --no-ff <分支>
```

**`--no-ff` 必须带，squash 禁用。** 这条分支的提交历史是它做过什么的依据，压成一个提交就没了。

## 冲突时哪一边是哪一边

`ours` 是**已经在基上**的那一侧，`theirs` 是**正在被应用进来**的那一侧。merge 的基是你当前所在的分支：

| 标记 | 指的是 |
| --- | --- |
| `ours`、`<<<<<<< HEAD` 那一段 | 主线，你现在站的地方 |
| `theirs`、`>>>>>>>` 那一段 | 正在合进来的那条分支 |

## 完成

解完全部冲突块之后：

```bash
git add <解完的文件>
git commit
```

提交信息保留 git 生成的那句，另起一段写这次解了哪几处冲突、各保了哪一边。

## 放弃

`git merge --abort` 干净回到合并前的提交，工作区不留残留。代价只有已经解掉的那几块要重解一遍。

但 `/mmw-integrate` 的第 3 步要求解出来。判不出保哪一边时按「下一步」那张表停下交给用户，不要用放弃代替判断。
