# 交付前自检与就绪门

> 交回之前读这一份，逐条过。

## 自检（保存前逐条过）

- **检索验证**：符号检索只用来发现候选；plan 里每个关键的路径、类型、函数、fixture 和影响面结论，都已经回到当前代码用检索或读文件验证过。工具不可用或者图过期时如实降级，不要把「没查图」说成被阻塞。
- **spec 覆盖**：逐条扫 spec 和你那张 ticket 的每条需求，每条都能指到一个实现它的任务包；有缺口就补上。
- **类型一致**：后面的包用的类型、签名、字段名跟前文定义的一致。第三包写 `clearLayers()`、第七包写 `clearFullLayers()`，就是一个缺陷。
- **过度设计（要删）**：为一小块新增多个长期对象却只要一个可验证行为；提前塞进将来才要的功能；没有重复的证据就抽公共辅助函数；铺了整套矩阵却没有本包能单独跑的命令。
- **设计不足（要补）**：包里只写「实现功能」没写行为、结果和失败态；只写路径没写归属方、提供方、消费方和合同锚点；界面没有视觉规格；ticket 的验收标准没进包；被阻塞关系没进依赖，或者真串行的写成了并行；改共享合同却没写消费方怎么跟着改、旧用法什么时候下线；红绿步骤的预期结果不清楚；改既有行为却没有现状验证；碰数据却没有回滚办法；验收用了主观语言。
- **覆盖**：spec 的每条意图都映射到某个包；你拆出来的每一小块都映射到一个包；文件与职责表里每条路径都被某个包消费；后文引用跟前文一致；发布风险覆盖了全部有生产风险的包。
- **反模式**：[task-pack.md](task-pack.md) 列的反模式一条都没命中。

## 就绪门（写完每个包检查一遍）

**能进落地的**：对应一个确认过的小块；是可独立验证的垂直切片；写清了拥有哪些文件和各自职责；有 Interfaces 的消费与产出；验收标准能判真假；有本包能单独跑的验证命令；碰合同的有合同锚点；有原型选中的那一版的写了具体视觉规格；有提交边界、风险标记、依赖、复杂度评级；改既有行为的有现状验证和回滚办法。

**不能进落地的**：横切的包（按层分，不能单独验证）；界面只写「实现原型」没写状态和交互；缺目标行为要靠猜；多个人写同一个文件；只写辅助函数没有公开行为；抽不出独立 task（依赖「看上一包」）；需要人决定却标成 AFK。

碰不变量、合同、数据的唯一事实来源或发布风险时，尤其确保上面每条都过。被打回的 findings 自己验证过再改。
