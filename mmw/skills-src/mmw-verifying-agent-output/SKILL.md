---

派出去的 subagent 交回的是报告，不是结论。报告里的事实断言只有带着出处、再经过主 agent 验证，才能成为可用证据。

## 每条关键断言都要有出处

| 产出 | 出处是什么 | 你怎么验证 |
| --- | --- | --- |
| 审查 findings | `file:line` 加该行原文 | 读取该位置，确认原文一致 |
| 完工报告 | 能跑的测试、能读的 diff | 跑一次，读一遍 |
| research 报告 | 可读取的源码位置或一手链接 | 读取报告引用的位置 |

**关于结构关系的断言另有一种出处形式。** 「A 调用 B」「改这里会波及 C」「没有别的地方引用它」，这三类断言 `file:line` 证明不了：它只能证明那一行长什么样，证明不了这一组引用是完整的。装饰器注册的处理函数和动态导入解构出来的符号，文本检索根本看不见，它的空结果和「不存在」是两回事。

所以这类断言的出处是**结构候选**加源码位置：报告写清它从 Serena 或 Graphify 取到了什么，你再回当前源码验证那条关系。只拿得出文本检索结果的，自己取一次结构候选再验证。说「没有别的调用方」却说不清是怎么穷尽的，标 `needs-evidence`。

引不出出处的断言不进交付物，标 `needs-evidence`。

哪条算关键：这条断言如果是假的，会不会改变代码、改变结论、或改变你给用户的交代。关键之外的数字和定位不逐条验证，也不重做 subagent 已经完成的整段 research。

**验证过才采信。它的原话不转发出去，转出去的是你验证之后的结论。**

**结构化的自述不是验证过的结论。** 有些宿主会让 subagent 附一张表，写它跑了哪些命令、输出是什么、自检通过没有。那张表里的每一格仍然是它自己填的，跟正文里的断言同一档，照本文「每条关键断言都要有出处」下的产出/出处/怎么验证表逐条验证。

## 取证可以派，判定不可以

验证是两件事，能拆开：

| | 是什么 | 派不派 |
| --- | --- | --- |
| **取证** | 打开它说的那个位置、把那一行原文抄回来；跑一遍它说的那条命令、把输出贴回来 | **可以派** |
| **判定** | 这条断言成不成立、这一轮值不值得修、要不要写进交付物 | **不派** |

**什么时候值得派取证**：条目多到你逐个打开会撑满上下文。三五条的时候自己打开更快。

派取证时：四栏表——目标「原样抄回下列位置的原文」；读=位置清单路径或逐条 `文件:行号` + 仓库根路径；约束=「不要判断成立与否」；验收=每条一行原文或「不存在」。
派一个独立上下文的 `investigator`。它只读，不需要工作目录。
[[mmw-launch:investigator:none]]

互不依赖的实例在同一条消息里一起启动，全部回来之后再汇总。

它要交回的形状固定：一条位置一行，写那一行的原文加真实行号；位置不存在的写「不存在」；行号对不上但附近有相似内容的，把附近那几行一起抄回来。**不许写「这条成立」或者「这条不成立」。**

**抽检它抄回来的原文。** 从它交回的里挑几条你自己打开验证，尤其挑那些恰好完美支撑 finding 的。抽检对不上就整批作废，自己重来。

## `worker` 交回的四档

| 交回 | 什么意思 | 怎么办 |
| --- | --- | --- |
| 完成 | 它认为做完了 | 照本文「每条关键断言都要有出处」下的产出/出处/怎么验证表来：测试跑一遍、diff 读一遍。验证完了，回到把你叫起来的那个技能。审查 findings 接下来怎么处置，在 `/mmw-review` 第 5 步 |
| 带隐忧完成 | 做完了，但它对某处不放心 | 先验证完成的部分，再单独看它说的那处隐忧。隐忧验证下来是真的：回到调用方，由它决定这处隐忧本轮修还是记账 |
| 缺上下文 | 材料不够，做不下去 | 看它缺什么：你没给全就补齐重派；产物里真的没有，那是上游的问题 |
| 卡住 | 试过了，走不通 | 读它的尝试记录再决定。它说这件事本身太大，处置是**把活拆开**，交回调用方重派。报告里说它缺输入、或者它怀疑自己解错了问题：把它缺的东西或者它的怀疑原样交给用户 |
