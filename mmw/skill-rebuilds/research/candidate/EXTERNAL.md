# 外部 research

本文件只在当前 research 包含外部调查角度时读取。按照 task 点名的问题取得仓库外事实，并把每项断言追溯到拥有该事实的一手来源。

## 选择一手来源

一手来源由事实的所有者决定：

| 事实 | 一手来源 |
| --- | --- |
| 库或框架的行为 | 官方文档和官方源码 |
| API 合同 | API 提供方的正式文档、规范或第一方 API |
| 语言语义或行业协议 | 正式规范 |
| 版本声明和发布行为 | 官方发布记录、官方源码或第一方接口 |

Context7、网页搜索和其他检索工具可以用来定位或读取资料。最终出处必须指向拥有该事实的官方文档、源码、规范或第一方 API，不能停在博客、问答、教程或搜索结果页面。

## 取得事实

只读命令能够直接显示版本、实际返回或命令行为时，可以运行该命令，并保留命令原文和支持断言的关键输出。

如果问题必须制作可持续迭代的可运行资产、让用户操作状态模型，或者验证外部系统的实际行为才能回答，停止当前调查角度并向主 agent 说明需要 `/mmw-prototype`。不要在本调查分支自行建立 prototype。

只报告外部事实。方案选择和产品决定由调用方负责。

| 断言 | 必须引用的内容 |
| --- | --- |
| 库行为、API 合同或规范语义 | 指向具体页面或章节的一手来源链接 |
| 版本、实际返回或命令行为 | 命令原文和支持断言的关键输出；能够引用官方版本记录时同时给出链接 |
| 文档与实际输出不一致 | 文档出处和实际输出，两项都保留并明确区分 |

记录每项外部资料的访问日期和与结论有关的版本。引不出一手出处的内容不写成事实。

## 交回报告

报告按以下顺序书写：

1. task 点名的调查角度和具体问题。
2. 已查明的事实。每项事实紧跟一手出处。
3. 文档、源码、规范或实际输出之间的冲突。
4. 未查清项、未查清原因和已经查过的来源。
5. 访问日期和相关版本。

完成判据：task 点名的每个子问题都有一手来源支持的答案，或者有明确的未查清原因和已经查过的来源。调查范围固定为 task 点名的问题。
