# 内部 research

本文件只在当前 research 包含内部调查角度时读取。按照 task 点名的问题和仓库范围取得事实，并把每项断言追溯到当前源码。

## 读取当前上下文

开始取证前，读取当前目录适用的 `AGENTS.md`。运行 `mmw domain path`：

| 返回 | 读取范围 |
| --- | --- |
| `single` | 命令返回的领域文档 |
| `map` | 命令返回的 Context Map，以及当前调查角度涉及的全部 leaf |
| `none` | 不读取或创建领域文档，继续调查 |

运行 `mmw domain dirs`，读取 `adr` 路径下与当前调查角度相关的 ADR。使用领域文档中的 canonical 术语；用户说法、领域文档、ADR 或当前源码互相冲突时，把冲突原样交回。

## 取得事实

使用当前仓库提供的文本检索、符号检索和结构图谱定位候选。图谱、索引和搜索结果只负责定位；每项结论都要回到当前源码验证。

只报告当前实现中的事实。根因判断、方案选择和修改建议由调用方负责。

| 断言 | 必须引用的内容 |
| --- | --- |
| 一处调用关系 | 调用方和被调用方两端 |
| 一条数据流或跨模块关系 | 数据的写入端、读取端和中间转换位置 |
| 一个类型缺少字段 | 该类型的当前定义 |
| 元编程或代码生成产生的符号 | 生成该符号的源码 |
| 某项行为已有测试覆盖 | 对应测试文件和测试名 |
| 某项行为由其他位置处理 | 实际处理该行为的位置 |

每项断言使用 `文件:行号`，并附足以让主 agent 判断出处是否支持断言的原文。引不出出处的内容不写成事实。

## 交回报告

报告按以下顺序书写：

1. task 点名的调查角度和具体问题。
2. 已查明的事实。每项事实紧跟出处。
3. 互相冲突的事实及其各自出处。
4. 未查清项、未查清原因和已经查过的位置。

完成判据：task 点名的每个子问题都有当前源码支持的答案，或者有明确的未查清原因和已经查过的位置。调查范围固定为 task 点名的问题。
