---
name: mmw-research
description: 重型多步取证流程。用于用户明确要求系统调查、`wayfinder:research` ticket，或者问题需要拆成多个独立角度或对照多份一手来源时。一个函数、一个已知文件、一个事实、文件计数、一条命令或一次直接查询能回答时，主 agent 自己处理。
---

启动后台 `investigator` 执行 research，使主 agent 能在它阅读资料时继续处理不依赖相应事实的工作。

research 的核心任务保持不变：对照拥有事实的一手来源回答问题，为每项断言标注出处，并在用户选择保存时把主 agent 验证后的完整结论写入一份 Markdown 文件。

## 1. 确定问题

按以下顺序判断：

| 当前情况 | 处理 |
| --- | --- |
| 问题必须通过持续迭代的可运行资产、用户走查，或者按测试计划运行外部系统并保留 evidence 才能回答 | 移交 `/mmw-prototype` |
| 用户明确要求系统调查、问题来自 `wayfinder:research` ticket、问题需要多个独立角度，或者需要对照多份一手来源 | 继续本技能 |
| 一个函数、一个已知文件、一个事实、文件计数、一条命令或一次直接查询能回答 | 主 agent 直接取得事实，不派 `investigator` |

运行一条只读命令取得版本号、实际返回或命令行为，本身不等于 prototype。只有答案依赖持续迭代的可运行资产、用户走查，或者按测试计划运行外部系统并保留 evidence 时，才移交 `/mmw-prototype`。

写出本次必须回答的顶层问题。问题只需要一个取证方向时，不要为了并行而拆分。问题确实包含互不依赖的取证方向时，把它拆成独立角度。

| 角度 | 适用范围 | 读取方法 |
| --- | --- | --- |
| 内部 | 当前仓库的实现、seam、数据流、调用链和影响面 | 完整读取 [INTERNAL.md](INTERNAL.md) |
| 外部 | 第三方库、API、正式规范和当前工作目录之外的知识 | 完整读取 [EXTERNAL.md](EXTERNAL.md) |

每个角度都要写明具体问题和范围。完成判据是：问题已经得到带出处的答案，或者已经列出未查清原因和查过的位置。

## 2. 派发 `investigator`

一个 `investigator` 只处理一个角度。每个角度使用一份四栏 task：

| 栏 | 内容 |
| --- | --- |
| 目标 | 顶层问题、当前角度和需要回答的具体问题 |
| 读 | 内部角度列 [INTERNAL.md](INTERNAL.md)，外部角度列 [EXTERNAL.md](EXTERNAL.md)；再列出仓库根、领域文档、ADR、已有 research 或外部合同的精确位置 |
| 约束 | 只读；只取得事实；不改文件；不选择方案；不超出当前角度 |
| 验收 | 具体问题得到带出处的答案，或者报告未查清原因和已经查过的位置 |

互不依赖的角度并行派发。派发以后，主 agent 继续处理不依赖这些事实的工作。

[[mmw-launch:investigator:none]]

## 3. 验证并综合

收到报告后，按 `/mmw-verifying-agent-output` 验证关键断言。不要重做 `investigator` 已经完成的整段 research。

1. 打开关键断言引用的源码位置或一手来源。
2. 丢弃没有出处，或者出处不支持的断言。
3. 并列保留互相冲突的证据。
4. 合并重复事实，并为每项事实保留精确出处。
5. 对照每个角度的完成判据，列出已经回答的问题和未查清项。

某个角度没有达到完成判据时，只补派缺少的部分。新的 task 必须写明缺少的答案或不成立的出处。

subagent 报告不是 research。research 是主 agent 验证并综合后的事实、出处和未查清项。

## 4. 询问是否保存

完成验证和综合后，先确定拟保存路径。调用方已经传入 `mmw path research` 的实际输出时，直接使用该输出。调用方没有传入时，按下表取得 `产物目录`：

| 场景 | 处理 |
| --- | --- |
| Wayfinder decision ticket | 使用 map 原样继承的 `产物目录`，并传入 `issue-<编号>` |
| 当前工作已经有 `产物目录` | 复用已有值 |
| 用户直接调用，而且当前工作没有 `产物目录` | 根据 research 主题提议一个稳定的单路径段，并在本节的人工审批关卡中让用户确认或改正 |

运行：

```bash
mmw path research <产物目录> [issue-<编号>]
```

命令返回 research 目录的上级目录。选择一个符合 `mmw path` 安全路径段规则的 `<research 主题>`。拟保存路径是：

```text
<mmw path research 的实际输出>/<research 主题>/
```

向用户展示：

| research 问题 | 结论摘要 | 拟保存文件 | 拟保存路径 |
| --- | --- | --- | --- |
| `<顶层问题>` | `<验证后的摘要>` | `README.md`、`report.md` 和用户确实需要的 research 配套文件 | `<完整仓库相对路径>` |

然后通过一次人工审批关卡询问用户是否保存。用户明确选择前，不创建 research 目录或文件。

| 用户选择 | 处理 |
| --- | --- |
| 保存 | 创建拟保存路径并写入下列文件。写入这些文件不需要单独建立 worktree |
| 不保存 | 不创建 research 目录或文件；验证后的事实仍然交回调用方 |

| 文件 | 内容 |
| --- | --- |
| `README.md` | 问题、范围快照、结论摘要、文件索引、下游用途和未查清项；内部 research 记录 commit，外部 research 记录访问日期和相关版本 |
| `report.md` | 主 agent 验证后的完整结论和逐条出处。这是上游要求的一份 Markdown research 报告 |
| research 配套文件 | 用户批准保存的 HTML、字段表、脚本或其他文件；每个文件的用途写入 `README.md` |

保存不代表下游必须引用。下游只读取当前工作点名的 research 索引和精确文件。

research 不进入 ADR 目录。research 形成需要长期保留的领域术语或决定时，由调用方按照 `/mmw-domain-modeling` 的判据处理。

subagent 报告默认不落盘。取证过程中确实需要保存网页转储、抓取缓存、未采信内容或跨进程临时文件时，使用调用方传入的 scratch 路径；没有传入时运行：

```bash
mmw path scratch <产物目录> [issue-<编号>|task-<任务 slug>]
```

交回结果前，只删除本次 research 创建的 scratch 文件。

## 5. 交回结果

| 调用方 | 交回内容 |
| --- | --- |
| `/mmw-wayfinder` | 验证后的事实、出处和未查清项；用户选择保存时，再交回 research 索引的精确路径 |
| 其他技能 | 验证后的事实、出处和未查清项；用户选择保存而且调用方需要时，再交回 research 索引和精确文件路径 |
| 用户直接调用 | 结论、出处、未查清项和保存结果 |
