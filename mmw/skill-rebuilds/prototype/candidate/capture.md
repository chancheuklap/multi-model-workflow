# 保存逐轮结论

用户给出走查意见后，更新 prototype 产物路径中的 `README.md`。本文件只保存 prototype 结论并准备下游输入；调用方负责自己的 tracker、共同理解、spec 或人工审批关卡。

## 1. 记录本轮

每一轮记录以下内容：

- 当前验证问题。
- 本轮可运行资产的精确路径和运行方式。
- 用户原话。
- 根据用户意见完成的修改。
- 本轮验证结果。
- 下一轮问题，或者用户选中的产物路径。
- 整个方向不成立时，记录击穿方向的事实。

用户要求修改时，继续修改同一份 prototype。用户选定结果时，记录选中产物的精确路径。每项记录都写用户原话和实际结论。

## 2. 维护 prototype 资产索引

`README.md` 必须让下游只读索引就能找到需要的内容。持续维护以下项目：

- 当前问题和逐轮用户走查结论。
- 选中产物的精确路径；没有时写「无」。
- 落选变体及其形成的否定约束；没有时写「无」。
- 页面每个功能或按钮对应的后端脚本、接口合同或可复用 `module` 路径；没有界面时写「无界面对应」。
- 被提升为长期证据的精确路径；没有时写「无」。
- 当前可直接复用的组件、纯逻辑、接口合同或后端脚本，以及它们已经达到的项目质量要求；没有时写「无」。

调试外壳、切换器和落选变体继续保留为 prototype 资产，不列为可复用内容。

## 3. 生成 README 的普通 HTML 可视化解释

`README.md` 更新后，按以下顺序处理：

1. 询问用户是否手动调用 `/wait-what`，生成或更新 `README.md` 的普通 HTML 可视化解释。
2. 用户不需要时，继续第 4 节。
3. 用户确认时，请用户手动调用 `/wait-what`，并提供 `README.md` 的精确路径。明确使用普通 HTML 可视化分支。
4. 停止本步骤，等待用户完成 `/wait-what`。
5. `/wait-what` 交回本地 HTML 路径和 Sites 结果后，继续第 4 节。

## 4. 提交持久资产

提交本轮可运行资产、更新后的 `README.md`、普通 HTML 可视化解释和其中明确引用的长期证据。没有生成普通 HTML 可视化解释时不要求对应文件。scratch 路径中的过程材料不提交。提交后只删除本轮 prototype 创建的 scratch 文件；不要清空其他流程共用的 scratch 路径。

## 5. 交回调用方

交回以下内容：

- 当前验证问题和用户走查结论。
- prototype 资产索引的精确路径。
- 选中产物的精确路径；没有时写「无」。
- 当前验证事实和否定约束。
- 页面功能或按钮与后端脚本、接口合同或可复用 `module` 的精确对应；没有界面时写「无界面对应」。
- 可以直接复用的内容及其质量状态；没有时写「无」。

`/mmw-wayfinder` 负责 decision ticket 的 resolution comment、关闭 ticket 和更新 map。`/mmw-grilling` 负责继续讨论和确认共同理解。`/mmw-to-spec` 负责综合 prototype 结论和 spec 人工审批关卡。本技能不重复这些步骤。
