# 保存逐轮结论

用户给出走查意见后，更新 prototype 产物路径中的 `README.md`。本文件只保存 prototype 结论并准备下游输入；调用方负责自己的 tracker、共同理解、spec 或人工审批关卡。

## 1. 记录本轮

每一轮记录以下内容：

- 当前验证问题。
- 本轮可运行资产的精确路径和运行方式。
- 用户原话。
- 根据用户意见完成的修改。
- 本轮验证结果。
- 下一轮问题，或者用户选中的资产路径。
- 整个方向不成立时，记录击穿方向的事实。

用户要求修改时，继续修改同一份 prototype。用户选定结果时，记录精确的选中路径。每项记录都写用户原话和实际结论。

## 2. 维护资产索引

`README.md` 必须让下游只读索引就能找到需要的内容。持续维护以下项目：

- 当前问题和逐轮用户结论。
- 选中产物的精确路径；没有时写「无」。
- 落选变体及其形成的否定约束；没有时写「无」。
- 页面每个功能或按钮对应的后端脚本、接口合同或可复用 `module` 路径；没有界面时写「无界面对应」。
- 被明确引用为必要证据的精确路径；没有时写「无」。
- 当前可直接复用的组件、纯逻辑、接口合同或后端脚本，以及它们已经达到的项目质量要求；没有时写「无」。

调试外壳、切换器和落选变体继续保留为 prototype 资产，不列为可复用内容。

## 3. 询问是否生成记录可视化

更新 `README.md` 后，询问用户：**是否使用 `/wait-what` 生成或更新这份记录的 HTML 可视化？**

用户确认后，移交 `/wait-what`，并提供 `README.md` 的精确路径。这个请求使用 `/wait-what` 的普通 HTML 可视化分支，不使用 Logic HTML 分支。

用户不需要可视化时，立即继续处理本轮结论。只有普通 HTML 可视化分支被省略。

## 4. 提交持久资产

提交本轮可运行资产、更新后的 `README.md` 和其中明确引用的必要证据。scratch 路径中的过程材料不提交。提交后清理当前任务的 scratch 路径。

## 5. 交回调用方

交回以下内容：

- 当前验证问题和用户结论。
- prototype 资产索引的精确路径。
- 选中资产的精确路径；没有时写「无」。
- 当前验证事实和否定约束。
- 页面功能或按钮与后端脚本、接口合同或可复用 `module` 的精确对应；没有界面时写「无界面对应」。
- 可以直接复用的内容及其质量状态；没有时写「无」。

`/mmw-wayfinder` 负责 decision ticket 的 resolution comment、关闭 ticket 和更新 map。`/mmw-grilling` 负责继续讨论和确认共同理解。`/mmw-to-spec` 负责综合 prototype 结论和 spec 人工审批关卡。本技能不重复这些步骤。
