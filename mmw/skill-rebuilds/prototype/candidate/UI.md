# UI/UX Prototype

UI/UX prototype 用可运行页面理顺页面、状态和操作路径。用户在浏览器中走查，选择一个方向，或者指出需要组合和修改的部分。

## 1. 选择承载形态

| 项目情况 | 承载形态 |
| --- | --- |
| 已有成熟应用，而且 prototype 天然属于某个页面或流程 | 挂入已有页面。保留真实页头、侧边栏、数据密度、取数、参数和鉴权，只替换正在验证的界面部分 |
| 全新产品、纯后端仓库，或者需要跨前端和后端验证可行性 | 在 [SKILL.md](SKILL.md) 确定的 `mockup/` 中使用独立 HTML。它是正常形态，不是最后手段 |
| 已有应用，但没有任何现有页面能够承载一个新的顶层界面 | 按项目现有路由约定建立明确标记的 prototype 路由 |

挂入已有页面时，prototype 更容易暴露真实密度、数据和流程问题。独立 HTML 适合尚无前端宿主的产品，也适合把前端和后端可行性放在同一份 prototype 中验证。

## 2. 判断是否需要多个变体

只有 UI 结构方向尚未确定时，才生成多个变体。变体必须在布局、信息层级或 `primary affordance` 上存在真实差异。数量由仍待比较的结构方向决定，不使用固定的默认数量。

用户已经选择方向后，继续迭代选中的版本。不要在每一轮重新生成整组变体。

多个结构方向可以独立生成，而且并行能够缩短当前轮次时，可以为每个方向派一个 `prototype-worker`。每份 task 使用以下四栏表：

| 栏 | 内容 |
| --- | --- |
| 目标 | 当前验证问题，以及该 `prototype-worker` 负责的一个结构方向 |
| 读 | 页面或流程的精确路径；真实数据、组件库、样式系统和现有 prototype 资产的精确路径 |
| 约束 | 只实现分配的结构方向；只修改分配给自己的文件；不实现其他变体；不把 prototype 外壳接入生产路由 |
| 验收 | 变体可以运行；结构方向与其他变体存在真实差异；交回精确运行方式、走查地址或文件路径，以及项目要求的验证结果 |

派发前，确认当前任务分支已经提交，而且 worktree 干净。为每个 `prototype-worker` 确定唯一、完整的结果分支名，并记录当前任务分支的 `HEAD` 作为基点 SHA。把结果分支名和基点 SHA 写入对应 task。

[[mmw-launch:prototype-worker:worktree]]

每个 `prototype-worker` 交回后收取结果：

[[mmw-host-action:collect-worktree-result]]

按 `/mmw-verifying-agent-output` 验证结构差异、项目组件约束和可运行性，再集成通过的结果：

[[mmw-host-action:integrate-worktree-result]]

并行没有明显收益时，由主 agent 直接完成。不要为单一已选方向建立无意义的 subagent 或 worktree。

## 3. 生成结构不同的变体

每个变体都遵守页面用途、真实数据和项目现有组件库或样式系统。每个变体使用清楚的名称，例如 `VariantA`、`VariantB`。

变体必须在结构上存在差异，例如布局、信息层级或 `primary affordance` 不同。只改变颜色或文案不构成新变体。变体之间可以共享页头等稳定组件，但不能共享正在比较的整体布局。

多个变体需要切换时，在同一路由使用 `?variant=` 查询参数和浮动切换器。保留切换器上方的真实取数、参数和鉴权，只切换正在比较的渲染子树。

浮动切换器固定在屏幕底部居中，提供上一个变体、当前变体名称和下一个变体。上一个和下一个按钮在首尾之间循环。点击按钮或按 `←`、`→` 方向键时更新 URL 查询参数，使链接可以分享并在刷新后保持稳定。焦点位于输入框、文本域或可编辑元素时，不拦截键盘方向键。切换器在视觉上与产品界面区分，并在生产构建中隐藏。

只有一个已选方向时，不保留无用切换器。

## 4. 连接后端行为

初轮可以使用桩来验证 UI/UX 流程。流程确定后，为每个功能和按钮补上后端脚本、接口合同或可复用 `module`，并在 `README.md` 中记录精确对应关系。

写操作尚未接入真实后端时，必须清楚显示桩行为。需要验证真实写操作时，先完成对应后端 prototype，再让页面调用它。

每个实际存在的页面状态都应能呈现，包括与当前问题相关的加载、空、错误、成功和部分完成状态。页面变化后显示用户判断当前问题所需的完整相关状态。

## 5. 交给用户

把页面地址和 `?variant=` 取值交给用户。只有一个方向时，直接给出该页面地址。

[[mmw-host-action:present-ui-review]]

用户给出任何走查意见后，继续第 6 节。用户要求组合不同变体时，完成本轮记录后再把组合做成一个可运行版本，并重新走查；不能只用文字宣布组合已经选定。

## 6. 保存结果

逐轮记录、prototype 资产索引和下游输入只由 [capture.md](capture.md) 定义。本文件不重复这些字段。

达到项目技术与质量要求的选中组件可以复用。仍使用桩、缺少测试或只为走查编写的界面外壳，不能进入生产路由。调试路由、切换器和落选变体继续作为 prototype 资产保存。
