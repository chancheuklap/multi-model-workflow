# 普通 HTML 可视化解释

本文件把方案、文档或回复解释成 HTML。需要让读者按按钮驱动状态模型时，使用 [LOGIC.md](LOGIC.md)。

先完整读取用户要求解释的方案、文档或回复。根据当前对话确定要解释的范围。

可视化解释必须完整覆盖用户要求解释的内容。沿用其中的术语和表达，不创造新术语、缩写或代号。内容涉及仓库时，使用领域上下文中的 canonical 术语；存在冲突时显示冲突。

以图、表和交互为主，只使用必要的标签、短说明和出处。让读者尽量不打开原文也能看懂。

## 路线一：完整 HTML

这是默认路线。生成完整 HTML。要解释的内容已经落盘时，本地 HTML 与它放在同一目录并使用同名 `.html`。内容只在对话中时，先使用调用方提供的精确输出目录；调用方没有提供时，询问用户保存到哪个精确目录。确定目录后，把原始内容和本地 HTML 一起保存在该目录。

[[mmw-host-action:publish-visual-explanation]]

这条路线完成时，本地 HTML 已保存并能打开，同一个 Sites 网站已经保存本次更新的新版本。发布失败时保留本地 HTML，并明确报告 Sites 未完成。

## 路线二：对话内可视化

只有用户要求解释的范围非常精确、非常小，而且一个紧凑的图或表可以完整讲清时，才使用这条路线。

[[mmw-host-action:render-inline-visual-explanation]]

这条路线完成时，HTML fragment 已在对话内显示，并完整覆盖用户要求解释的范围。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 完整 HTML 已在本地保存，而且有调用方等待 | **移交**：把本地 HTML 路径和 Sites 版本结果交回调用方 |
| 本地 HTML 已保存、Sites 发布失败，而且有调用方等待 | **移交**：把本地 HTML 路径和 Sites 未完成状态交回调用方 |
| 小范围内容已经在对话内完整显示，而且有调用方等待 | **移交**：把对话内可视化结果交回调用方 |
| 完整 HTML 或对话内可视化已经完成，而且没有调用方等待 | **停**：展示可视化并说明本地文件位置或对话内结果 |
| 本地 HTML 已保存、Sites 发布失败，而且没有调用方等待 | **停**：展示本地产物并明确报告 Sites 未完成 |
