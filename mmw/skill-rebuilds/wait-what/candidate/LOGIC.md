# Logic HTML

Logic HTML 是一个独立、自包含的 HTML 文件。任何人都能点击按钮来驱动状态模型。它回答业务逻辑、状态转移或数据形状的问题。普通文档解释使用 [VISUAL.md](VISUAL.md)。

Logic HTML 适合以下情况：

- 纯状态模型没有合适的产品界面。
- 非开发者需要亲自用按钮驱动状态模型。
- 纸面上难以判断某条状态转移或数据边界。

开始本分支前，必须从用户的调用内容和此前上下文取得以下内容：

- 当前验证问题。
- 现有状态模型或后端脚本的精确路径。
- 真实场景和边界。
- Logic HTML 的精确输出路径。

缺少会改变模型行为的输入时，先向用户取得缺失内容。不要自行补造业务动作、状态或边界。

## 1. 说明问题

编写代码前，读取现有状态模型或后端脚本。把当前验证问题写在页面顶部的可见介绍中。介绍必须说明用户正在驱动什么状态模型，以及这一轮要判断什么。

## 2. 隔离可移植逻辑

把回答当前问题的实际逻辑放进一个小型纯 `module`。根据问题选择形态：

- 动作是离散事件，而且状态是单一值时，使用纯 `reducer`。
- 合法动作取决于当前状态时，使用状态机。
- 只有数据转换，没有隐含当前状态时，使用一组纯函数。
- 逻辑确实持有持续的内部状态时，使用具有清晰方法集合的类或 `module`。

现有状态模型或后端脚本是行为依据。Logic HTML 只承载当前问题需要的最小逻辑。页面调用纯 `module`；纯 `module` 不访问 DOM、`document` 或按钮处理器。页面外壳不能反向决定业务行为。

现有状态模型或后端脚本无法直接在浏览器中运行时，根据它的公开行为实现回答当前问题的纯 `module`。只实现现有行为能够确定的动作、状态和边界；无法确定的业务事实交回等待结果的调用方，不自行补造。

构建 HTML 前确认现有行为足以表达当前验证问题：

| 情况 | 处理 |
| --- | --- |
| 现有行为无法表达当前验证问题，而且有调用方等待 | 说明无法表达的事实，交回调用方，并结束本分支 |
| 现有行为无法表达当前验证问题，而且没有调用方等待 | 向用户说明无法表达的事实，并结束本分支 |
| 现有行为足以表达当前验证问题 | 继续第 3 节 |

## 3. 构建自包含 HTML

生成一个原生 HTML、CSS 和 JavaScript 文件。全部内容内联。文件无需框架、打包器或服务器，用户双击就能运行。

页面使用领域语言，不暴露内部事件枚举或字段缩写。按照以下顺序布局：

1. 标题和一行说明。说明当前验证问题。
2. 当前状态。使用带标签的字段展示完整相关状态，不直接倾倒原始 JSON。每次动作后重新渲染。
3. `free-play` 按钮。每种动作一个按钮，用户可以任意排序尝试。非法动作也可以触发，由模型明确拒绝并说明原因。
4. `guided walkthrough`。一个场景一个标签页。每个场景说明初始情形和观察重点，并提供按顺序执行的真实动作按钮。

每次启动同一个 `guided walkthrough` 时，先重置到相同的已知初态。场景至少覆盖正常路径、一个真实边界和一次应被拒绝的非法动作。并发、回滚、空状态和失败状态只在模型真实存在时加入。

排版保持克制。使用清楚的层级、足够的间距和一个强调色。视觉装饰不能盖过状态和动作。

## 4. 交给用户驱动状态模型

打开 Logic HTML，把 `free-play` 和每个 `guided walkthrough` 交给用户。用户必须能够独立重置并重复运行场景。

[[mmw-host-action:present-ui-review]]

用户指出不合理行为时，记录原话。走查结束后，按文末“下一步”处理修改或交回。

Logic HTML 默认只保存到用户调用本技能时提供的本地输出路径。普通文档可视化的 Sites 发布规则不适用于本分支。用户明确要求发布时，才执行以下宿主动作：

[[mmw-host-action:publish-visual-explanation]]

## 完成判据

- 页面明确显示当前验证问题。
- 所有动作调用同一个纯 `module`。
- 每次动作后显示完整相关状态。
- `free-play`、可重复的 `guided walkthrough` 和真实边界都能运行。
- 文件保存在用户提供的精确路径。
- 用户的走查意见已经记录；有调用方等待时，交回内容已经准备完整。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 用户要求修改动作、场景或状态呈现 | **自己继续**：修改同一 Logic HTML，再次交给用户驱动状态模型 |
| 用户走查后确认现有状态模型无法表达验证问题，而且有调用方等待 | **移交**：把用户原话、无法表达的事实和 Logic HTML 路径交回调用方 |
| 用户走查后确认现有状态模型无法表达验证问题，而且没有调用方等待 | **停**：展示用户原话、无法表达的事实和 Logic HTML 路径 |
| 用户给出其他走查结论，而且有调用方等待 | **移交**：把用户原话、Logic HTML 路径和验证结果交回调用方 |
| 用户给出其他走查结论，而且没有调用方等待 | **停**：展示用户原话、Logic HTML 路径和验证结果 |
