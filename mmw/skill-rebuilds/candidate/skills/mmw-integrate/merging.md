# merge：把完成的结果分支合入当前任务分支

正常入口是 `/mmw-integrate` 的 `mmw result integrate`。本文件只说明 merge 冲突和完成动作。

## 先看清楚现在停在哪

带着一个已经存在的冲突进来时，先取现状再动手：`git status` 看这次 merge 停在哪一步、哪些文件还冲突着，`git log --oneline HEAD..MERGE_HEAD` 看正在合进来的是哪几条提交。没弄清楚合的是谁、卡在哪几个文件，不要开始解冲突。

## 识别两边

| 标记 | 内容 |
| --- | --- |
| `ours`、`<<<<<<< HEAD` | 当前任务分支已有的内容 |
| `theirs`、`>>>>>>>` | 正在合入的结果分支内容 |

逐块读取双方的提交、issue 和 spec。兼容的行为全部保留；不兼容的行为按 `/mmw-integrate` 已确定的目标取舍并写入集成记录。只组合这些 primary source 已经表达的意图，不发明第三种行为。

## 完成

```bash
git add <已经解决的文件>
git commit
```

保留 Git 生成的 merge 标题。提交正文写明解决了哪些实质冲突及取舍；只有机械冲突时不增加空泛说明。

完成后运行项目要求的检查，并确认 `git status` 不再显示进行中的 merge。

## 停止

`git merge --abort` 会回到集成前。只有用户取消本次集成，或现有目标无法决定冲突取舍时才停止；不要用停止代替冲突判断。
