# 内部 research

只在当前角度需要查明仓库内部事实时读取本文件。

## 取得事实

读取 task 点名的仓库根、领域文档和 ADR。使用领域文档中的 canonical 术语。用户说法、领域文档、ADR 和当前源码互相冲突时，保留各自出处，不自行消除冲突。

用 Serena 查符号定义、直接引用和实现。用 Graphify 查模块关系、依赖路径、影响面和跨语言数据流。文本检索、Serena 和 Graphify 只用于定位候选。每项事实都要回到当前源码验证。

| 断言 | 出处要求 |
| --- | --- |
| 调用关系 | 同时引用调用方和被调用方 |
| 数据流或跨模块关系 | 引用写入端、读取端和中间转换位置 |
| 类型缺少字段 | 引用当前类型定义 |
| 元编程或代码生成产生的符号 | 引用生成该符号的源码 |
| 已有测试覆盖 | 引用测试文件和测试名 |
| 行为由其他位置处理 | 引用实际处理位置 |

每项断言使用 `文件:行号`，并附上支持该断言的源码原文。没有出处的内容不写成事实。

## 交回报告

按以下顺序交回：

1. task 点名的具体问题和范围。
2. 已查明的事实及其出处。
3. 互相冲突的事实及其各自出处。
4. 未查清项、原因和已经查过的位置。

完成判据：task 点名的问题已经得到当前源码支持的答案，或者已经列出未查清原因和查过的位置。把报告交回主 agent。
