# 保存逐轮结论

`prototype 产物路径` 下的 `README.md` 是下游读取 prototype 的入口。spec、ticket、plan、审查和实现都从它出发找内容。

## 1. 收到意见时先记录

用户给出走查意见后，先在 `README.md` 的本轮记录中追加：

- 本轮验证问题。
- 本轮可运行资产的精确路径和运行方式。
- 用户原话。
- 用户接受当前 mockup、要求继续修改、选择一个变体、组合多个变体，还是否定整个方向。
- 本轮变体组的精确路径、完整变体或局部变体类型；没有时写「无」。
- 用户点名的变体 key；没有时写「无」。

记录之后，按当前工作面继续处理用户意见。用户接受当前 mockup 时，继续检查本轮是否完成。用户要求修改时，修改同一份 prototype 并重新走查。用户选择或组合 UI 变体时，回 [UI.md](UI.md) 第 6 节形成 `mockup/current/` 并重新走查。记录选择本身不代表本轮完成。

用户确认修改后的结果时，再追加实际修改和本轮验证结果。整个方向不成立时，记录击穿方向的事实。

## 2. 维护 `README.md` 当前索引

每一轮都把下面内容维护成最新状态：

- 初始问题和本轮验证问题。
- 本轮保持不变的部分。
- 本轮路径：完整变体、局部变体，或者直接创建或修改。
- 逐轮用户原话、实际修改和走查结论。
- `mockup/current/` 中当前 UI mockup 的精确路径和运行方式；没有 UI mockup 时写「无」。
- 每个变体组回答的问题、`preview/` 入口、页面 URL、变体 key 与目录映射、完整变体或局部变体类型，以及用户选择；没有时写「无」。
- 其他选中产物的精确路径；没有时写「无」。
- 落选变体及其形成的否定约束；没有时写「无」。
- 本轮新建或修改的页面功能或按钮的全部当前行为类型和精确路径；`stub` 或 `contract` 还要写尚未接入的正式行为；没有 UI mockup 时写「无界面对应」。
- 这一轮已经磨清楚、下游可以直接参考或复用的纯逻辑、后端脚本、接口合同、状态模型或 UI mockup，以及各自的精确路径；没有时写「无」。

**可复用指的是想法，不是工程完备度。** 列进可复用那一项的文件是在 prototype 约束下写出来的：没有测试，错误处理最少。下游把它折进正式代码时按生产标准重写——补测试、补错误处理，不要原样搬文件。在可复用那一项的开头写上这句话，让只读 `README.md` 的下游也看得到。

调试外壳、变体切换器和落选变体留在 `mockup/` 里，但不要列进可复用那一项。它们保存本轮比较过的方向和形成的否定约束。

## 3. 检查本轮是否完成

提交前检查适用项目：

- 用户意见已经原样记录。
- 本轮以 `mockup/current/` 为结果时，用户已经接受它，或者已经确认修改、选择或组合后的结果。
- 用户要求的修改已经完成并重新走查。
- UI 变体被选择或组合时，结果已经写进 `mockup/current/`。
- UI 变体被选择或组合时，用户已经确认 `mockup/current/` 与选择或组合结果一致。
- `README.md` 已经记录当前 UI mockup、变体组和功能对应。
- 没有尚未处理的用户修改要求。

没有 UI mockup 的工作面不检查 UI 项。走查事实证明整个方向不成立时，可以没有 `mockup/current/`，但必须记录击穿方向的事实。

适用项目全部满足后，本轮才算完成。

## 4. 提交持久资产

提交本轮可运行资产和更新后的 `README.md`。`scratch 路径` 下的过程材料不提交。提交之后，只删除本轮 prototype 自己在 `scratch 路径` 下建立的文件。这个目录中的其他文件由对应流程处理。

## 5. 交回调用方

交回 `README.md` 当前索引中的以下内容：

- 当前验证问题和用户走查结论。
- 这份 `README.md` 的精确路径。
- 当前 UI mockup 的精确路径和运行方式；没有时写「无」。
- 本轮变体组、变体 key 和用户选择；没有时写「无」。
- 其他选中产物的精确路径；没有时写「无」。
- 当前验证事实和否定约束。
- 页面功能或按钮的全部当前行为类型和精确对应；没有 UI mockup 时写「无界面对应」。
- 这一轮已经磨清楚、下游可以直接参考或复用的内容及其精确路径；没有时写「无」。

交回之后就结束。调用方负责 issue 评论、ticket、map 和后续用户确认。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 用户要求继续修改 | **自己继续**：回当前工作面修改同一份 prototype，并重新走查 |
| 用户走查已经回答当前问题，而且有调用方等待 | **移交**：把第 5 节的完整内容交回调用方 |
| 用户走查已经回答当前问题，没有调用方等待，而且需要形成 spec | **移交**：`$mmw:mmw-to-spec` |
| 用户走查已经回答当前问题，没有调用方等待，而且不需要形成 spec | **停**：展示本轮结论、`README.md` 路径和选中产物路径；没有选中产物时写「无」 |
| 走查事实证明整个方向不成立，而且有调用方等待 | **移交**：把击穿这个方向的事实和 `README.md` 路径交回调用方 |
| 走查事实证明整个方向不成立，而且没有调用方等待 | **移交**：`$mmw:mmw-grilling`，重新讨论方向 |
