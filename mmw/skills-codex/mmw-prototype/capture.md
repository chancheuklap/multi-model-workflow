# 走查过了之后怎么回填

**回填完成之前这一轮不算完。**

## 1. 先把这一轮记完

往 `docs/prototypes/<slug>/README.md` 追加这一轮的结论一节，结论状态写 `accepted`，并列出**选中的是哪几份产物**（写路径）。落选的那些留在原地作为迭代历史，但不往下传。

然后提交：源码、`README.md`、这一轮的证据文件在同一个提交里。

## 2. 结论写到哪去

看是谁把你叫起来的：

| 谁叫的 | 结论写去哪 |
| --- | --- |
| `$mmw:mmw-wayfinder` 的一张 `wayfinder:prototype` ticket | 回 `$mmw:mmw-wayfinder`，按 `mmw-wayfinder/walking.md` 第 4 步那六件事记录这次解答；结案评论里留一个指向原型产物的路径。关 ticket、追加 map 索引、写 ADR 都归那一步，不要在这里先做一遍 |
| `$mmw:mmw-grilling`，或者用户直接叫你 | 写进这份 spec 的 `Implementation Decisions`；spec 还没建就先留在 `README.md` 里，`$mmw:mmw-to-spec` 会来取 |

**每一条回填进去的决定，末尾标注它的原型出处**——第几轮、哪份产物。`$mmw:mmw-to-spec` 定稿时要逐条验证：每条需求都得指得到一份原型证据，或者写明它为什么不需要原型。

## 3. 逻辑这一侧怎么回填

TUI 那条 branch 和最小脚本那条 branch 都走这一节。

- **状态、合法转移、被拒绝的非法转移、schema** 逐条写成文字，每条对应一项能执行的验收。「退款窗口关闭后申请会被拒绝」是一条，它对应一个测试。
- **验证过的那个模块整块搬进正式代码**——reducer、状态机或者那组纯函数（见 [LOGIC.md](LOGIC.md) 第 2 步）。搬过去，不重写。
- **TUI 那层壳不进生产**，留在 `docs/prototypes/<slug>/logic/` 里。
- **最小脚本那条 branch**：用户在走查中选定的那份样例、那个数据形状、那份合同定义，逐个字段写成验收标准，字段的类型、可空性和取值范围都写出来。样例文件本身留在 `docs/prototypes/<slug>/logic/` 里当出处，跑它的那个脚本跟 TUI 一样不进生产。

## 4. 界面这一侧怎么回填

- **选中变体的每个界面元素、每个状态、每处交互、每句文案，原子级拆成验收标准。** 「空状态显示一句说明加一个『新建订单』按钮」是一条。
- **视觉契约单独写一节**：布局、间距、配色、用到哪些组件，并指向具体的变体文件路径。
- **全部变体归档进 `docs/prototypes/<slug>/mockup/`**——选中的和落选的都要。
- **生产代码里撤干净**：挂在已有页面上的，把选中变体并进那个页面，删掉落选变体和切换器；用了一次性路由的，把选中变体提升成正式路由，删掉那条路由和切换器。
- **界面代码重写，不搬运。** 并进生产时按仓库的规范重写，技术栈也在这时候改造到位。

## 5. 冲突了听谁的

回填过程中发现原型跟先前写下的决定对不上，**以用户在走查中选定的版本为准**，反过来改决定文档。

## 6. 材料怎么交给写码的 `worker`

派 `worker` 实现时（见 `$mmw:mmw-implement`），task 里给的是**回填后的验收标准和视觉契约**，加上选中的那一版在仓库里的路径。

不要只给一句「照原型做」，原型目录里还躺着落选变体和 TUI 壳。

| --- | --- |
| 结论已经回填，而且是别的技能把你叫起来的 | **移交**：回到把你叫起来的那个技能 |
| 结论已经回填，没有别的技能在等你，这份 spec 还没写 | **移交**：`$mmw:mmw-to-spec` |
| 结论已经回填，spec 已经在了，这条需求是补验的 | **自己继续**：把这条决定补进 spec 的 `Implementation Decisions`，然后看还有没有别的需求指不到原型证据 |
| 回填时发现原型跟先前写下的某个决定对不上 | **自己继续**：按本文「冲突了听谁的」一节，以选中的那一版为准改决定文档，并在改动处留一句说明它出自哪一轮走查 |
| 还有别的问题要验 | **移交**：回 [SKILL.md](SKILL.md) 的「一轮只回答一个问题」一节，登记下一轮要回答的问题 |
