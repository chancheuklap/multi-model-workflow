# 保存逐轮结论

`prototype 产物路径` 下的 `README.md` 是下游入口。

## 1. 记录本轮

收到用户反馈后，先在 `README.md` 追加：

- 本轮验证问题。
- 本轮可运行资产的精确路径和运行方式。
- 用户原话和选择的变体 key。
- 实际修改和本轮结论。

用户要求修改时，回当前工作面继续。用户选择或组合 UI 变体时，按 [UI.md](UI.md) 形成 current 并重新走查。

## 2. 更新当前索引

把以下内容维护为最新状态：

- 当前问题和逐轮走查结论。
- current、其他选中资产及其运行方式。
- 变体组的 preview、URL、key 映射和用户选择。
- 落选变体形成的否定约束。
- 本轮功能对应的 `frontend`、`stub`、`contract` 或 `backend` 路径。
- 下游可以参考的逻辑、合同、状态模型或 UI mockup。

可复用项必须注明：prototype 没有生产级测试和错误处理，下游应按生产标准重写。切换器和落选变体不列为可复用内容。

## 3. 完成本轮

用户原话已经记录，修改已经重新走查，且没有待处理意见时，本轮才完成。选择或组合变体时，current 必须已经形成并由用户确认。整个方向不成立时，记录击穿事实即可。

## 4. 提交持久资产

提交可运行资产和 `README.md`。不提交 `scratch 路径`；提交后只删除本轮创建的 scratch 文件。

## 5. 交回调用方

交回 `README.md` 路径、当前问题、走查结论、选中资产及运行方式、变体选择和否定约束。调用方负责后续 issue、ticket 和 map。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 用户要求继续修改 | **自己继续**：回当前工作面修改并重新走查 |
| 当前问题已回答，而且有调用方等待 | **移交**：交回第 5 节内容 |
| 当前问题已回答，需要形成 spec | **移交**：`$mmw:mmw-to-spec` |
| 当前问题已回答，不需要形成 spec | **停**：展示结论、`README.md` 和选中资产路径 |
| 整个方向不成立，没有调用方等待 | **移交**：`$mmw:mmw-grilling` |
