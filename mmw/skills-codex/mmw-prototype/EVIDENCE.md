# 取证原型

另外三条 branch 验的是**我们自己要写的东西**——那套状态模型、那个界面、那份数据形状。这一条验的是**我们要依赖的外部系统**：它在我们的负载、我们的数据、我们的账号下实际表现如何。

适合的问题长这样：

- 「那个服务撑得住我们的并发吗？」
- 「这三个候选哪个扛得住？」
- 「这个第三方接口实际返回什么，跟文档说的一样吗？」
- 「这个方案的延迟能压到多少？」

问题是我们自己那套东西成不成立，就走错了，回 [LOGIC.md](LOGIC.md) 或 [UI.md](UI.md)。

## 先判要不要做这一轮

| 走 | 什么时候 | 例子 |
| --- | --- | --- |
| 本文第 1 步到第 5 步 | 要真实运行、要比几个候选、要多轮测量，而且有决定被它卡住 | 选哪个供应商、并发上限定多少、这个第三方接口的实际合同是什么 |
| 主 agent 直接读取 | 一个已知文件或一个事实就能答 | 这个接口支不支持游标分页、这个字段的类型是什么 |
| 主 agent 运行单条命令 | 一次运行就得到答案 | 这个包的实际版本号、这个命令的退出码 |

**只在决定真的被卡住时开。** 不确定就先由主 agent 直接读取相关材料或运行单条命令，仍需要多角度系统取证时再调用 `$mmw:mmw-research`，必须真实运行时再升级到本文流程。

## 1. 冻结

把待验证的那条假设，和它卡住的那个决定，写进 spec 的 `## Open Decisions`（还没有 spec 就先记在对话里）。

**只暂停依赖这条事实的分支。** 其余的接着谈、接着做。

## 2. 立计划

使用 [SKILL.md](SKILL.md) 通过 `mmw path evidence` 取得的 evidence 产物路径。写 `<evidence 产物路径>/<日期>-<对象>-test-plan.md`，四栏：

| 栏 | 写什么 |
| --- | --- |
| 对象 | 测哪几个候选，各是什么版本、什么配置 |
| 口径 | 测什么指标，怎么测，跑几轮，用什么输入 |
| 通过判据 | 什么结果算它通过。**先写判据再跑** |
| 真实环境需求 | 要什么账号、凭证、数据量、网络位置 |

## 3. 真实跑

使用 [SKILL.md](SKILL.md) 通过 `mmw path scratch` 取得的 scratch 路径。探测脚本、过程截图、DOM、console、录屏、完整命令输出和生成中间物默认落在 `<scratch 路径>/runs/<战役名>/`，不进 Git。

完整读取并遵守 `/browser:control-in-app-browser`。交互式浏览器取证使用 Codex 内置浏览器，保存相关状态的截图、DOM 和 console 证据。需要多轮测量或稳定断言时，仍使用项目已有的 Playwright 或 Puppeteer 入口。取证时覆盖过 viewport 的，保存最后一份证据后恢复默认 viewport。项目没有自动化入口时，记录可重复执行的浏览器步骤；不为本次取证安装新的浏览器工具。

**这几件事动手之前先问用户**：要用真实凭证、要连生产环境、要在真机上跑、会产生费用、会写入外部系统的数据。他点头再动。

多候选、多轮时：

- **test-plan 和台账**一律由**主 agent**写入 evidence 产物路径。探测脚本和过程原始产物由主 agent 写入 scratch 路径。
- 需要并行只读取证时：一个对象一个 `investigator`。四栏表——目标「对该对象跑探测，原样交回命令与关键输出」；读=该对象 test-plan 路径 + 仓库根；约束=只读、不改仓库、不写 `docs/`、不写结论等级；验收=交回可复述的命令原文与输出摘要（或临时路径说明），**不要求**它创建 evidence 产物路径下的文件。
启动：按名称调用 Codex 原生 subagent `mmw-investigator`，task 传四栏表全文。互不依赖的实例在同一条消息中并行启动，全部完成后再汇总。

派出 subagent 后，主 agent 不得执行与该 subagent task 重叠的 research、实现或审查。没有明确不重叠的协调工作时，立即等待 subagent 交回报告；报告交回后只按 `$mmw:mmw-verifying-agent-output` 验证关键断言，不重做整个 task。
- 主 agent 把交回的完整输出落入 scratch 路径，再写台账。
- 只有一两个对象则主 agent 自己跑，不派 subagent。
- **不派 `worker` 改 `docs/`。** 脚本与产物归主 agent。

收回后按 `$mmw:mmw-verifying-agent-output` 验证。

## 4. 记台账

结论写 `<evidence 产物路径>/<日期>-<主题>.md`，逐条标证据等级：

| 等级 | 是什么 |
| --- | --- |
| 一手实测 | 你自己按 test-plan 跑出来的；台账记录精确命令、环境和结果摘要，有提升原始证据时指向该路径 |
| 官方文档 | 第一方文档或源码写着的 |
| 二手 | 别人的测评、博客、问答 |

**没有精确命令、环境和可验证结果的实测结论标「待验」**，不当结论用。

被否掉的候选也留一条：它是什么、为什么否、证据在哪。

台账正文写结论、精确命令、环境、结果摘要和证据出处，长输出不内联。只把**不能低成本重建且直接支撑结论**的最小原始证据从 scratch 提升到 evidence 产物路径。提升前移除 secret、个人数据和与结论无关的原始内容，并在台账里逐条引用。

## 5. 回填，解冻

结论写进 spec 对应的那条决定，末尾标台账路径。然后从 `## Open Decisions` 里划掉这一条，回到被冻结的那个分支接着谈。

每确定一个结论提交一次。

## 落点

```
<evidence 产物路径>/
├── <日期>-<对象>-test-plan.md    第 2 步的计划
├── <日期>-<主题>.md              第 4 步的台账
└── raw/                         不能低成本重建的最小脱敏原始证据，没有就不建
```

**evidence 产物路径不随 spec 删。** 它记的是外部世界的表现。持久化的是测试计划、结论台账和无法低成本重建的最小证据，不是所有 runs。

其余探测过程留在 scratch 路径，回填完结论就清理。另外三条 branch 的产物落在 prototype 产物路径，两边不混：测出来的数据不塞进 prototype 目录，走查用的界面变体不塞进台账。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 台账记完、结论回填、`## Open Decisions` 里那条划掉了，scratch 路径已清理 | **移交**：回到把你叫起来的那个技能 |
| 第 3 步要用真实凭证、连生产环境、上真机、产生费用，或者写入外部系统 | **停**：说清要做什么、影响什么、花多少，等用户点头 |
| 跑完发现候选全都不满足通过判据 | **停**：报测了哪几个、各自卡在哪条判据上，不要自己放宽判据 |
| 测出来的结果要用户走查一套状态模型或者几个界面候选 | **自己继续**：回 [SKILL.md](SKILL.md) 的「一轮只回答一个问题」一节开新一轮，走 [LOGIC.md](LOGIC.md) 或 [UI.md](UI.md)，带上台账里的相关结论 |
| 第 1 步发现卡住的其实不止一个决定，而且互相牵连 | **停**：报是哪几个决定、它们怎么互相牵连，让用户定先解哪一个 |
| 读文档、读源码或运行单条命令就能答，不需要真跑 | **自己继续**：主 agent 直接取得事实和出处，再移交回把你叫起来的那个技能 |
