等一下——我不明白你现在讲到哪一步了。换一种方式重新说明：补一点上下文，使用 ASD-STE100 简化技术英语（Simplified Technical English），并采用领域上下文中的通用语言。

用户没有另行指出时，要重新说明的就是上一条消息。用户点名一份文档时，重新说明的是那份文档。session 里的输出和仓库里的各种文档都在范围内。

在仓库任务中，先遵守目标仓库 `AGENTS.md` 的领域上下文规则，使用领域上下文中的 canonical 术语；没有领域文档时使用行业标准术语。

只重新说明用户点名的内容，不引入新方向。根据读者缺少的上下文解释必要的缩写和代码标识符。

## 选择分支

| 用户需要什么 | 处理 |
| --- | --- |
| 用更简单的文字重新说明 | 补齐理解当前内容所需的上下文，再用短句重新说明 |
| 把它画出来，做成普通 HTML 可视化解释 | 完整读取 [VISUAL.md](VISUAL.md) |
| 看不懂的是一套业务逻辑、状态转移或数据形状，需要自己按按钮走一遍才能明白 | 移交 `$mmw:mmw-prototype`，交给它当前看不懂的内容、现有状态模型或后端脚本的精确路径，以及要弄明白的问题；它按 Logic HTML 工作面制作可点击的页面 |

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 文字重新说明已经完成 | **停**：展示重新说明后的内容，等待用户反馈 |
| 用户需要按按钮走一遍才能明白 | **移交**：`$mmw:mmw-prototype`，按 Logic HTML 工作面制作可点击的页面 |
