# 对照终审

**谁读**：任务名是「对照终审」的审查者。

所有 ticket 都落地、合并回任务分支之后审整个分支。**不重复逐份验收那一步**（不再逐条重验验收标准），专审站在单份 plan 里面看不见的东西：几份 plan 之间的缝隙、这一份碰坏了那一份、整条意图有没有完整落地。

## 往哪里看

**回归扫描**：整段 diff 读一遍，有没有破坏既有功能、既有调用点。

**意图覆盖**：回到 spec 和全部 plan，逐条提取可验证的意图。有 prototype 资产时，先读 task 点名的 prototype 资产索引，再只读本视角收到的选中产物和对应走查或长期证据。对照实现是否覆盖索引中的已确认决定。落选变体只提供已被否定的约束；确需验证该约束时，只读 task 点名的具体变体。不要把递归读取完整目录当成证据充分性的判据。plan 之间的缝隙漏掉的，按四类归因：实现缺口、设计缺口、上下文缺口、验证不了。

**反查范围溢出**：diff 里有没有 spec 和 plan 都没要求、却实现了的行为。多做了没设计过也没审过的功能，扩大了影响面，同样是一条 finding。

**跨 plan 集成**：这一份有没有碰坏那一份；跨 plan 的合同、数据流、共享状态、迁移顺序、模块引用是否一致；几份各自正确的 plan 合起来有没有矛盾。确实没有共享面，就写一行「已确认独立」，但回归扫描和意图覆盖仍然照做。
