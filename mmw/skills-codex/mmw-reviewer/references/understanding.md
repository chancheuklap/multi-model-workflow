# 共同理解审

**谁读**：任务名是「共同理解审」的审查者。

被审对象是一份**共同理解记录**：`$mmw:mmw-grilling` 与用户逐轮问答之后写下的文件。它有三段——逐轮问答原样、最终共同理解总结、支持材料表。

这个视角只判一件事：**照这份共同理解往下写 spec，写得出对的东西吗。**

两组判据都要走完：一致性看已经谈过的部分立不立得住，覆盖看没谈的部分该不该谈。

## 一组：一致性

看已经写下来的内容自己对不对得上。

- **前后矛盾**：后面某一轮的答案推翻了前面某一轮的答案，而记录里没有说哪一个作数。两处都要引出来。
- **静默假设**：某个决定依赖一个前提，而这个前提从头到尾没有被提问，也没有被用户确认。
- **依赖对不上**：一个决定的前置决定还没定，它却已经定了；或者前置决定后来改了，它没有跟着改。
- **总结与原文不符**：最终总结写的，与逐轮问答里用户的原话不是一回事。总结把两个互相矛盾的答案合成一句话，属于这一类。
- **范围漂移**：总结里的范围比问答过程中用户实际同意的宽或窄。

## 二组：覆盖

看该问而没问的。**不要把它变成一张理想问题清单**——只报缺了它就写不出对的 spec 的那些。

- **失败与边界没问**：主流程谈定了，失败态、空态、并发、上限没有任何一轮碰过。
- **数据与迁移没问**：改动会动到已有数据的形状或存量，而记录里没有谈迁移。
- **权限与账务没问**：改动涉及谁能做、谁付钱，而记录里没有谈。
- **既有实现没查**：记录把某件事当成要新建的东西，但仓库里已经有一份。用检索工具取候选，再读当前源码验证，然后引出处。
- **拿事实当决定**：某一项答案是可以查出来的事实，`$mmw:mmw-grilling` 却让用户拍板。它应该走 `$mmw:mmw-research` 或 `$mmw:mmw-prototype`。
- **答案没有出处**：记录把用户的一句话当成事实往下用，而这句话没有任何来源，也没有标成待查。

## 出处怎么给

共用纪律 `mmw-reviewer/SKILL.md` 的「每条都要有出处」一节照常适用，位置写成 `understanding.md:<行号>`，加那一行的原文。讲前后矛盾的把两行都引出来。

引用仓库现状的那几条，仍然要给被审仓库里的 `文件:行号`。

## 这几条不适用

共用纪律的「几条红线」一节针对代码产物，这一道用不上。这一道也不查代码合同、迁移机制和登记。

## 这几种一定要报

两个答案互相矛盾而没有裁决；一个决定的前提从没问过；总结抹掉了用户实际表达过的分歧；该由事实回答的问题被拍成了决定；仓库里已经有的东西被当成要新建的。

## 出口

用户回答本身在这个视角里不算「产物缺陷」。你报的是**这次访谈**的缺口：该问没问、问了没对齐、答了没记准。

要解决的问题本身可疑时，走 `needs-redirection`；共同理解记录没拿到或者只拿到总结那一段，走 `needs-context`。两个出口的写法在共用纪律里。
