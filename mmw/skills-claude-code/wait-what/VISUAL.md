# 普通 HTML 可视化解释

把原文重新组织成能揭示关系的图、表或交互。根据内容，清楚展示整体结构、关键流程或重要对比。让读者先掌握全局，再定位具体节点和过程。概念或流程仍然抽象时，用真实场景中的具体示例逐步演示。如果一张完整的图或表能讲清内容，就在同一个视图中集中呈现。让读者直接看清全局关系。不要照抄原文，也不要只把原文放进图形框。

本文件把方案、文档或回复解释成 HTML。需要让用户按按钮驱动状态模型才能弄明白时，回 [SKILL.md](SKILL.md) 的「选择分支」移交 `/mmw-prototype`。

先完整读取用户要求解释的方案、文档或回复。根据当前对话确定要解释的范围。

可视化解释必须完整覆盖用户要求解释的内容。沿用其中的术语和表达，不创造新术语、缩写或代号。内容涉及仓库时，使用领域上下文中的 canonical 术语；存在冲突时显示冲突。

以图、表和交互为主，只使用必要的标签、短说明和出处。让读者尽量不打开原文也能看懂。

## 路线一：完整 HTML

这是默认路线。生成完整 HTML。要解释的内容本身就是仓库里的一个文件时，HTML 放在它旁边，同名换成 `.html`。要解释的内容只存在于这段对话里时，问用户想保存到哪个目录，然后把这段内容和 HTML 一起放进去。

宿主有把本地 HTML 发布成可访问网页的能力时，用它发布，发布出去的内容与本地 HTML 一致；发布成功后把网址写进本地 HTML 同目录的 `<同名>.url` 里，一行一个网址——同一份本地 HTML 以后再更新时，读它拿到上次的站点，复用那个站点存成新的一版。完成后交回本地路径和网址。宿主没有这个能力时，本地 HTML 就是最终产物。

这条路线完成时，本地 HTML 已保存并能打开。宿主支持发布的，站点上已经有本次更新的新版本；发布失败或者宿主根本不支持发布的，保留本地 HTML 并说清网页这一步没有做——不要说成做了。

## 路线二：对话内可视化

只有用户要求解释的范围非常精确、非常小，而且一个紧凑的图或表可以完整讲清时，才使用这条路线。

宿主能在对话里直接渲染 HTML fragment 时，用一个 fragment 把这个小范围完整讲清。宿主渲染不了时这条路线不成立——回路线一出完整 HTML，不要把 fragment 的源码当文本贴出来充数。

这条路线完成时，HTML fragment 已经在对话内显示出来，并完整覆盖用户要求解释的范围。

| 情况 | 处理 |
| --- | --- |
| 完整 HTML 已在本地保存，而且有调用方等待 | 把本地 HTML 路径交回调用方；宿主支持发布的，连网址一起交 |
| 本地 HTML 已保存但网页没发出去，而且有调用方等待 | 交回本地 HTML 路径，并说清网页这一步没做 |
| 小范围内容已经在对话内完整显示，而且有调用方等待 | 把对话内可视化结果交回调用方 |
| 完整 HTML 或对话内可视化已经完成，而且没有调用方等待 | 展示可视化并说明本地文件位置或对话内结果 |
| 本地 HTML 已保存但网页没发出去，而且没有调用方等待 | 展示本地产物并说清网页这一步没做 |
