# Logic HTML

Logic HTML 由一个原生 HTML 外壳和一个纯 `module` 组成，让用户用按钮驱动状态模型。

开始前取得验证问题、现有状态模型或脚本、真实场景和 `logic/` 输出路径。缺少会改变行为的输入时，向用户取得。

## 1. 说明问题

读取现有状态模型或脚本。页面顶部写明用户正在驱动什么，以及本轮要判断什么。

## 2. 隔离可移植逻辑

把实际逻辑放进一个不访问 DOM 的纯 `module`：

- 动作是离散事件，而且状态是单一值时，使用纯 `reducer`。
- 合法动作取决于当前状态时，使用状态机。
- 只有数据转换，没有隐含当前状态时，使用一组纯函数。
- 逻辑确实持有持续的内部状态时，使用具有清晰方法集合的类或 `module`。

把纯 `module` 单独保存在 `logic/`。现有逻辑不能直接在浏览器运行时，只按其公开行为移植当前问题需要的部分。现有行为无法表达问题时停止构建，并记录这个事实。

## 3. 构建 HTML

使用原生 HTML、CSS 和 JavaScript，不使用框架或打包器。页面外壳只调用纯 `module`。

页面使用领域语言，并按以下顺序布局：

1. 标题和一行说明。标题让人一眼看出这是 prototype；说明写清当前验证问题。
2. 当前状态。使用带标签的字段展示完整相关状态，不直接倾倒原始 JSON。每次动作后重新渲染。
3. `free-play` 按钮。每种动作一个按钮，用户可以任意排序尝试。非法动作也可以触发，由模型明确拒绝并说明原因。
4. `guided walkthrough`。一个场景一个标签页。每个场景说明初始情形和观察重点，并提供按顺序执行的真实动作按钮。

每个 `guided walkthrough` 都能重置到相同初态，并覆盖正常路径、一个真实边界和一次非法动作。

## 4. 交给用户驱动状态模型

按 [SKILL.md](SKILL.md) 的浏览器规则打开 Logic HTML。确认可见并截图后，把 `free-play` 和所有 `guided walkthrough` 交给用户。收到反馈后按 [capture.md](capture.md) 记录；后续轮次修改同一份资产。

## 完成判据

- 页面显示验证问题和 prototype 身份。
- 所有动作调用 `logic/` 中同一个纯 `module`。
- 每次动作后显示完整相关状态。
- `free-play`、可重复场景和真实边界都能运行。
