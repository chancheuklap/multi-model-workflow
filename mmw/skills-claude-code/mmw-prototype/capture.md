# 保存逐轮结论

用户给出走查意见后，更新 `prototype 产物路径` 下的 `README.md`。这份 `README.md` 是下游读取 prototype 的入口。

## 1. 记录本轮

每一轮记录以下内容：

- 本轮验证问题。
- 本轮可运行资产的精确路径和运行方式。
- 当前 UI mockup 的精确路径；没有时写「无」。
- 变体组的精确路径、变体 key 与目录对应关系；没有时写「无」。
- 用户原话。
- 根据用户意见完成的修改。
- 本轮验证结果。
- 下一轮问题，或者用户选中的产物路径。
- 整个方向不成立时，记录击穿方向的事实。

用户要求修改时，继续修改同一份 prototype。用户接受 current 时，记录它是本轮结果。用户选择或组合变体时，先按 [UI.md](UI.md) 形成 `mockup/current/`。用户重新走查并确认后，再记录本轮验证结果。

## 2. 维护当前索引

每一轮都把下面内容维护成最新状态：

- 当前问题和逐轮用户走查结论。
- `mockup/current/` 的精确路径和运行方式；没有时写「无」。
- 每个变体组回答的问题、入口、变体 key、目录和用户选择；没有时写「无」。
- 其他选中产物的精确路径；没有时写「无」。
- 落选变体及其形成的否定约束；没有时写「无」。
- 页面功能或按钮对应的后端脚本、接口合同或可复用 `module` 路径；没有界面时写「无界面对应」。
- 下游可以直接参考或复用的内容及其精确路径；没有时写「无」。

**可复用指的是想法，不是工程完备度。** prototype 没有测试，错误处理最少。下游折进正式代码时，按生产标准重写。把这句话写在 `README.md` 的可复用内容之前。

调试外壳、变体切换器和落选变体留在 `mockup/`，但不列为可复用内容。

## 3. 提交持久资产

提交本轮可运行资产和更新后的 `README.md`。`scratch 路径` 下的过程材料不提交。提交后，只删除本轮 prototype 在 `scratch 路径` 下建立的文件。

## 4. 交回调用方

交回以下内容：

- 当前验证问题和用户走查结论。
- `README.md` 的精确路径。
- 当前 UI mockup 的精确路径和运行方式；没有时写「无」。
- 本轮变体组、变体 key 和用户选择；没有时写「无」。
- 其他选中产物的精确路径；没有时写「无」。
- 当前验证事实和否定约束。
- 页面功能或按钮与后端行为的精确对应；没有 UI mockup 时写「无界面对应」。
- 下游可以直接参考或复用的内容及其精确路径；没有时写「无」。

交回之后结束。调用方负责 issue 评论、ticket、map 和后续用户确认。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 用户要求继续修改 | **自己继续**：回当前工作面修改同一份 prototype，并重新走查 |
| 当前问题已经回答，而且有调用方等待 | **移交**：交回第 4 节内容 |
| 当前问题已经回答，没有调用方等待，而且需要形成 spec | **移交**：`/mmw-to-spec` |
| 当前问题已经回答，没有调用方等待，而且不需要形成 spec | **停**：展示本轮结论、`README.md` 路径和选中产物路径 |
| 整个方向不成立，而且有调用方等待 | **移交**：交回击穿方向的事实和 `README.md` 路径 |
| 整个方向不成立，而且没有调用方等待 | **移交**：`/mmw-grilling` |
