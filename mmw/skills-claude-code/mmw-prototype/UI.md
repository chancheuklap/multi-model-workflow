# UI Mockup

UI mockup 用可运行页面理顺页面、状态和操作路径。它是 prototype 资产，不是临时预览。用户在浏览器中走查，选择一个方向，或者指出需要组合和修改的部分。

## 1. 确定本轮验证问题

用 [SKILL.md](SKILL.md) 写入 `README.md` 的初始问题确定读取范围。先读取 `README.md` 和 `mockup/current/`。只读取 `README.md` 点名的历史变体，以及与初始问题直接相关的其他变体。再读取相关文档、讨论结论、真实数据、组件库和样式系统。

读完后，把以下内容写进 `README.md` 的「当前一轮」：

- 初始问题。
- 本轮验证问题。
- 本轮保持不变的部分。
- 本轮路径：完整变体、局部变体，或者直接创建或修改。

| 不确定范围 | 本轮路径 |
| --- | --- |
| 没有不确定方向 | 没有当前 mockup 时直接创建 `mockup/current/`；已有当前 mockup 时直接修改它 |
| 整个页面或操作流程不确定 | 以相关文档和已有当前 mockup 为依据，生成多个完整变体 |
| 某个页面、组件、状态或操作路径不确定 | 保持其他部分不变，只为这一部分生成多个局部变体 |

没有当前 mockup，但只有局部方向不明确时，先把已经明确的部分建立为 `mockup/current/`。这个 current 是局部比较的基底。开始建立局部变体后，选择前不再修改这个基底。

变体是解决方向不确定的手段。已有当前 mockup 时，以它为起点继续优化。只有整个页面或操作流程需要重新比较时，才生成新的完整变体。

这一节完成时，`README.md` 必须已经写清本轮验证问题、保持不变的部分和本轮路径。

## 2. 选择承载形态和运行入口

| 项目情况 | 承载形态 |
| --- | --- |
| 已有成熟应用，而且 prototype 天然属于某个页面或流程 | 挂入已有页面。保留真实页头、侧边栏、数据密度、取数、参数和鉴权，只替换正在验证的界面部分 |
| 全新产品、纯后端仓库，或者需要跨前端和后端验证可行性 | 在 `mockup/current/` 或对应变体目录中使用独立 HTML；current 的入口固定为 `mockup/current/index.html` |
| 已有应用，但没有任何现有页面能够承载一个新的顶层界面 | 按项目现有路由约定建立明确标记的 prototype 路由 |

UI mockup 的持久资产必须保存在 `mockup/`。应用源码中确实需要 route 或挂载文件时，只保留让 mockup 运行所需的薄接线。把接线文件和 `mockup/` 内资产的精确对应关系写进 `README.md`。

## 3. 创建当前 mockup 或变体

直接创建或修改时，UI mockup 资产只改 `mockup/current/`。应用确实需要新增 route 或挂载文件时，可以同时修改第 2 节规定的薄接线。不要把 UI mockup 实现移到应用源码。`mockup/current/` 是后续轮次继续优化的唯一当前 mockup。

需要完整变体或局部变体时，完整读取 [UI-VARIANTS.md](UI-VARIANTS.md)。完成该文件后，回到本文件第 6 节打开页面并处理用户选择。

## 4. 验收 current 或变体

current 或变体交给用户前，逐项完成以下共同验收：

- 使用 `README.md` 中的运行方式能够启动。
- 页面完整加载。
- 本轮相关按钮可以操作。
- 本轮相关状态可以呈现。
- 页面没有阻断走查的 console 错误。
- 主 agent 已经操作本轮关键路径。
- 每个页面已经留下截图。

不适用于本轮的项目写「不适用」并说明原因。适用项目全部通过后，current 或变体才算可以运行。

## 5. 连接后端行为

初轮可以使用桩来验证 UI 流程。为本轮验证问题新建或修改的每个页面功能或按钮，都必须在 `README.md` 中记录一种或多种当前行为类型：

| 当前行为类型 | 记录内容 |
| --- | --- |
| `frontend` | 正式纯前端行为的实现文件精确路径，例如标签页切换、展开收起或本地筛选 |
| `stub` | 桩文件的精确路径，以及它正在替代的正式行为 |
| `contract` | 接口合同的精确路径，以及尚未接入的正式实现 |
| `backend` | 可运行后端脚本或可复用 `module` 的精确路径 |

一个按钮跨越多层时，分别记录各层类型。例如，前端事件调用桩时，同时记录 `frontend` 和 `stub`。

写操作尚未接入真实后端时，页面必须清楚显示桩行为。如果当前问题必须依赖真实写操作才能判断，先在 `README.md` 记录这项依赖。结束当前 UI 工作面，按 [SKILL.md](SKILL.md) 第 3 节在下一轮完成对应后端 prototype。后端可以运行后，再回到同一份 UI mockup 开始下一轮并接入它。不要在同一轮交错两个工作面。

每个实际存在的页面状态都应能呈现，包括与当前问题相关的加载、空、错误、成功和部分完成状态。页面变化后显示用户判断当前问题所需的完整相关状态。

## 6. 打开、走查和处理选择

把页面地址和全部变体 key 交给用户。只有一个方向时，直接给出该页面地址。

按 [SKILL.md](SKILL.md)「用户走查」的浏览器规则打开全部页面。宿主有内置浏览器时使用内置浏览器。宿主没有内置浏览器时使用 Playwright。用户和主 agent 必须看到同一个运行中的 mockup 和同一组 URL；两者不必使用同一个浏览器进程。

用户给出意见后，先按 [capture.md](capture.md) 第 1 节记录用户原话。再按下表继续：

| 用户意见 | 动作 | 本轮何时完成 |
| --- | --- | --- |
| 继续修改当前 mockup 或某个变体 | 修改对应资产，重新执行第 4 节验收并重新走查 | 用户确认不再修改时 |
| 接受当前 mockup | 不再修改当前资产；完成第 7 节 | 用户明确确认当前 mockup 可以作为本轮结果时 |
| 选择一个变体 | 把选中结果独立写进 `mockup/current/`，移除切换器和对变体目录的运行依赖，再验收并打开当前 mockup | 用户确认当前 mockup 与选择一致时 |
| 组合多个变体 | 把用户指定的部分独立写进 `mockup/current/`，移除切换器和对变体目录的运行依赖，再验收并打开当前 mockup | 用户确认组合结果时 |
| 否定整个方向 | 保持现有资产，记录击穿方向的事实 | 事实已经写进 `README.md` 时 |

选择或组合变体后，记录选择本身不算完成。`mockup/current/` 已经形成，而且用户重新走查并确认后，才进入第 7 节。

## 7. 保存结果

当前问题已经通过走查得到答案后，按 [capture.md](capture.md) 完成 `README.md`、提交和交回。

`mockup/current/` 中经过用户确认的页面结构、组件和交互，是下游可以直接参考或复用的内容。变体组、`preview/` 和切换器继续作为 prototype 资产保存，不列为可复用内容。
