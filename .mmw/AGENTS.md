# .mmw

This repository's own product answers: root `target.json` lists `task-board`, whose `task-board/target.json` declares its commands, `task-board/harness/` starts and stops it behind a fake `gh`, `task-board/stories/` serves its component stories, `task-board/journeys/` holds the whole-product journeys. The design package is `efforts/task-board/claude-design/`; `efforts/task-board/screen-contract.yaml` maps each complete scene name to the input value that drew it.

## Key Conventions

- `task-board/harness/target.py` runs only under a lease: without `MMW_DATA_DIR` and `MMW_PORT_BASE` it refuses and points at `lease.py run --`. `start` is idempotent (0 when the recorded pid still runs the same `server.py` at the same origin with the same token, otherwise it stops the old one first) and names the holder through `lsof` when something else has the port.
- `start` prepends `task-board/harness/bin` to the board's `PATH`, gives the board a private `MMW_HOME` under `MMW_DATA_DIR`, seeds its `models.json` from the dispatch skill's `hosts.json` defaults, one row per role (a copy left with another set of rows is seeded again), and points `MMW_HOST_CATALOG` at `task-board/harness/catalog.json`. The catalog offers every seeded row and an alternative value, so a journey can change and save one cell without touching this machine's real configuration.
- `start` reads `MMW_BREAK` as `<METHOD> <route>`. `task-board/harness/board_server.py` makes only that matching board interface answer `503`, and `start` prints `BREAK ARMED <METHOD> <route>` after the broken board answers.
- The fake `gh` looks up the exact compact JSON of its argument array in `task-board/harness/github/responses.json`; keys keep `{owner}` and `{repo}` literally because the board hands those placeholders to `gh` to expand. The second comments read answers 304 (exit 1, `gh: HTTP 304` on stderr) so a journey walks the production conditional-request path.
- `task-board/journeys/<flow>/run` is started by `journey.py run task-board/<flow>`, which uppercases every key `discover` prints into the environment (`smoke.py` reads `ORIGIN` and `INSTANCE_TOKEN` from there). `task-board/harness/target.py` arms the one `MMW_BREAK` interface for a journey run with `--break`; the same script receives no pass marker and must fail after reading the result back. The smoke journey runs without `--break`: its second pass keeps the product stopped and repoints every discovered address to a closed port, and it must fail there or the run reports `JOURNEY GREEN WITHOUT PRODUCT`.
- `task-board/stories/serve.py` serves the shipped modules from `mmw-v3/board/page/` under `/product/`, so a story renders production code. It requires `python3` and `node` on `PATH`, executes each trusted `input.file` as JavaScript in an isolated `window`, then resolves the full scene name through the screen contract's `input.value` and `input.with`. `task-board/stories/story.mjs` swaps the API transport for a stand-in that records `{method, path, fields}` as `window.storyCalls()` and reads per-`METHOD path` answers from `window.__STORY_ANSWERS__`; an answer can set any status and body or remain pending.

- `task-board/target.json` declares one leased port. `task-board/harness/target.py doctor` reads the running board's pid and startup commit from its harness-only endpoint, checks its page token and actual TCP listeners with `lsof`, and leaves the process and data unchanged.

## Gotchas

- An unregistered call makes the fake `gh` exit 2 with `no gh response …; add that exact call before rerunning`: one changed argument order, flag or GraphQL string in how the board calls `gh` breaks every journey until `responses.json` is updated. It also refuses without `MMW_DATA_DIR`, since every call is appended to `$MMW_DATA_DIR/gh-calls` first.
- `task-board/stories/serve.py` listens on a port the machine hands out and prints it as `origin`; it takes no lease, so a story criterion costs no instance slot. A `?page=` with no `task-board/stories/adapters/<page>.mjs` is a 404: the adapters are `board`, `topbar`, `tasks`, `canvas`, `detail`, and `settings`.
- Root `target.json` has no `checks` key, and `task-board/target.json`'s `leaves_machine` declares the one thing that leaves the machine: the board reading GitHub through `gh`. Its `harness_markers` declares `MMW_BREAK`.
