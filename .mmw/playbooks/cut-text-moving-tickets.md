### Cut text-moving tickets

In this repository, a ticket that writes or moves skill text carries a manifest of every sentence it carries, rewrites, adds and drops, and two checks hold the worker to that manifest. The worker reads the ticket at night with nobody to ask, so a sentence the manifest leaves open is written by someone who was not in the conversation that settled it. These steps add to the `to-tickets` skill's own while **Cut the tickets** of **Write a spec and tickets** runs; they live here because the scripts they run are in `mmw-v2/tests/lib/`, which only this repository has.

1. **Pin `from`.** Give each ticket that the `to-tickets` skill drafts and that writes or moves skill text (a `.md` file under `mmw-v2/skills/`, `mmw-v2/upstream*/skills/` or `.mmw/playbooks/`, or another file its manifest names, such as the root `AGENTS.md`) a `## Moves` section between `## Owns` and `## Acceptance criteria`, holding one fence with the info string `moves`. Its first line is `from <sha>`: the full sha of the base branch's `HEAD` when the batch is cut, the same in every ticket of the batch. Every source range is read at that commit, so a ticket that lands earlier in the night never moves the lines a later ticket reads.
   Done when every such ticket has one `## Moves` section with one `moves` fence whose `from` is that full sha.
2. **Write the manifest from the exemplar notes.** Follow the notes of the exemplar for that kind of component under `docs/research/workflow-compare/exemplars/`, read as its `README.md` `## 怎样作为票的基准使用` says, and copy the exemplar's sentences as they stand (**principle-the-baseline-is-a-contract**). Write every sentence that carries understanding (an ownership line, an opening paragraph, a stance, a `**Why:**`, a `Done when`, a `**Reply:**`, a sentence that connects an upstream skill to the workflow) whole, in a `new` line with its source, so the worker copies it instead of drafting it. A line that opens with bold text is a title unit followed by its sentences: give the bold text its own `new <target> title` line, then one `new` line per sentence, since a `new` line that holds two sentences never matches. A sentence that starts with inline code stays joined to the sentence before it, so the two go in one `new` line. Carried text is a `move` or a `copy` followed by one `replace` for each rewrite, case and punctuation included; an edit in place is a `copy` from the file to itself, and a source that a night role still reads is always a `copy`. Each sentence of a carried range that goes nowhere gets a `drop` line saying what it guided and what guides that case afterwards.
   Done when every sentence the ticket adds, rewrites, carries or drops is a line of its manifest, and no `new` line holds more than one sentence.
3. **Copy only the rename rows the ticket uses.** Copy as `rename` lines only the rows of the effort's `renames.tsv` under `docs/specs/<effort>/` that this ticket executes, or whose old name its own text contains. Two tickets that carry the same row cannot run side by side: put the one that executes the rename first, and record the edge in the other's `BLOCKED BY` line, which the `to-tickets` skill publishes as a blocking edge.
   Done when every `rename` line equals a row of the table, and every two drafts that carry one row are joined by a `BLOCKED BY` chain.
4. **Lint the drafts.** Save each draft as `<draft name>.md` in one directory, headed by `TITLE:`, `LABELS:` and `BLOCKED BY:` lines and a `---` line, and run `uv run --quiet mmw-v2/tests/lib/check_verbatim_moves.py --lint-drafts <directory> --renames-table docs/specs/<effort>/renames.tsv`, adding `--renames-table mmw-v2/import/pstack-rewrites.tsv` for a ticket that **Import a component** cuts. Fix each finding and run it again until it prints `DRAFTS OK <n> drafts` with `<n>` the number of drafts you wrote: a directory that lacks a draft lints clean as well (**principle-silence-is-never-a-pass**).
   Done when the last run printed `DRAFTS OK` and counted every draft.
5. **Add the two text criteria.** Give each such ticket two criteria in the `to-tickets` skill's four-line form. The verbatim one is `CHECK: uv run --quiet mmw-v2/tests/lib/check_verbatim_moves.py --ticket "$MMW_TICKET"` with `EXPECT: /^VERBATIM OK \d+ /m`. The structure one is `CHECK: uv run --quiet mmw-v2/tests/lib/check_component_structure.py <files>` with `EXPECT: /^STRUCTURE OK \d+ files?/m`, listing only the component files the ticket writes under `mmw-v2/skills/` and `.mmw/playbooks/`, `INDEX.md` excepted: the lint skips any other file, and with none left it exits 1 on `0 findings in 0 files`, so a ticket that writes no component file carries no structure criterion. A ticket that pays exception debt due in a batch adds `--batch <Bn>`, because without it the exception table still cancels the finding the ticket was meant to remove. A `drop` only permits a removal, so a ticket that deletes text also gets a criterion that the text is gone.
   Done when every ticket that writes or moves skill text carries the verbatim criterion, every one that writes a component file carries the structure criterion, and every deletion has a check of its own.
6. **Give the last ticket the whole-tree criteria.** The ticket that lands last, blocked by every other ticket of the batch, carries the criteria that read the whole tree: `bash mmw-v2/tests/lib/run_shared_lints.sh`, and `uv run --quiet mmw-v2/tests/lib/check_component_structure.py --batch <Bn>` with `EXPECT: /^STRUCTURE OK \d+ files \(\d+ exceptions in use, 0 stale\)/m`. The closing pass runs every criterion of the batch again on the base branch, so a whole-tree criterion on an earlier ticket would be decided by the tickets that land after it, as the `to-tickets` skill says of a criterion that names what a later ticket may change. Only `0 stale` proves the exception table was cleaned: an exception already paid but still listed prints a warning and leaves the exit at 0 (**principle-silence-is-never-a-pass**).
   Done when exactly one ticket carries these two criteria and it is blocked by every other ticket of the batch.

**Reply:** the drafts directory; the `from` sha; the last `--lint-drafts` line; which ticket carries the whole-tree criteria.
