### Promote a change

Every host on this machine reads skills and hooks from the installed checkout `.worktrees/mmw-installed`, so a change committed in the main worktree reaches no session until this playbook has moved that checkout. **Deliver a change** runs this playbook here, because this repository's `.mmw/target.json` names it in `delivery`.

1. **Commit on dev.** Commit the change on `dev` in the main worktree once the suites that `TESTING.md` `## Which suites a change needs` names for it have passed (**principle-prove-it-works**). After **Move the installed checkout**, every session on this machine runs this commit, so a change nobody has seen work reaches all of them at once.
   Done when `git log -1 dev` shows the change and `git status` in the main worktree lists none of its files.
2. **Fast-forward main.** Run `git push . dev:main`, which moves `main` to `dev` only when `main` has no commit that `dev` lacks. When git refuses it as not a fast-forward, stop and show the user the commits only `main` has: rewriting `main` cannot be undone, so that choice is theirs (**principle-never-block-on-the-human**).
   Done when `git rev-parse main` prints the same commit as `git rev-parse dev`, or the user has the commits that stopped it.
3. **Move the installed checkout.** Run `bash mmw-v2/install.sh --check` and read its last line. While it is `NOT-SAFE-TO-MOVE-INSTALLED`, with `OPEN-WATCH` or `LIVE-LOCK` lines above it, a watch is running on the installed checkout, and this step waits until it closes (`## Self-hosting boundary` in the root `AGENTS.md`). On `SAFE-TO-MOVE-INSTALLED`, list what the move brings with `git diff --name-only $(git -C .worktrees/mmw-installed rev-parse HEAD) main`. When the list holds `mmw-v2/skills.txt`, `mmw-v2/install.sh`, `mmw-v2/hook-launcher.py`, or a file of a skill whose `skills.txt` line ends in `+model-invoked`, the move needs the full install as well: ask the user to authorise it, and run the two as one command sequence, `git -C .worktrees/mmw-installed checkout --detach main && bash .worktrees/mmw-installed/mmw-v2/install.sh`. Run apart, they would leave every host reading the new checkout through old skill copies and old hook registrations. The full install records the checkout it runs from in `~/.mmw/installed-root`, so it is the installed checkout's own `install.sh` that runs, never the main worktree's. Without such a file in the list, the move is `git -C .worktrees/mmw-installed checkout --detach main` alone. Either way, confirm with `bash mmw-v2/install.sh --check`. Until the user authorises the install, report this step as waiting on them, not as done (**principle-human-steps-stay-human**).
   Done when the `--check` run after the move exits 0 or the user has each line it printed that was not ok, or the step waits on an open watch or on the user's go-ahead and the user has heard which.
4. **Push both.** Run `git push origin dev main`. Read the result from the remote itself, not from the push's own output (**principle-prove-it-works**).
   Done when `git ls-remote origin dev main` shows the commits that `git rev-parse dev main` prints.

**Reply:** where `main`, the installed checkout and `origin` now stand; whether the full `install.sh` ran, or waits for the user or for a watch to close.
