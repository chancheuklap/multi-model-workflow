### Pull an upstream

This repository has changed text in some of its upstream subtrees, and `mmw-v2/merge-notes/` records each change: the passage, why it changed, and which side a later pull keeps. A pull is finished when every recorded change has survived it or been given up on purpose, not when git stops reporting conflicts.

1. **Pull the subtree.** Pull one subtree per run, from the main worktree on `dev` with nothing uncommitted, with the `git subtree pull --squash` command kept for that subtree: `mmw-v2/merge-notes/README.md` `## 上游更新时怎么用` has it for `mmw-v2/upstream/`, and the subtree's own merge-note for each of the others (`diagram-design.md`, `unlazy.md`, and `pstack.md` `## 以后拉更新`). Run the command as that note writes it, not from memory, since the note is where a change to it is made (**principle-one-home-per-meaning**).
   Done when the pull has made its `Squashed '<prefix>/'` commit and merged it, or has stopped with conflicts left in the working tree.
2. **Resolve by the merge-notes.** Read `mmw-v2/merge-notes/README.md` first; resolve each conflict by the skill's merge-note entry, take upstream for passages no note covers. Settle the merge itself with the `resolving-merge-conflicts` skill, keeping for each conflicted passage the side its merge-note entry names. Then read each changed skill's `SKILL.md` and references through once, and make sure no two sentences contradict each other. When upstream renamed, merged or split a file a merge-note cites, correct that note's locations. Every paragraph that still differs from upstream maps to a merge-note entry, as `mmw-v2/skills/mmw/references/skill-set-rules.md` `### Upstream skills` requires.
   Done when no file holds a conflict marker, the merge is committed, and every paragraph that differs from upstream has its merge-note entry.
3. **For unlazy, read every listed diff and run its suite.** For unlazy, also read upstream's diff of every passage its merge-note lists, conflicting or not, and run `bash mmw-v2/tests/verify-ticket/run.sh`. Unlazy's gate-check is the engine the `verify-ticket` skill judges criteria with, and an upstream condition that merged without a conflict can still quietly undo one of this repository's changes to it.
   Done when every passage `mmw-v2/merge-notes/unlazy.md` lists has had its upstream diff read, and the suite's last line is `all passed`.
4. **Refresh imported pstack files.** For `mmw-v2/upstream-pstack/` only, run `python3 mmw-v2/import/import_component.py --refresh`. It reads `mmw-v2/skills/mmw/imports.tsv`, where every file imported into the `mmw` skill has a row, and prints `STALE <local> <source>` for a row without judgement changes whose copy no longer matches the subtree, `REVIEW <local> <source>` for a row with judgement changes whose `commit` is not the one the subtree now pins, and last `REFRESH <rows> <stale> <review>`. It lists rows and prints no difference: compare each `<local>` with its `<source>` yourself, for example with `git diff --no-index <source> <local>`. Bring a `STALE` row up to date by running the importer again for that component. For a `REVIEW` row, keep or redo each judgement change against upstream's new text as its row in `mmw-v2/merge-notes/pstack.md` `## 判断改动` explains, then write the `git-subtree-split` hash of the newest squash commit into the row's `commit` column, which is what `--refresh` compares.
   Done when `--refresh` exits 0 and prints `REFRESH <rows> 0 0`.
5. **Check.** Run `bash mmw-v2/tests/lib/run_shared_lints.sh`, which runs `check_wiring.py` with the other shared lints, then `bash mmw-v2/install.sh --check`. A `没查` line from `--check` means a check could not run: report it as unchecked, never as a pass (**principle-silence-is-never-a-pass**).
   Done when `run_shared_lints.sh` exits 0, and `--check` exits 0 or the user has each line it printed that was not ok.
6. **Deliver.** Run **Deliver a change**.
   Done when the pull is committed on `dev` and the user has heard how far **Deliver a change** took it.

**Reply:** the subtree and the upstream commit it now pins; each conflict and the merge-note entry that settled it; each `--refresh` row and what was done with it.
