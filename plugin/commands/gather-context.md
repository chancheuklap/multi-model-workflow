你在 design 阶段的一问一答途中。用户用本命令要你**就当前缺口做一次定向上下文收集，补进设计文档**，然后续上问答——不打断节奏。

按 design 方法论里的「按需补充上下文」流程做（单一源在 `${CLAUDE_PLUGIN_ROOT}/skills/orchestrate/references/design/discussion.md` 的同名小节，现读那节照做，别在这另记一份）：

1. 一句话点明缺口（缺哪个事实 / 哪条假设没坐实）。
2. 按缺口取证：内部 `rg`/`Read`（给 `path:line`）、外部网搜成熟方案 / 库——**亲验，子代理 / 网文是线索不是结论**。
3. 坐实的写进设计草稿对应章节 / Open Decisions / 领域文档，**不只留在对话里**。
4. 回到原问答续上，基线从文档续。

用户在命令后补的话 = 这次要收集的缺口；没补就先问他要补哪一块，别空跑。
