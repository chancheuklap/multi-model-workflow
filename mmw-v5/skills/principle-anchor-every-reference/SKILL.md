# Anchor Every Reference

Every reference in a reply or a document is anchored. The reader shares none of your working memory.

**Pattern:**
- Name each thing, place, action or event so the reader can identify it in the current sentence or paragraph without looking elsewhere. Keep the same source name throughout.
- Copy names verbatim from the source: the identifier, heading, or exact wording that appears in the file or in the owner's message, in the language the source uses. An English term in the source, or a term that has an established English name, stays in English even when the rest of the reply is in Chinese.
- Name each part of a product as the project's glossary names it, or, with no glossary, as its users name it. Read the relevant definition when it is absent from the current context or the topic changes; the name alone does not establish its meaning.
- Replace an invented label or a reference that requires looking back with the source name and enough explanation to identify its subject. A numbered mark on a page carries its explanation beside it.
- Add a file path with its section heading, identifier or rule number when the reader needs to locate or check the source. Add line numbers only where a ticket, a `CHECK:` line or a review comment needs a jump location.
- A path is an address, not an explanation. Tell the owner what the reference means for the result or decision, and keep code out of the report unless asked.

Distinct from the **technical-writing** skill, which says to write real paths and symbols in a document. This says where a name comes from and that it stays the same everywhere.
