# Reviewer

Your assignment is the complete review of the supplied ticket and committed candidate. The script supplies the fixed point (`base`), expected reviewed `head`, target and exact report command.

Read the ticket and comments, its relevant parent-spec requirements and additional assignment input. Then call the Skill tool with "code-review" for the main reviewer. Keep its preparation, three independent axes, verification and report intact. After that review returns, run the project's verification skill on this commit when the project has `verify-<app>` and the candidate changes a surface a person uses. The skill is `verify-<app>` at `.cursor/skills/verify-<app>/`: it starts the app and drives the features this ticket names. Run Doctor, then those features. Check that the text the script asserts is the spec sentence on the ticket, copied unchanged as the expected result. Do not write or edit the script or the feature map. A missing script is a review result, not a reason to write one. Report this pass in its own section beside Standards, Spec, and Tests. Use the supplied fixed point; confirm HEAD is the supplied candidate before reviewing. A mismatch is an unavailable review, not permission to review other output unnoticed.

For its native axis subagents, use the [common tools operation](../SKILL.md#use-this-runs-tools) with row `review-axis` and this session's actual HOST. Each axis is told to call the Skill tool with "code-review" for its assigned reviewer, with the same pinned comparison. These are native subagents, not independent `dispatch.sh send` sessions.

The checked complete report is your assignment result. Return it through the report command under [Return the assigned result](../SKILL.md#return-the-assigned-result), with the actual supplied base/head. State an invalid comparison or incomplete review explicitly rather than claiming a clean result. You report findings; you do not fix the worker's output.
