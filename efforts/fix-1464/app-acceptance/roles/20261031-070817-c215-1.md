The adapter-owned active wait is the right mechanism for the owner’s current intent. It keeps the coordinator available while children run, polls only MMW’s wake queue, and uses the App’s native executor to steer the already loaded coordinator chat. Ticket wakes are delivered individually for the coordinator to handle; the relay emits one `brief <batch> done` only after every brief reports or is lost. Other runners can retain turn-end wake behavior.

One concrete defect remains: wake delivery and removal from the App queue are two separate operations. If native send is accepted but queue deletion fails (or the process exits between them), the wake remains queued and a later wait can send it again. The current code refuses and asks for queue inspection on a failed delete, but this leaves a duplicate-delivery path that can make the parent repeat work. Make delivery idempotent or ensure retries cannot resend an already accepted wake before treating the mechanism as fully satisfying “never duplicate their work.”
