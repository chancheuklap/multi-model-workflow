# 编写 framework-mode 的 playbook

**Playbook 写一类任务如何推进到交付，skill 写完成某项工作的具体方法。** Playbook 选择并衔接所需方法，skill 规定一种方法需要什么材料、怎样执行、交回什么。

## 判断一段提示词放在哪里

| 提示词决定的事情 | 放在哪里 |
| --- | --- |
| 哪种任务从这条流程开始，各步怎样衔接，何时继续、暂停、交回或结束 | Playbook |
| 某项工作具体怎样做，方法需要什么输入，内部怎样分工，怎样判断结果 | Skill |
| 各类任务共同遵守的授权、委派和回复规则 | Mode |
| 这一次任务的文件、符号、目标值和具体命令 | 当次计划或任务说明 |

**两类内容混在一起时，在方法返回结果的位置拆开。** Playbook 保留调用条件、所需结果及后续动作。Skill 负责产生那个结果的做法。一两句话足以交代的局部操作直接留在步骤里。

区分依据是职责。Skill 也能有完整流程和子代理，playbook 也能被复用。把方法独立出来，是为了让调用者使用它的结果，并让方法的具体做法有一个维护位置。[完整区别](../README.md#区分-playbook-和-skill) · [pstack 的流程读取规则](../../upstream/pstack/skills/poteto-mode/SKILL.md#playbooks)

## 写一份可以直接执行的 playbook

1. **先写入口和终点。** 在 mode 的 Playbooks 索引加一行，用用户给得出的条件区分相邻流程。正文放在 `playbooks/<title>.md`，文件名采用小写和连字符，另取文件名时在索引注明。主对话选中以后才读全文。[mode 的 Playbooks 索引](../SKILL.md#playbooks)
2. **从终点倒推步骤。** 写出哪些证据必须先取得，哪些动作依赖它，什么结果会让主对话停止或改走另一条路。用主对话可以原样抄进待办的动作句。按依赖顺序排列，运行时跳过某步仍保留该项并写明原因。[pstack 路由指南](../../upstream/pstack/docs/guide/02-poteto-mode.md)
3. **在用得上的那一步调用 skill。** 写清交给它什么、需要拿回什么、结果怎样影响下一步。一两句能交代完的局部动作就写在步骤里。值得单独调用或维护的方法再抽为 skill。若一段内容同时规定整项任务的下一步和某种方法的内部做法，就在方法产生结果的位置分开写。
4. **写出交回什么就停。** 在 `Reply` 中列这条流程特有的产物、证据和未决项。需要另一个流程接手时，写清交接条件。执行需要用户确认时，把暂停点写在对应动作之前。[Multi-phase plan](../../upstream/pstack/skills/poteto-mode/playbooks/multi-phase-plan.md)

步骤需要子代理时，补上分给它的范围、完成条件和返回材料。主对话收到结果后要做的检查也写在这一步。子代理如何读 mode、何时新建、按什么配置选模型，沿用 mode 的 Subagents 指令。调用自行组织子代理的 skill 时，沿用该 skill 的分工。[两种委派的判断规则](../README.md#区分两种委派)

常见的正文可以这样起笔。需要几步就写几步，已有 playbook 能承担一段完整流程时可以直接引用。

```markdown
### ⟦Playbook 名称⟧

**你负责交付⟦结果⟧。** ⟦足以区分相邻流程的输入或范围⟧。

1. ⟦取得后续判断所需的证据⟧。
2. ⟦根据证据采取行动。需要专门方法时，写明调用的 skill 和所需结果⟧。
3. ⟦验证交付物。说明什么结果须停止或交回⟧。

**Reply:** ⟦本流程的结果、证据位置及仍待确认的事实⟧。
```

## 决定写多细

**写到 agent 能正确选下一步、知道凭什么继续，以及到哪里结束为止。** 依次检查正文是否回答了下面的问题。

- 什么输入适用这条流程，最终交付什么？
- 先取得什么证据，后面的哪项决定依赖它？
- 哪一步调用 skill 或委派，交出什么，收回什么？
- 什么结果可以继续，什么情况必须暂停、改走其他流程或交回？
- 最后怎样验证、报告，完成后在哪里停下？

能改变这些判断的细节应留在 playbook。被调用 skill 已经规定的方法细节，用引用承接。Mode 已经规定的共同准则由 mode 提供。特定任务才知道的值，执行时填进计划或任务说明。跨任务必须一致的命令或产物格式，可以直接写在 playbook。[pstack 的撰写原则](../../upstream/pstack/skills/poteto-mode/playbooks/authoring-a-skill.md)

篇幅由必要的决定数量决定。写完后逐句试删，直到再删就会使执行者遗漏一个必要判断。采用已有流程时只写真正不同的步骤。[沿用已有流程的实际写法](../../upstream/pstack/skills/poteto-mode/playbooks/autopilot-stack.md)
