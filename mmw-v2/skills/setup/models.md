# 模型角色映射

## 红线：写者 ≠ 审者

每一道审**至少有一路审者与作者不同家**。这不是配置项，是本仓库存在的理由。

同家的那一路可以加派，但不能是唯一——它的价值是补另一家模型才看得到的盲区，不是替代跨家那一路。任何审者都不得是产出自己的那个会话。

| 产物 | 谁写 | 必派（跨家） | 可加派（同家） |
| --- | --- | --- | --- |
| spec | Claude 主线程（和用户对谈出来的，派不出去） | Codex | Claude 另一视角 |
| 计划 | Codex 写计划工人 | Claude（两路视角） | 不加 |
| 代码 | Codex 写码工人 | Claude | Codex 一路 |

代码终审加派 Codex，是为了拿到另一家模型的盲区覆盖；它审的是别的 Codex 会话、别的型号写出来的东西（`terra` 写、`sol` 审）。

spec 的最终裁判是用户敲的那道人闸，不是主线程。

裁判权在主线程，不在审者。审者交回的 findings 是证据不是结论；主线程自己坐实、自己判断值不值得修。所以主线程全程不写代码——它一旦成为代码的写者，就没资格裁判代码的 findings。

## 角色

| 角色 | 谁干 | 模型 | 档位 | 权限 |
| --- | --- | --- | --- | --- |
| 写码工人 | Codex 无头 | `gpt-5.6-terra` | high | 可写 |
| 写码工人 · 高风险档 | Codex 无头 | `gpt-5.6-sol` | medium | 可写 |
| 写计划工人 | Codex 无头 | `gpt-5.6-sol` | high | 只写计划与 issue |
| Codex 审者 | Codex 无头 | `gpt-5.6-sol` | xhigh（spec 预审降 high） | 只读 |
| Claude 审者 | Claude 会话内 sub-agent | 继承主线程 | — | 只读 |
| 编排与裁判 | Claude 主线程 | 继承会话 | — | 写 spec，不写代码 |

**高风险档什么时候用**：这次要动的是计费、权限、数据迁移，或其他改错了不可逆的地方。由主线程判断后选档，不靠工人自己升级。

## 调用形态

- Codex 无头：`codex exec`，模型和档位用 `-m <模型> -c model_reasoning_effort=<档位>` 显式钉。
- Codex 审者一律 `--sandbox read-only`，审者不许动代码。
- Codex 会话续接（`codex exec resume`）不继承原来的围栏和模型档，追问时整套重钉。
- 不用 `codex review`——它自带提示词，会绕过我们的审查方法论。
- 派发前自检：点名的技能已装、传给工人的文档真实存在，缺装备当场报错，不让工人开工后才发现。

## 型号会过时

上表的型号是当前可用的值，不是约束。换型号只改这份文件，技能正文不出现任何型号。
