description: 派一个 subagent 去查清一个问题，交回一份每句都带出处的报告，主 agent 验证过才采信。用户说要调研一个话题、要查某个库或接口的官方说法时用它；别的技能遇到一条要查一手来源才能定的事实时也用它。

把「去查清楚」这件事派出去，你继续做别的。

**你不查。** 每个问题交给一个 subagent。你的职责是定问题、组装提示词、派发、验证、存盘。

## 1. 定这次要查的问题

一个 subagent 查一个问题。问题要收得能答得上：「那个接口支不支持按游标分页」答得上，「那个接口好不好用」答不上。

收不成这个形状就停下来说清楚——是这件事本身要人拍板，还是它得先拆成几个问题。

## 2. 组装提示词

从文件里取，不凭记忆：

1. 本文件旁边的 `researcher-brief.md`，全文。
2. 这次要查的问题，一句话写清楚。
3. 已经知道的背景：查过哪里、排除过什么。让它从你停下的地方接着查，不要从头再来一遍。

写到 `.dispatch/<slug>-research-<问题短名>.prompt.md`（先 `mkdir -p .dispatch`）。

## 3. 派发

按 `/mmw-dispatching-agents` 派，**只读沙箱**——它不写文件。模型档从 `docs/agents/models.md` 取。

问题互不依赖就一条消息里并行发出去。

## 4. 验证，存盘

报告按 `/mmw-verifying-agent-output` 验证：每条关键断言点开它给的出处，对得上才采信。

**验证过的事实才往下走。** 落到哪里看这次是谁要它：

| 谁要的 | 落到哪 |
| --- | --- |
| `/mmw-wayfinder` 的一张调查类 ticket | 那张 ticket 的评论，然后关掉它 |
| 别的技能 | 交回给把你叫起来的那个技能，由它决定 |
| 用户直接叫你来查 | 按 `docs/agents/domain.md` 的落点写一份文件，或者他指定的位置 |

交回来的出处是二手转述、或者点开对不上，那是 brief 没生效——把 `researcher-brief.md` 补进提示词重派，不要自己替它找出处。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 验证完了，是别的技能把你叫起来的 | **移交**：回到把你叫起来的那个技能，带上验证过的事实，不是报告原文 |
| 验证完了，是用户直接叫你来查的 | **停**：报查清了什么、报告落在哪、哪些没查清 |
| 出处是二手转述，或者点开对不上 | **自己继续**：确认 `researcher-brief.md` 全文在提示词里，重派一次 |
| subagent 交回「卡住」，理由是找遍了没有一手来源 | **停**：报这个问题查不到一手来源、它查过哪些地方，让用户定是换个问法还是接受不确定 |
| 第 1 步问题收不成能答得上的形状 | **停**：说清是要人拍板，还是这个问题得先拆开 |
