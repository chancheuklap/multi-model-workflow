把探仓库派出去，一个角度一个 subagent。

| | |
| --- | --- |
| 查什么 | 这个仓库里读得到的东西 |
| 不查什么 | 第三方文档、外部接口、别人的实现——那些走 `/mmw-research` |
| 不派的情况 | 一个函数、一个已知文件、一条命令答得完的，自己 `Read` 或 `Grep` |

## 1. 定角度

一个 subagent 一个角度，每个角度写两样：

| 栏 | 写什么 |
| --- | --- |
| 角度 | 从哪个方向看 |
| 要回答什么 | 一句话，能判真假。「订单受理这个模块的公开边界有哪些」答得上，「订单模块写得好不好」答不上 |

常用的角度：这块功能现在怎么实现、seam 在哪、数据从哪来到哪去、改动会波及谁、测试覆盖到哪。角度定几个按这次需要，不设上限。

**按角度分，不按范围分。** 每个 subagent 都看同一片地方，只有角度那一栏不同。范围一切，跨边界的发现就没人看得见——一个概念散在三个模块里、一处耦合从 seam 漏进另一个子系统。

## 2. 亮清单

按这个形状亮一次，**不等回应直接往下派**：

```
| # | 角度 | 要回答什么 |
```

## 3. 组装提示词

一个角度一份，装五样，从文件里取，不凭记忆：

| 装什么 | 取自哪 |
| --- | --- |
| 调查纪律 | 本文件旁边的 `investigator-brief.md`，全文 |
| 这一题 | 第 1 步定的角度和要回答什么 |
| 仓库根 | 目标仓库根的**绝对路径**，写明只许在这个路径下取证 |
| 领域词 | `CONTEXT.md`；多 context 的仓库按 `CONTEXT-MAP.md` 找到对应那几份 |
| 已知背景 | 已经查过哪里、排除过什么 |

仓库根不钉死，subagent 会在自己当前所在的目录取证——主仓库和各棵 worktree 长得一样，交回来的报告整份作废。

写到 `.dispatch/<slug>-investigate-<角度短名>.prompt.md`（先 `mkdir -p .dispatch`）。

## 4. 派发

按 `/mmw-dispatching-agents` 派，**只读沙箱**。模型档从 `docs/agents/models.md` 取。角度之间互不依赖，一条消息里全部并行发出去。

## 5. 过滤

引不出 `文件:行号` 的断言丢掉。这一步只看有没有出处，不做判断。

**丢掉的要在你的报告里列出来**：丢了几条、分别是什么。

## 6. 验证

按 `/mmw-verifying-agent-output`：打开那个 `文件:行号`，看原文对不对得上。条目多的时候取证那一半派得出去，判定归你。

**报「没有找到」的那几条自己再查一次。**「这个行为还没实现」「这里没有测试」会直接决定下一步做什么，判错的代价比一条错引用大。

## 7. 综合

跨角度去重，把相关的事实串起来，每条保留 `文件:行号`。**综合不派**——它是判定的开始。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 综合完了 | **移交**：回到把你叫起来的那个技能，带上验证过的事实，不是报告原文 |
| 综合完了，是用户直接叫你来查的 | **停**：报查清了什么、哪些没查清、过滤丢掉了哪几条 |
| 出处点开对不上，或者根本没给出处 | **自己继续**：确认 `investigator-brief.md` 全文和仓库根都在提示词里，重派这个角度 |
| 报了「没有找到」，你自己再查一次却找到了 | **自己继续**：以你查到的为准，这个角度整份降级重验——漏了一处多半不止一处 |
| 报告里提了方案、选了路线 | **自己继续**：那部分不采信，只取事实和出处 |
| 交回「卡住」，理由是这块代码看不懂 | **停**：报是哪一块、卡在哪里，让用户定换角度还是他自己讲一遍 |
| 第 1 步角度收不成能答得上的形状 | **停**：说清是要人拍板，还是这个角度得先拆开 |
