派出去的 subagent 交回的是证据，不是结论。把它的原话转发出去，等于把判断权让了出去。

## 每条关键断言都要有锚

| 产出 | 锚是什么 | 你怎么验证 |
| --- | --- | --- |
| 审查 findings | `file:line` 加那一行原文 | Read 那个位置，看原文对不对得上 |
| 工人完工报告 | 能跑的测试、能读的 diff | 跑一次，读一遍 |
| 调查报告 | 能读的源码位置 | Read 它引的位置 |

引不出锚的断言不进交付物，标 `needs-evidence`。

哪条算关键：这条断言如果是假的，会不会改变代码、改变结论、或改变你给用户的交代。关键之外的数字和定位不逐条验证，也不重做 subagent 已经做完的整段调查。

**验证过才采信。它的原话不转发出去，转出去的是你验证之后的结论。**

## 工人交回的四档

| 交回 | 什么意思 | 怎么办 |
| --- | --- | --- |
| 完成 | 它认为做完了 | 照上表验证：测试跑一遍、diff 读一遍 |
| 带隐忧完成 | 做完了，但它对某处不放心 | 先验证完成的部分，再单独看它说的那处隐忧。它在现场，隐忧多半指着一个真问题 |
| 缺上下文 | 材料不够，做不下去 | 看它缺什么：你没给全就补齐续接；产物里真的没有，那是上游的问题 |
| 卡住 | 试过了，走不通 | 读它的尝试记录再决定。它说这件事本身太大，处置是**把活拆开**，不是原样重派 |

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 验证完了 | **移交**：回到把你叫起来的那个技能。它要的是验证过的事实，不是报告原文。审查 findings 接下来怎么处置，在 `/mmw-review` 第 6 步 |
| 有断言引不出锚 | **自己继续**：那条标 `needs-evidence`，不进交付物，接着验证其余的 |
| 工人交回「带隐忧完成」，隐忧验证下来是真的 | **移交**：回到调用方，由它决定这处隐忧本轮修还是记账 |
| 工人交回「卡住」，理由是这件事本身太大 | **移交**：回到调用方，由它把活拆开重派，不要原样再派一遍 |
| 无人值守时遇到缺输入、怀疑解错了问题、或者要做对外发布的动作 | **停**：这三种是仅有的三种停下来理由 |
