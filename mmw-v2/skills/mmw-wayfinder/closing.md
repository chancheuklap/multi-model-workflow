# 收口

frontier 上一张 ticket 都不剩了。收口就是把这张 map 结束掉：清算还没说清楚的部分、把这个视角的决定各自归位、切出 spec、关掉 map。

进来的方式有两种，都合法：

- **刚解完最后一条链**，人还在那条链的 worktree 里。就地做，收口写的文件跟着这条链的分支一起合回 map 分支。
- **新会话进来发现 frontier 空了**，人还在主仓库。`EnterWorktree` 进 map 的 worktree 做，不在就先 `git worktree add` 建回来。

## 1. 清算还没说清楚的部分

把 map 的 `Not yet specified` 剩下的条目原样列给用户看，问他里面还有没有会挡住后续工作的。

这一步要人拍板：agent 判得出一个条目说不说得清楚，判不出它对用户重不重要。

有挡住后续工作的，就建成新的 decision ticket 连好阻塞关系，然后停——见文末的下一步表。剩下不挡路的原样留在 `Not yet specified` 里，它们跟着 map 一起关掉。

## 2. 决定各自归位

map 关掉之后就不再是查阅入口，所以这个视角做出的决定要按类型分开落到仓库里。这张表跟 `docs/agents/issue-tracker.md` 的产物分流表是同一份，那里是权威：

| 这个视角产出的 | 落到哪 |
| --- | --- |
| 难以回退、有真取舍的决定 | `docs/adr/`，编号四位、只增不改 |
| 考察过但决定不做的方向 | `.out-of-scope/`，一个概念一个文件 |
| 沉淀下来的术语 | `CONTEXT.md` |
| 其余可回退的决定 | 不单独归档，被下一步切出来的 spec 正文吸收 |
| map 本身 | 关掉即止。它是按走过顺序记的过程日志，含死路，不转 Wiki |

走 map 的过程中该写的已经写了，这一步是补漏：逐条过一遍 `Decisions so far`，看有没有当时判成「可回退」、现在回头看其实难以回退的。

## 3. 切出 spec

map 按**决定**组织，spec 按**能独立设计和实现的一块功能**组织。这一步是把已经定好的决定重新分组，看哪些凑起来是一份做得下去的东西。**只分组，不重新讨论任何决定。**

一组一份 spec，各建一张 issue 挂在 map 底下，正文写清楚这份 spec 交付什么、它依赖 `Decisions so far` 里的哪几条。spec issue 跟 decision ticket 同处一层，靠**带不带 `wayfinder:` 类型标签**区分：decision ticket 带，spec issue 不带。

切出来只有一份，说明当初路由判早了——一份 spec 说得完的事本该走 `/mmw-grilling` 再 `/mmw-to-spec`，不必画 map。发生了不用回头重来，照样派生这一份走下去。

### 提前派生

不必等到收口才切 spec。某份 spec 满足下面三条，就可以在走 map 的中途派生，跟剩下的链并行做：

| 条件 | 怎么查 |
| --- | --- |
| 这份 spec 的题目已经清楚 | 说得出它交付什么，不需要等更多决定来定义它自己 |
| 它依赖的决定全部已经关掉 | 逐条在 `Decisions so far` 里找得到，没有一条还开着 |
| 还没说清楚的部分不会波及它 | 把 `Not yet specified` 整节逐条对一遍 |

三条齐了就现在派生这一份，其余的链继续走。任何一条不齐就等收口——后解开的决定有可能推翻先前的，赌不起。

## 4. 关掉 map

关掉 map issue。把这一步写下的文件提交进 map 分支（刚解完最后一条链的，随这条链的分支合回去）。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 第 1 步问出来还有挡路的，已经建成 decision ticket | **停**：报又建了哪几张 ticket，让他另开一个会话认领 |
| 决定归位完、spec 切完、map 关掉 | **停**：报这张 map 收了、切出了哪几份 spec，说明每份 spec 各开一个会话去做 |

停下来时用 spec 的名字报，不用编号。每份 spec 的 worktree 从 map 分支分叉，做完合回 map 分支；整个 effort 收尾时 map 分支才合回主线（见 `docs/agents/worktrees.md`）。
