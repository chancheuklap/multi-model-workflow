# 裁判劳动力的产出

派出去的劳动力交回的是证据，不是结论。它也不是放行权人。你把它的原话转发出去，等于把裁判权让了出去。

本技能两段。**采信**段所有产出都要过，**处置**段只有审查 findings 要过。

## 采信

每条承重断言必须有一个你自己能复核的锚。

| 产出 | 锚是什么 | 你怎么复核 |
| --- | --- | --- |
| 审查 findings | `file:line` 加那一行原文 | Read 那个位置，看原文对不对得上 |
| 工人完工报告 | 能跑的测试、能读的 diff | 跑一次，读一遍 |
| 调查报告 | 能读的源码位置 | Read 它引的位置 |

引不出锚的断言不进交付物，标 `needs-evidence`。

哪条算承重：这条断言如果是假的，会不会改变代码、改变结论、或改变你给用户的交代。承重之外的数字和定位不逐条复核，也不重做劳动力已经做完的整段调查。

**复核过才采信。审者的原话不转给工人，转过去的是你复核之后的结论。**

## 处置

只对审查 findings。每条过两问：

1. **不修会伤到谁、在什么场景？** 说不清伤害面的，不能当承重项采信。
2. **这轮花预算修，还是挪出去？**

然后标一个处置词。这五个词写英文，留痕文件里当机器可扫的标记用：

| 处置 | 含义 | 驱动返工？ |
| --- | --- | --- |
| `accepted` | 成立，且本轮值得修 | 是——唯一能驱动返工的 |
| `rejected` | 不成立，或审者误读 | 否，写一句理由 |
| `duplicate` | 与另一条重复 | 否，指向保留的那条 |
| `needs-evidence` | 可能成立，但没复核出锚 | 否，补证之前不修不争 |
| `waived` | 可能成立，但过度设计、收益太低或超出本次范围 | 否，理由必填 |

几个审者报同一件事，合并成一条处置，别让工人修两遍。

## 搁置项去哪

按伤害面分流：

- 说得清伤害面的，开一张 GitHub issue 打 `needs-triage`。issue 就是留痕，也是交给用户的通道。标签词汇见目标仓库的 `docs/agents/triage-labels.md`。
- 纯品味、没有当前用户路径的，只写进本次报告，不开 issue。

**无人值守不为搁置停机。** 会停的只有三种：缺输入、怀疑解错了问题、要做出站动作。

## 留痕

findings 原样落盘，不重写不摘要。处置词就近标在每条下面，文末写一句总结论。

审查留痕和终审报告落 worktree 根的 `.reviews/`，工人的提示词和完工报告落 `.dispatch/`。两个都随 worktree 一起死，不进 git 也不进 Wiki，也都已在仓库根 `.gitignore` 里，写的时候 `mkdir -p` 即可。

## 不收敛

同一条 `accepted` 修过两轮还在，停下来自问：是修错了地方，还是这条根本不该采信。

不算指纹、不设硬轮次上限。修了几轮从提交记录看得出来。

## 下一步

| 情况 | 下一步 |
| --- | --- |
| 采信段过完，这次是工人完工报告或调查报告 | **移交**：回到把你叫起来的那个技能。它要的是复核过的事实，不是回执原文 |
| 采信段和处置段都过完，有 `accepted` | **移交**：回到调用方，由它把采信项打包派给新工人 |
| 处置完一条 `accepted` 都没有 | **移交**：回到调用方，并说明搁置的那些各自去了哪 |
| 搁置项里有说得清伤害面的 | **自己继续**：开一张 GitHub issue 打 `needs-triage`，这就是它的留痕和交给用户的通道 |
| 同一条 `accepted` 修过两轮还在 | **停**：报这条修了两轮还在，并说出你的判断——是修错了地方，还是当初不该采信 |
| 无人值守时遇到缺输入、怀疑解错了问题、或者要做出站动作 | **停**：这三种是仅有的三种停机理由。搁置项本身不构成停机 |
