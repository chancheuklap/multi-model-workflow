# 任务包怎么写

> 写每个任务包之前读这一份，一份读完，不跳别的。交付前的自检见 [self-check.md](self-check.md)。

你拆出来的一小块对应一个任务包。

**一个任务包多大**：一个任务包等于**能携带自身测试周期、值得一个新审者单独过一道闸**的最小单位。安装配置、脚手架、文档这些步骤折叠进它服务的那个交付物里，不单独成包；只在「审者可能否决这一包却放行邻居」的地方才切开。每个包以一个可独立验证的交付物收尾。

## 任务包模板

```markdown
### Task Pack N.M: <这一小块的标题>

**Ticket:** <tracker 上的编号或标识>
**Goal behavior:** <端到端行为>
**Why this matters:** <谁受益、交付什么价值——落地的人要懂价值，不只懂机械动作>
**Owned files:** Create `path` / Modify `path:line` / Test `path`

**Verified current state:**（改既有行为时填）现状的真实行为加 `文件:行号` 加核实日期；改一族成员里的某一个时，给一张族审计表（组件 × 有没有 × 缺口），防隧道视野。

**Read first:** <spec 章节、ADR、项目规则，以及项目指令链实际指向的测试规则>

**Interfaces:**
- **Consumes:** <本包用到的、来自前序包的东西——精确签名>
- **Produces:** <后续包依赖的东西——精确函数名、参数与返回类型>

  （落地的人只看自己这一包，这一块是他知道邻居包名称与类型的唯一途径。）

**Contract anchors:**（碰合同时）归属方 / 提供方 / 消费方 / 数据模型 / 数据结构 / 登记位置 / 迁移 / 目录 / 怎么验证
**Schema / API shapes:**（涉及数据或接口时）真实的建表语句、接口、请求与响应形状，精确到让落地的人**零设计决定**。
**Mockup specs:**（有原型选中产物时必填）涉及哪些页面、视觉规格（写具体布局颜色字体间距，不写「见原型」）、交互、状态变体、怎么验证
**Do Not Touch:**（重构或审计类的包必填）哪些看着像目标但其实是对的、不许动——防止把没坏的「修」成回归。
**Root cause:**（修缺陷的包必填）问题为什么存在，再谈修法。

**Acceptance criteria:**（编号、能判真假、不用主观语言；写「三十天以上的订单对全部四个角色返回 HTTP 410」，不写「功能正常」）
- [ ] ...

**Verification commands:** `command` → Expected: ...
**Testing pyramid:**（**用项目自己声明的测试分层**，不套陌生词汇）
| 层 | 测什么 | 数量 |

**Rollback:**（碰数据、基础设施或共享状态时）怎么撤——哪怕是「回滚这个合并」也写明。
**Complexity:** cheap（碰一两个文件、spec 完整）/ standard（跨模块、要集成）/ capable（计费、权限、数据迁移、跨服务）——主线程派写码工人时按它选模型档。
**Commit boundary / Risk flags / 发布风险 / AFK·HITL / Dependencies / Out of scope:** ...
```

## 实施步骤（每步一个动作两到五分钟，红绿垂直穿透）

```markdown
#### Implementation tasks
- [ ] Step 1: 写一个会失败的公开行为测试 — 文件 / 行为 / 关键断言 / fixture（给真实测试代码，不写「写测试」）
- [ ] Step 2: 跑一遍确认失败 — Run: `command` → Expected: FAIL because ...
- [ ] Step 3: 实现最小合同 — 文件 / 归属方 / 提供方 / 消费方 / 类型 / 字段 / 状态转移
- [ ] Step 4: 跑一遍确认通过 — Run: `command` → Expected: PASS
- [ ] Step 5: 重构（只在绿的状态下做）
- [ ] Step 6: 建议的提交边界
```

**每一步的规则**：优先从公开行为起步（红 → 绿 → 重构）；每步只做一个动作；条件和场景写在动作前面；写出运行命令和预期结果。

**代码放在哪一区**：任务包的散文区只放数据结构和接口形状（用来消除歧义），不撒说明性的实现片段；实施步骤区**必须给完整可抄的代码**——零上下文的人要照抄，不写省略号，不写没定义过的方法。

后续任务包引用的类型、函数、字段必须前文定义过或者在既有代码里验真过；既有路径要验真，新文件写明 `Create`；文档、覆盖规则、登记、迁移跟对应行为放同一包；不写「跟前一包一样」；DRY 和 YAGNI 不为假想需求预建抽象。

**垂直切片不横切**：

```
错误：红：测试1、测试2、测试3 → 绿：实现1、实现2、实现3
正确：红→绿：测试1→实现1 → 红→绿：测试2→实现2
```

**禁止占位符**（出现一处就是整份 plan 不合格）：`TBD`、`TODO`、`later`；`add validation`、`handle edge cases`、`appropriate error handling`；写了「写测试」却没有行为描述；「跟第 N 包一样」；引用没定义过或没验真过的类型、函数、字段、fixture；描述做什么但没展示怎么做；只写了整套测试却没有本包能单独跑的命令。

## 测试规划

plan 必须自带完整的测试规划，不留到后面补。

测试本身怎么写、够不够格进仓库，在你已装的 `mmw-tdd` 技能里，加上目标仓库根的 `TESTING.md` 补的本仓库事实。**写测试规划之前读那几份。** 本文只讲规划这一层。

### 追覆盖

- **追承重行为**：每条变更后的验收行为、已复现的回归、会产生独立可观察后果的风险路径，都要有测试。没有独立合同的内部代码分支不为凑覆盖率单独加测试。
- **追这次相关的场景**：只选会改变用户结果、恢复能力、数据、权限或账务的交互边界、错误态和空边界态，不为假想组合铺测试矩阵。

### 测试类型怎么选

- **端到端**：跨三个以上组件的常见流程 / 打桩会掩盖真故障的集成点 / 鉴权、支付、数据销毁。
- **评测**：碰大模型调用、提示词、工具定义。
- **单元**：纯函数 / 无副作用的辅助函数 / 单函数边界。

### 测试规划的质量

三星是测承重行为加这次相关的边界与错误路径；两星是只测顺利路径；一星是烟雾测试或存在性断言。 plan 的目标是三星，不要只写到一星。

**权威层**：每个行为在拥有它的那一层测一次，不为凑数加脆弱的实现细节测试，同一个行为禁止跨层重复断言。不追求覆盖率数字最大化。用项目自己声明的测试分层，别套陌生词汇。

### 回归铁律（强制，不用问用户）

覆盖审计发现这次改了既有行为、既有测试没覆盖那条路径、或者给既有调用方引入了新的失败模式，就把回归测试作为**最高优先级**加进 plan，并写明什么坏了。拿不准时先核实现有行为和影响面，不凭猜测加测试。

### 验证语言对照

接口与合同 → 路由测试或合同类型解析；数据库与迁移 → 迁移或仓储测试加降级；JSON 与登记 → 校验器或未知字段测试；计费与权限 → 服务测试加用户可见的闸测试；运行时与浏览器 → 聚焦单元测试加日志证据；界面 → DOM 断言、截图、响应式、人工走查闸。

seam 锚到 spec 里定下的那份清单，选最高的那一层，不要增殖插桩点。

## 每一块的质量标准

- **现状核实**：改既有行为之前先写现状的真实行为加 `文件:行号` 加核实日期。
- **影响面给数字**：用数字不用形容词。「几个文件」写成「四十七个文件跨十二个目录」；「提升性能」写成「五百毫秒降到五十毫秒」；没数就写「未知，用什么方法测」。
- **族审计表**（改一族成员里的某一个时，防隧道视野）：

  | 组件 | 有 X | 有 Y | 缺口 |
  | --- | --- | --- | --- |

- **验收标准能判真假**：编号、能判真假、不用主观语言。
  - 写「三十天以上的订单对全部四个角色返回 HTTP 410」「一万行的查询低于一百毫秒（用执行计划分析测）」
  - 不写「功能正常工作」「处理好边界」
- **数据结构与接口形状**：真实的建表语句、接口、请求与响应，不写伪代码——精确到让落地的人零设计决定。

## 反模式（命中就修）

验收含混（「正常工作」）；文件引用含混（「鉴权模块某处」）；工作量没按组件拆；范围不小却缺「不做什么」；改动没有现状核实；一个包里混了流程反馈和战术修复；二十条以上没有分级和执行顺序；引用没定义没验真的类型或 fixture；写「跟第 N 包一样」不重复写出来；**plan 要求做审查会判成缺陷的东西**（断言为空的测试、整段逻辑逐字复制粘贴）。

**不合格任务包的信号**：落地的人要自己决定目标行为、文案、角色、计费、权限或数据形状；包里只写「实现原型」或者只给目录没把视觉规格拆进验收；把没验证过的路径、fixture、类名写成既有事实；把真实依赖隐藏成「可以并行」；只产出数据结构或辅助函数却没有公开行为可验证；需要人决定、真实账号或生产确认却标成可以无人值守。
