工作流的约定随插件走，不复制进仓库——issue 怎么用、标签怎么定、worktree 怎么建、模型怎么派、spec 怎么归档，都在插件的 `conventions/` 里，技能直接读那一份。**这个技能只做仓库这一侧的准备**：那些约定要能落地，仓库得先具备几样东西。

**不问问题。** 这些选择在本插件里是固定的，不存在每仓库变数。你要做的是查前提、动手准备、报一句完成。

## 1. 查三项前提

三项，缺任何一项都在报告里指出来。这些是既定选择，不是可协商的默认值。

| 前提 | 怎么查 | 缺了会怎样 |
| --- | --- | --- |
| 有 GitHub 远端 | `git remote -v` | issue 那套全不可用 |
| `gh` 已登录 | `gh auth status` | 同上；顺手提醒跑一次 `gh auth setup-git`，推 Wiki 要用 |
| Wiki 已初始化 | `git ls-remote "https://github.com/$(gh repo view --json nameWithOwner -q .nameWithOwner).wiki.git"` | spec 无处归档。**只能由用户去仓库的 `/wiki` 页手建一页**，没有 API 能替他建，别试着绕 |

## 2. 建标签

按 `../../conventions/triage-labels.md` 里那两个维度建标签，已有的跳过：五个状态标签、`bug` 与 `enhancement` 两个类型标签（GitHub 自带）、五个 `wayfinder:` 标签。

```bash
gh label create <名字> --description "<一句话>" 2>/dev/null || true
```

标签不在，分诊和派工人那道机器可核的门就形同虚设。

## 3. 让三个目录不进 git

目标仓库的 `.gitignore` 里缺哪行就加哪行，已有的跳过：

| 行 | 挡的是什么 |
| --- | --- |
| `.worktrees/` | 任务 worktree，还有 Wiki 的 clone（`.worktrees/.wiki/`） |
| `.reviews/` | 审查留痕和终审报告，随 worktree 死 |
| `.dispatch/` | 派给工人的提示词和它交回的报告，随 worktree 死 |

在这里一次挡掉，技能写文件时 `mkdir -p` 就行，不用在每个 worktree 里铺一份脚手架。

## 4. 把方法论装给无头劳动力

审者和写计划工人都不从提示词里读方法论，它们读自己技能目录里的那一份。跑 `/mmw-dispatching-agents` 旁边那个装载脚本，幂等，装过就跳过：

```bash
bash "<本技能目录>/../mmw-dispatching-agents/install-agent-skills.sh"
```

`<本技能目录>` 就是这份 `SKILL.md` 所在的目录，脚本在它的同级目录里，不用去找插件根。

这一步是**每台机器一次**，不是每个仓库一次，所以它跟别的步骤粒度不同——重跑无害。

报「冲突」说明那个名字被别的东西占着（多半是早先某个实现留下的软链）。**不要覆盖**，把冲突的路径报给用户，让他确认后自己清理。

## 5. 铺 TESTING.md 骨架

把本技能目录下的 `testing.md` 复制到仓库根，改名 `TESTING.md`。已存在就跳过并在报告里说明——那份比种子新。

这是唯一一份要落进仓库的文件，因为它装的是**只有这个仓库自己知道的事**：测试目录怎么分层、哪些边界允许打桩、值从哪个权威源读。测试怎么写、够不够格进仓库由 `/mmw-tdd` 随插件带着。铺的是空位，第一次写测试的技能顺手填。

## 6. 加指针节

编辑目标仓库根的 `CLAUDE.md`，没有就编辑 `AGENTS.md`；两个都没有，问用户建哪个——不要替他选。已存在的那个不要换成另一个。

已有 `## 多模型工作流` 节就原地更新，不要追加第二份；不要动周围的内容。

```markdown
## 多模型工作流

本仓库装了多模型开发编排插件。工作流的约定随插件走，技能自己读得到，这里不复述。

仓库自己持有这几样：

- **测试的仓库事实**：根目录的 `TESTING.md`。通用测试规范随插件走，那份只补本仓库事实
- **领域术语**：`CONTEXT.md`
- **难以回退的决定**：`docs/adr/`
- **否掉的需求**：`.out-of-scope/`，一个概念一个文件
```
