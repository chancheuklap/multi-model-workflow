| frontmatter 的 `description` | 前半句是上游的，我们在末尾补一句触发：``Use when a conversation, a wayfinder map or a triaged issue has to become a spec, or a section of a published spec has to change.``。这份技能在本仓是模型可触发的（下一行），而 host 启动时只扫这一行；四支触发各对应正文一个入口：对话、第 1 步的 wayfinder `map`、`triage` 技能第 5 步送来的外来 issue、第 1 步转去 `references/revising-a-spec.md` 的修订。**引号也不能去**。值里 `tracker: no` 是一个冒号加空格，YAML 会把不带引号的这一行读成一个嵌套 mapping 的 key，`yaml.safe_load` 对整块 frontmatter 抛 `ScannerError: mapping values are not allowed here`——坏的不是这一个 key，是整份 frontmatter。而 `description` 恰好是每个 host 启动时唯一扫进技能列表的那一行，所以症状不是一声响的失败，是这份技能整个安静地消失；再加上改这一行要重开会话才生效，改动和症状之间还隔着一段距离。理由写在这里，是因为 `description` 的值里装不下注释。别人要求「把 description 统一成不带引号」时 → 这一份是例外，值里含冒号加空格的都是。上游改前半句 → 收上游措辞，末尾这一句保留 |

## Critical flows 每一行的形状

模板 `## Testing Decisions` 的 **Critical flows** 一项加两句：每条流程一行，嵌在这一项下面，写成 ``- `<flow>`: Implementation Decisions sections <n>, <n>``；`Implementation Decisions` 这两个词不论 spec 用什么语言写都保持英文，与票的 `## Parent` 点名小节的写法一致，节号跟在它后面；`verify-ticket` 技能的 `--lint` 读这些行来判定哪些 journey 必须带 `--break`，读不出的行报 ERROR 并给出这个形状。`Implementation Decisions 第 2、4 节` 这类中文数节法也读得出的例子，2026-09-28 lightweight review 时从正文删掉（与「Each line sits nested…in one shape」自相矛盾），理由只留在这里。
