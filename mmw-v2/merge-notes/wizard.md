# wizard

源目录：`mmw-v2/upstream/skills/engineering/wizard/`

## 逐段意图

### SKILL.md

| 段落 | 我们的意图 |
| --- | --- |
| `### 2. Map each stage's journey`，"never invent steps that may not exist." 之后 | 我们加的：点击路径之外，每一步还要写清楚它要达成什么（设成什么值、拿到哪个密钥），控制台改版时人能靠目的而不是靠路径找到控件；凭记忆写的路径要在 stage 里用 `note` 标注出来。理由：agentflow #594 一次真实使用里，控制台改版（"OpenAPI 调用访问" 改名 "使用永久 AccessKey 访问"），用户两次拿着截图回来问该点哪里。上游改这一步措辞 → 收上游，这句接在后面 |
| `### 3. Author the wizard` 末尾 | 我们加的：stage 文案里的变量一律写成 `${NAME}`，不写 `$NAME`。理由：本机 `/bin/bash` 3.2（macOS 默认版本）在变量名后紧跟全角字符（中文标点、CJK 文字）时会把该字符并进变量名，导致 `set -u` 下以 "unbound variable" 退出；`bash -n` 和 `shellcheck` 都查不出来。agentflow #594 那次在 Stage 2/9 当场复现，本会话复现命令：`/bin/bash -c 'set -u; REGION=cn; echo "区域：$REGION，下一步"'`，退出码 127。上游改这一步措辞 → 收上游，这句接在后面 |

### template.sh

| 段落 | 我们的意图 |
| --- | --- |
| 文件头注释里 `Generated by the … skill.` 一行 | host 中立：技能名写成散文形式，不写斜杠。这一行会原样出现在每一份生成出来的 wizard 脚本里，读它的人手上未必有那台 host。`SKILL.md` 没有同类的写法，`description` 三段齐全（含「什么时候不要用我」那半段），两处都没动。共同理由见 [README.md](README.md#host-中立) |
| `RED` 变量赋值（第 17、19 行，色彩分支各一处） | 删。库里从没用过 `RED`，`shellcheck -S warning` 因此对每一份生成出来的 wizard 报 `SC2034 (warning): RED appears unused`；agentflow #594 那次 agent 为了消掉这条警告，在生成的 wizard 里插了一行 `# shellcheck disable=...`，落在 `never hand-edit it` 的库区之上，属于不该发生的越界编辑。删掉后没有功能损失：库里没有任何地方读它 |
