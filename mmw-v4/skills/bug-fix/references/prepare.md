# Prepare the repair

Keep the supplied issue and effort branch. Use `references/diagnose.md` only for missing observations, retaining the original and minimised scenarios. Revert any change a refuted hypothesis motivated. A returned result resumes with the evidence that refuted the earlier diagnosis, rather than restarting the whole investigation.

1. **Persist the feedback loop.** For a supported UI product without a verification skill, call the **create-verification-skill** skill within this authorized preparation, then return here. An unsupported or unreachable surface returns its concrete limitation; do not invent e2e proof. For a UI bug, read the `verify-<product>` skill's Read first, Rules and Evidence, and turn the loop into a failing e2e test in a new file belonging only to this ticket under `tests/e2e/<product>/`. Register that file on the affected feature file's `Tests:` line in the feature map, creating the feature file if missing, and commit and push the test and registration together on the supplied effort branch. This loop is AC2, after AC1, the worker's tdd regression test; when the fix-planning step finds no seam, it is AC1, the only criterion. Use Cleanup when you finish with a product you started. Commit the repeatable loop on the supplied effort branch. Done when its command and any required e2e registration are on origin.

2. **Plan the fix.** A question of code shape goes to the **prototype** skill's `## Pick a branch` first. When the fix needs new code beyond the bug itself, follow **principle-start-from-what-exists**. Find the seam where a regression test exercises the bug as it happens at the call site. When no such seam exists, that is itself a finding: the structure keeps this bug from being locked down. Register it with the **register-problem** skill, its suggested direction a behavior-preserving structural change, and this ticket goes on with the original feedback-loop command as its criterion. Done when the fix is planned and its seam is named, or the missing seam is registered.

3. **Supply the repair plan.** First clean up after yourself: remove every tagged debug log (`grep` its prefix), and delete each throwaway script that is not the original feedback loop. Return the following material to the caller for the **to-tickets** skill. **What to build** states the symptom, the cause with its runtime evidence, the hypothesis that held, and the planned fix; a sketch from the **prototype** skill is a baseline under **Read first**. **Seam** is the named seam, or says there is none. The first acceptance criterion is a regression test the worker writes at that seam from the minimised reproduction, which must fail on the project branch; the second is the original feedback-loop command. With no seam, the original feedback-loop command is the only one. **Read first** names this skill's implementation and verification entries with their baselines. Done when the caller has every source needed to write the repair ticket.
