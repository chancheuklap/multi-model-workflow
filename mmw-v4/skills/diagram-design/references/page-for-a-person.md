# Lay out a page for a person

Use this for a page with several diagrams or text beside a diagram. **principle-everything-at-hand** holds the reader rules. This reference gives their HTML layout.

## Page opening

Use a title that names the page's subject. Immediately below it, place the conclusion, totals, and decisions the reader needs to make, so the first view tells the reader what to judge.

## Figure units and numbered notes

Make each figure a unit with a figure number and a one-line title stating its question. Keep the figure number in notes that refer to the figure, so the reader can locate it.

On a wide screen, use a grid with the diagram and its explanation column beside each other. For a full-width diagram, put the explanation immediately below. Size each unit so the relevant diagram elements and notes can be seen together. Place that figure's legend beside the diagram. For a diagram taller than the viewport, use a sticky legend column so its notation stays visible while scrolling. A diagram that fits in one viewport can use a bottom legend strip.

Place a numbered circle beside the element being explained. Start the matching note with the same circle. Give questions, changes, and pending decisions distinct marker treatments, and include the treatments in that figure's legend, so a number's meaning is clear. Add a leader only when the numbered pairing leaves its target unclear. Before publishing, inspect each leader's endpoint on the rendered element, because source coordinates alone can hide a misplaced connection.

## Samples and long content

Place a sample of a file a step writes beside that step. When the sample needs more room, put it in a sticky side column and match its number to the diagram's number. The reader can inspect the sample while keeping its producing step in view.

## Interface mockups

Draw each screen in the real product's style so the reader judges the interface users will meet. Put its field table directly below the screen. If one field table spans several screens, group those screens together and put the table directly below the last screen, so the fields remain with their interface.

## Desktop width

Lay out for a desktop window and use the available width. Fit each diagram at window widths from 1440px to 1920px. When a diagram cannot fit, nest it as `SKILL.md` `## 7. Layout & Spacing` says. Keep horizontal overflow local to a diagram rather than the whole page. This preserves a complete, readable desktop view within the window. Also meet any publishing tool's mobile-width requirement for a page without horizontal scrolling.

## Revision

Before revising a design, read the current page in full. Update the existing page and diagram, and report the change and reason in the reply. Reading first keeps settled details intact across iterations.
