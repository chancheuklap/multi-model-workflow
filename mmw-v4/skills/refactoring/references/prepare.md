# Prepare the structural change

**The structure changes; the behavior does not.** If cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is a separately scoped behavior change returned to the caller. A larger structure change returns to the same preparation for a spec.

1. **Learn the contract and choose the pin.** Run the **how** skill over the affected subsystem to learn the contract, then choose the characterization test, snapshot, or equivalence harness that will capture current behavior before any structure moves. Where the area has no coverage, the pin is new. Reuse the supplied affected-feature result; when missing, call the **maintain-verification-skill** skill's **Find affected features** entry. For unchanged UI behavior, reuse the product verification method. If its reusable skill or required launch and drive capability is missing on a supported product, call **create-verification-skill**, **Generate and prove**, with current behavior, affected features, product, checkout and scope. Return here with the method. Reuse a matching pin from generation; otherwise call **prepare-ui-acceptance** to prepare the pin and registration. Return here with the green baseline and sensitivity evidence; retain the current non-UI characterization method and later structural-design steps. For non-UI behaviour, write the chosen pin as a characterization test that captures current behavior. This session prepares every pin, commits it and any feature file registration on the supplied effort branch, and pushes before the worker starts. Each pin meets the **test-audit** skill's pin-writing method. Read every file the move touches per **principle-read-before-you-conclude** before deciding the contract. Done when the contract is named and every pin is on the supplied origin effort branch.

If a selected pin relies on an existing formal check, read its local method and correspondence record. When relevant code changes skipped that method and no current evidence covers this baseline, call **maintain-formal-verification-skill** for that check before using it as a pin. Return its outcome here; a product bug follows this skill's separately scoped repair rule.

2. **Name the structure the code is missing** per **principle-model-the-domain**. Done when the missing structure is named, or you have found the shape already clear.

3. **Name the target shape.** State what the module layout, types, and call graph should be if built today (**principle-model-the-domain**, **principle-redesign-from-first-principles**). Run the **prototype** skill on the target shape before the move; its `## Pick a branch` decides whether a sketch is drawn, committed on the supplied effort branch. Follow **principle-start-from-what-exists** before writing a helper. Done when the target shape is stated.

4. **Return the move's contract.** Return the contract, prepared pins, missing structure, target shape and any sketch. Read first names those baselines and this skill's implementation / verification entries. The first criterion is the pin, green before and after; a larger reshape also needs an equivalence check comparing old and new outputs or replaying the recorded baseline. The independent reviewer judges whether the structure reduces reader load, per **principle-minimize-reader-load**; record that review constraint separately from machine criteria.
   Done when the caller can write the move without inventing its behavior baseline or target structure.
