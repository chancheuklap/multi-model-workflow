# Anchor Every Reference

Every reference in a reply or a document is anchored. The reader shares none of your working memory.

**Pattern:**
- Name each thing, place, action, or event you mention on first mention by its file path plus the section heading, identifier, or rule number that appears in the file, and by the same name each time after.
- Add line numbers only where a ticket, a `CHECK:` line, or a review comment needs a location that a shell or a reviewer will jump to.
- Copy names verbatim from the source: the identifier, heading, or exact wording that appears in the file or in the owner's message, in the language the source uses. An English term in the source, or a term that has an established English name, stays in English even when the rest of the reply is in Chinese.
- A label you invented while working ("the wiring step", "the second helper", "接线那一步") exists only in your head. When you catch yourself reaching for one, replace it with the source wording and the location it points to, even when that is longer.
- Use the thing's name in place of a pronoun or count: "this", "that", "the above", "figure 9", "the second one", "the two baselines", "这", "那", "同上", "上一个", or "两个基线". These can be labels that exist only in the author's head too. When you use a label in chat, such as a number or code, put the same label on the page the reader sees, so the reader can find its target.
- A path is an address, not content. Give the address so the reader can hand it on, and leave the code behind it out of the report unless asked.

Distinct from the **technical-writing** skill, which says to write real paths and symbols in a document. This says where a name comes from and that it stays the same everywhere.
