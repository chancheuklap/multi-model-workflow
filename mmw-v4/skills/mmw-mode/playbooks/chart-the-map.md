### Chart the map

**You own the map, not the answers. Charting resolves no ticket by hand.**

A loose idea too big for one agent session, with the way to the destination not yet visible. Read `../references/wayfinder.md` first. It holds the map body, the ticket format, and the ticket types every step below uses. Never resolve more than one ticket per session, with the exception of research tickets.

1. **Name the destination.** Use the **grilling** skill and the **domain-modeling** skill to pin down what this map is finding its way to: the spec, decision, or change. The destination fixes the scope, so it is settled with the user before you go on. Done when the user has agreed the destination.
2. **Map the frontier.** Grill again, **breadth-first** this time: fan out across the whole space rather than deep on any one thread, surfacing the open decisions and the first steps takeable now. **If this surfaces no fog** (the way to the destination is already clear, the whole journey small enough for one session), you don't need a map: stop and propose the Grill with docs playbook (`playbooks/grill-with-docs.md`) instead; the user decides. Done when the open decisions and first steps are listed, or the user has chosen Grill with docs.
3. **Create the map** (labels `wayfinder:map` and `mmw:map`): Destination and Notes filled in, Decisions-so-far empty, the fog sketched into **Not yet specified**. Done when the map issue exists with both labels.
4. **Create the tickets you can specify now** as child issues of the map, then wire blocking edges in a **second pass** (issues need ids before they can reference each other). Write cross-references in that pass too, with real ids: a placeholder `#<n>` auto-links to an unrelated issue. Wiring sorts them into the frontier and the blocked; everything you can't yet specify stays in the fog: the **Not yet specified** section. Done when every ticket is a child of the map with its blocking edges wired.
5. **Answer the research tickets.** For each `research` ticket you just created, write its brief as **Research** in `## Ticket Types` of `../references/wayfinder.md` says, and send them all with one `dispatch.sh send researcher <brief>...` of the **dispatch** skill, so you are woken once; end your turn. Not the **swarm** skill: each ticket keeps its own answer. Woken by `brief <batch> done`, follow the dispatch skill's `## On waking`; then for each answer save and push its note as that type says, post the resolution comment and close the ticket, and append the context pointers to the map's Decisions-so-far one at a time. Done when every research ticket is closed with its note pushed and its pointer on the map.
6. **Stop.** Charting is one session's work; it hand-resolves nothing. Tell the user the next move: Work through the map (`playbooks/work-through-the-map.md`) in a fresh session, with the map's number. Done when the user has it.

**Reply:** the map and every ticket by name, which tickets sit on the frontier and which are blocked, the research tickets resolved with their gists, and what stays in Not yet specified.
