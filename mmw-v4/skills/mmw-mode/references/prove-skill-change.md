# Prove it, once

Use the caller's candidate checkout, task and authority. Authoring or modifying a skill calls this proof after writing a text-only change on `fix-<n>`. For a script ticket, One ticket **Check it** calls it after the ticket passed, in `.worktrees/issue-<n>`. For a larger change, Run a night **Open the pull request** calls it on the candidate delivery version before owner acceptance or `finish`. Run each applicable check from that supplied checkout, reusing evidence already proven on the same candidate version:
- When a script changed, the suites **test-audit** picks (`bash mmw-v4/tests/<name>/run.sh`).
- `scripts/check` exits 0.

Then, when the change alters what an agent does in a task, have one fresh agent walk one real task the change touches, on the changed text read from that checkout, as the `writing-for-agents` skill's `references/WALKING-A-SKILL-SET.md` `### List the tasks` and `### A fresh agent's walk` say. A wording-only fix needs no walk. A change to a script's output that an agent reads to choose its next step alters what an agent does. Its record of the walk is the task's load. Post the record as a comment on the ticket and link it from the pull request. A required walk without that record fails the check. A place where the agent ended wrong, stopped short of the completion criterion, or guessed at a sentence this change wrote, you fix in the text yourself on the current delivery branch (`fix-<n>` after `land` for an independent ticket, or the night branch for a batch), following the current execution flow's repair rules for script changes, then one more fresh agent walks the same task. Never reopen the ticket or send a worker for it. What the second walk still finds goes to the owner: an end that is wrong or short holds the change until the owner decides, and a guess goes into the Reply. Every other guess goes into the Reply as a finding for a later change: each fresh agent finds a new guess somewhere, and fixing each one adds a sentence that raises the next.
