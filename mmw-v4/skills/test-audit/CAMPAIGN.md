# Test audit campaign

Coordinate a bounded repository or subsystem audit using the shared judgments in the test-audit skill. Use this when ordinary change scope cannot account for the old suite. The caller's existing planning and ticket lifecycle supplies execution and delivery; a campaign is not a new scheduler or permanent database.

1. Name the agreed scope and pin the baseline revision. Discover its tests and support code from native configuration, including shared-boundary cases and relevant platform or live proof. Record baseline results and unrun areas separately. A missing environment is a proof limit, not a passing baseline.
   Done when every in-scope test area has an owner and a recorded baseline or explicit unproved state.
2. Divide by production responsibility and independent contract, not merely filename prefixes. Give each area the task to audit its assigned declarations using the test-audit skill's audit branch. Keep per-area dispositions and remaining-proof plans together; no separate second discovery pass is required. Plan shared fixture changes through their existing owner.
   Done when every in-scope declaration belongs to an area, and its ticket or task names the boundary and expected handback.
3. Execute the approved area work through the existing tickets, with their normal review and validation. Keep the baseline, dispositions and supporting controls with that task. Broad work uses To spec and To tickets; a small area fits its existing ticket. Product defects and frozen-acceptance corrections follow the caller's normal routes.
   For that planning handoff, the existing tests are the assets being maintained. A slice preserves one bounded contract area and names its keeper proof; it does not require a new feature or prototype. Put the audit scope in Implementation Decisions and its repository validation in Testing Decisions. Protected product-acceptance corrections remain daytime work through the existing contract route, outside a night worker's Owns.
   Done when each completed area has retained proof and review evidence, and unfinished areas have durable work and a next executable ticket in the existing tracker.
4. Reconcile changes to the base before declaring the scope complete. If new contracts entered a retired suite, carry those contracts into its keeper rather than silently discarding them. Native test routing must still discover the moved proof.
   Done when all agreed areas are accounted for, remaining risks and platform gaps are explicit, and the caller receives the final disposition and proof report.

Archive the task evidence when the campaign ends. Future changes or failures re-enter the relevant branch; they do not require rerunning the whole campaign. Project-specific execution facts stay in the project's configuration and product tools, and common testing rules stay in this skill.
