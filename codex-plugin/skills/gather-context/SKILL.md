# 定向补上下文

只在 design 问答中使用。用户随调用给出的文字就是要坐实的缺口；没有给缺口时先请用户说明。

1. 用一句话说明缺哪条事实或哪项假设尚未坐实。
2. 内部事实用当前仓库源码和 `path:line` 亲验；外部事实只用适合该问题的第一方资料。
3. 把坐实结果写进当前设计草稿、Open Decisions 或领域文档，不能只留在聊天里。
4. 回到被打断的设计问题继续讨论，沿用已有基线。

这不是新 investigate 阶段，也不另开工作树或状态机。
