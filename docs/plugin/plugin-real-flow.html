原则 确定的归脚本,判断归 LLM —— 判断是核心,不是兜底

这条线是整个架构的组织方式:把机械、可固化的步骤压进脚本/Hook,把判断留给 Agent。Agent 的判断不是"待消除的风险",是这 plugin 的价值所在;全是脚本就不需要 Agent 了。

脚本 / Hook 管(确定)
  • 阶段推进、审闸冻结、返工/掉头计数、caps
  • 建 worktree / scaffold / 写状态(fail-closed)
  • 派 Codex 落地、起审、记步、拦红线
Agent 管(判断)
  • 路由选路、每步选结论词
  • 方案/设计/计划/代码的内容
  • 验收 Codex 产物真假、finding 真假
  • 执行放权:afk 下自己拍小决策、留痕继续(loop.sh softstop)
  • HITL 集中在 propose/design/plan(要你拍方向);进 build 默认放权,只有真缺输入/方向疑/合并红线才停。
