⚖ · 诚实判定

✓ 引擎强制(代码焊死)

  • 阶段推进 = flow.sh 状态机
  • 结论词只 5 个,写别的当场拒 flow.sh:52
  • design / plan / build 三个产出阶段统一审闸:产物 pass 后 phase 物理冻结,不审过不放行 flow.sh:82-86 / routes.json:13-17
  • 审闸 stage 由引擎按 map 吐确切命令,不靠散文猜 flow.sh:264-274
  • 返工 2 / 掉头 1 封顶 flow.sh:102,112
  • 内层没完成 SubagentStop 顶回 guard-loop.sh
  • merge/push/deploy 无令牌一律拦 guard-redline.sh
  • 状态写入 fail-closed,绝不截空 flow.sh:29-35 / loop.sh:30-36

⚠ 仍靠 Agent 自觉

  • 每阶段"干什么"的方法论 = reference 文档,Agent 要真读真做
  • 引擎强制 Agent 进审闸 stage(冻结+2pass);审 loop 一旦起、guard-loop 强制其完成。但"Agent 是否真起审 loop / 真派审者"靠 review.md 纪律 —— 这是审闸的剩余信任面(①②④ 一致,不再有 ③④ 比 ①② 弱的不对称)
  • ③合同门是 build 内部机器检查(非 HITL 审闸),像测试套,由 build 流程驱动
结论: 不是空壳 —— flow.sh 状态机 + 两状态文件 + 三道引擎强制审闸(design/plan/build,本版修平) + 三 hook,全在代码坐实。之前 design/plan 强制、代码落地(③④)弱的不对称已消除:同一套 gate map 机制,引擎吐确切审命令。全量测试(8 脚本 + build)绿、零 drift。
