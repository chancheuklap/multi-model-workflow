步 9

verifier 子代理，只审一次

新◆F9◆F10

输入（brief）

  • 只有票号。它自己 gh issue view 读每条 AC 的 CHECK/EXPECT/MANUAL 与 Seam；与 worker 同一 worktree，git rev-parse HEAD 自取 commit
  • 禁令（不改仓库文件不 commit 不修不加标准、首尾 git status --porcelain；可以动环境：装依赖、换端口、找配置）、五级定义、汇报格式全在 agents/verifier/body.md，不由 worker 转述

动作

  • 在 code-review 之前跑（定案 2026-08-28：先验后审，避免 verifier 返工后再复审）；由运行 implement 的那个会话派出（白天手工、夜间 Herdr 同一流程）；能选模型就选与自己不同的；不能派子代理 → 自己从干净 shell 重跑，标 self-reported
  • 同样从票派生账本，跑 gate-check.mjs --reverify --approve（已勾的也重跑）；不评代码

产出

  • verifier 自己 gh issue comment 到票上：一行 VERDICT <sha> <level> by <model|self-reported> — 一句话 + 逐条结果；worker 之后读票。level ∈ live-ui-verified / unit-test-verified / type-check-only / verifier-blocked / verifier-failed

  • 新 第四个 subagent mmw-v2/agents/verifier/：agent.json 五宿主各选与写码常用模型不同的；Claude/pi 给 Read, Grep, Glob, Bash；body 写动作、五级定义、两次 git status、REPORT。06-independent-verifier.md §8.2–8.3；定案 00「第三轮之后的定案」verifier 的父会话 行。
  • 事实 「不同模型家族」pstack 无数据；Claude Code 只能选 Anthropic 内模型；Grok/Codex 子代理能否按定义切模型未实测。06 §3。
  • ◆F9 派发条件：定案序列「worker 自跑 → verifier 一次」读起来是每票都派；06 §5.2 只对四类票派（有 MANUAL 或 Seam 在界面、无人看守、Owns 触及迁移/鉴权/对外接口/共用路径、CHECK 要起 app/DB），其余 self-reported。
