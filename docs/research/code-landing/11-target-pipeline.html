MMW v2 落地流水线蓝图

一张票从 spec 到关票要走 14 步。每一步在这页上都是一张图；图里出现的每样东西按它的机制画：技能、脚本、hook、subagent、会话、票、评论、标签、文档、外部系统——十种，各一种固定画法，下面十张小卡是全页的图例。每张图下面一条编号：Sn 本页步号，§n 落地 spec #60 的 Implementation Decisions 节号，#nn 落地票。

词汇全部取自根 CONTEXT.md（146 条，英文正名加中文正名）；定案出处是 docs/research/code-landing/12-decisions.md，各图引用的字母加数字（如 I3、H4）是那份文件的记录号。图的画法用 diagram-design 默认样式（paper #f5f5f5、ink #2d3142、accent #eb6c36），未按品牌定制。

技能 SKILL

多个 agent 复用的做法。白底、实线、名字用正体。

软链进 ~/.agents/skills；正文改完下一次调用即生效。

脚本与子命令 SCRIPT

固定操作，模型不逐步照做。白底、实线、名字用等宽字。

verify-ticket.py 五个子命令、dispatch.sh、visual-parity.py、gate-check。

hook HOOK

宿主强制，模型绕不过。橙色虚线边界。

只有一个：hook.py pretool。半途停下的处置在 #87，本轮不做。

会话 SESSION

经 Herdr 起在自己 pane 里的宿主进程。灰底、实线。

主 agent、worker（junior / senior）、reviewer。

subagent AGENT

在派它的会话里面跑，Herdr 看不见。灰底、虚线。

verifier、advisor、claim-checker；模型在 models.md，成品由 assemble.py 装配。

票与 spec TICKET

GitHub issue，唯一的事实与状态存放处。淡灰底、灰实线。

spec 是票的容器，不打状态标签。

票评论 COMMENT

脚本或 agent 落到票上的一条评论，以首行为名。方角、等宽首行。

NOT_READY: self-run reverify VERDICT REVIEW ALL MET HANDOFF REQUIRED。

标签 LABEL

只表达票在哪个队列。小方片。

五个：needs-triage needs-info ready-for-agent ready-for-human wontfix。

文档 DOC

事实，只给指针不抄写。折角页。

CONTEXT.md、models.md、AGENTS.md、ADR、基线目录。

外部系统 EXT

流水线用而不改的东西。极淡底、淡边。

Herdr、GitHub 网页、Claude Design。

5 三种「做不下去」：只有两种让票停下

标准层三个 kind，每一个机器都据它做不同的事：failed 要票上有三轮自跑的记录，stuck 不看轮次，decision 不挡关票。
