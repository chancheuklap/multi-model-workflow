这页在比什么

MMW 只有一条主工作流：白天把想法定成一份 spec，拆成一批带命令验收的 ticket；夜里脚本把 ticket 派给 worker 并行做完、验收、合并进一条临时分支；早上人看报告，接受后并入项目分支。

pstack 里和它重叠最多的完整路径是：Multi-phase plan（写逐 PR 计划）→ 人明确 go → Autopilot（每个 PR 派一个云端 owner 并行做，root 每轮独立验证）→ 合并（full）或交人落地（stack）→ 早上审阅决策记录，需要时 reflect。

怎么读

  1. 先看为什么选这条来比（重叠矩阵）。
  2. 再看两条流程左右并排，每个阶段中间一栏写「同一意图，两种做法」。
  3. 意图对照把 MMW 的每个设计还原成它要达到的目标，再看 pstack 用什么办法达到同一目标。
  4. 实地证据是 MMW 8 个夜晚里反复出现的问题。
  5. 改造研究问题按证据强弱排序：每题先写要保住的意图，再写可替代的路径。

调查说明

  • 来源：pstack 快照 docs/research/code-landing-refs/pstack/（cursor/plugins b0b9c7a0）；MMW 本仓库 dev。本轮 5 个 Codex agent（GPT-6-Sol medium）：I1–I3 从 31 份 ADR、CONTEXT 与技能原文提取 MMW 前半段、过夜机器、单票循环共 73 个设计元素的意图；I4 提取 pstack 这条工作流 38 个设计元素的意图、防的失败与代价；I5 用只读的 gh 与 nmem 查实跑记录。前几轮的流程调查也用于并列总图。原始数据在 docs/research/workflow-compare/reports/。
  • 意图对照与改造问题是我根据这些数据写的归纳；每条意图的出处在对照表里，每个实地问题的证据位置在问题卡里。
