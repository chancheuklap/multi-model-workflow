      调查说明

      • 来源：pstack 为 docs/research/code-landing-refs/pstack/（cursor/plugins b0b9c7a0，2026-09-23）；MMW 为本仓库 dev 的 362aa555。
      • 方法：6 个 Codex agent（GPT-6-Sol medium）各读一块，只读、不运行任何脚本，读实现而不只读 README：P1 pstack 主线、P2 pstack 编排与脚本、P3 pstack 其余技能、M1 MMW 前半段、M2 MMW 过夜机器、M3 MMW 单票循环。原始报告在本仓库 docs/research/workflow-compare/reports/。页面上每个方块的出处都来自这些报告；我抽查了模型分配、orch 只记账、owner 自行 squash merge、30 分钟 tick、frontier 计算几处，与原文一致。
      • 所以这是规定与代码的静态读法，不是实测：没有真正跑过 pstack，也没有观察一整夜 MMW。

      调查员标出的出入

      • pstack Opening a PR 写「每个 playbook 结束都调用」，但 Investigation 明写不开 PR；图按后者画。
      • pstack Orchestrate 要求用 Graphite 的 gt 管 stack，orch frontier set 也只读 gt；而 Autopilot-full/stack 明写不要求 Graphite。两套 stack 机制不能当成一种。
      • MMW finish 的书面 runbook 只说「检查前置条件」，实现 finish_preflight 还要求同一 base branch 的相关 ticket 全部关闭；summary 却允许有待分诊的票。人接受报告不能越过这道门。
      • MMW check 在安装检查不通过时会调用 install.sh 从已安装 checkout 修复，不是纯只读。
