这页画的是什么

MMW 从想法到合并的每一步：白天定决定、画界面、写合同与 spec、拆票；夜里开夜、派发、一张票从认领到关票、唤醒与活性、落地、收尾、复盘、早晨 finish；以及支撑这一切的安装、提示词、hooks、模型配置、看板和 Memory。

每个方块左上角标着它的载体：是技能正文、reference 文件、脚本函数、命令、hook、拼给 agent 的提示词、配置、仓库文件、GitHub 对象、事件、外部工具、常驻进程，还是人的决定。

右侧与每个阶段对齐的是每一步的根源：它来自哪个外部项目的哪个仓库、哪个文件哪一节（带 commit 或访问日期），是原样照搬、改写、只取思路，还是运行时调用它；以及顺着什么线索追到那里（研究笔记、ADR、spec issue、merge-note、提交、Memory 只是线索，不算来源）。找不到外部根源的步骤标为 MMW 原创，并写明查过哪些地方。

    左边从上到下是时间顺序，泳道是执行者；每个方块右下角写着它的根源项目，或「原创」。右边是与该阶段对齐的根源卡片：项目 → 仓库文件与小节 → 取了什么 → 线索链 → 可信度。点任一方块看它的全部细节、上下游与根源。

    前代谱系：曾借用、后被替换或删除

    这些外部项目进过 MMW 的前几代（plugin-v1、落地编排器 spec、0.2 verifier、旧检索插件），现行版本里已经没有它们的原文；列出来是为了看清现在的做法是从哪里演变来的。最后一格是不落在某一步、而是全仓约定的组成部分。

    调查员标出的断点与不一致

    画图时遇到的「原文未写下游」「文档与实现不一致」「读不到」，按组列出。

    调查说明

    • 流程：本仓库 dev。4 个 Codex agent（GPT-6-Sol medium）只读画出节点和连线：C1 白天与界面前段、C2 过夜机器、C3 单票循环与界面下游、C5 工具箱；合并后 0 个孤立节点。8 个已安装但不在主流程上的技能（按 mmw-v2/skills.txt 核对）补在最后一个阶段。
    • 根源：另 5 个 Codex agent 逐个组成部分追溯到外部项目仓库：T1 白天与界面、T2 夜里机器、T3 单票与界面下游、T4 工具箱、T5 全仓历史与上游逐段对照。线索来自研究笔记、docs/research/code-landing-refs/ 快照、mmw-v2/merge-notes/、ADR、spec issue 正文、提交信息、archive/ 与 Nowledge Mem；线索只用来找到外部仓库，页面上的「根源」一律写外部仓库里的文件与小节，并附 commit 或访问日期。
    • 可信度：确证 = 本仓库文本或快照与外部原文逐字或近乎逐字对得上，或 ADR / merge-note 明写出处；较可信 = spec issue、研究笔记写了借自该项目，但现行代码已改写到对不上原文；推测 = 只有间接线索。
    • 「MMW 原创」的意思是：调查员查过卡片上「查过」列出的那些地方，没找到外部根源；不排除作者当时读过某篇资料但没留下记录。
    • 组成部分挂到步骤的方法：优先用调查员给出的节点 ID；没有时按 MMW 文件路径加小节标题匹配，其次按文件、按技能目录。逐段对照每段只挂到最贴近的一个步骤。
    • 原始数据：docs/research/workflow-compare/reports/C1–C5*.json（流程）与 T1–T5*.json（根源）。全部是对文件、代码与外部仓库的静态读法，没有运行任何流程。
