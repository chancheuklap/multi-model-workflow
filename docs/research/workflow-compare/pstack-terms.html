pstack 是什么。Cursor 官方插件仓库 cursor/plugins 里的一个插件，把一位工程师（poteto）的工作方式写成技能、agent 类型和几个脚本。装进 Cursor 后，它不是一个后台服务：它是一组给 agent 读的说明，agent 读了再照做。

读这页前要知道的一件事。pstack 里「调度」几乎全靠 agent 读文字规则完成；脚本只做两件窄的事：orch 记账，watch-pr 看 GitHub 状态。这和 MMW 用脚本决定派发、合并正好相反，所以很多同名的词含义不同，见「和 MMW 同名不同义」一节。

pstack 由什么组成

从下往上：Cursor 提供的能力 → pstack 插件本身 → 它带的脚本 → 运行时产生的东西。点术语跳到它的卡片。

状态值：机器与 agent 用来交接的固定词

绿色是通过或可推进，红色是失败或阻断，黄色是等待或需要判断。只列代码或技能里写死的值。

23 条原则（principle-*）

pstack 的工程价值观。每条是一个独立的技能文件，但不是每次都整篇读。

1 · 常驻的只有索引poteto-mode 开头读一张「什么情况用哪条」的触发索引，不读 23 篇正文。
2 · 触发时读全文某个决定碰到触发条件，agent 才读那条 principle-*/SKILL.md 全文；playbook 和其他技能也会点名引用。
3 · 说明改变了什么应用一条原则后，要在答复里说它改变了哪个决定。
4 · 不能单独调用23 个文件都设 disable-model-invocation: true：宿主不会因描述匹配而自动加载它们；人可以说出原则名来引导。
