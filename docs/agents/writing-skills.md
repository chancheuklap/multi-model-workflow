# 写技能

写法以 `writing-for-agents` 为准，它只有一份，在 `mmw-v2/upstream/skills/productivity/writing-for-agents/SKILL.md`。改技能前读完整 `SKILL.md` 及其链接的 reference。下面是那份文档没有、在这个仓库里踩出来的补充。

- **例子不是规则。** 只在例子里出现过的路径形状、命名或映射，读者会照着外推。规则单独写一句，例子跟在后面。用户举的使用场景同样是例子——把它当成功能定义，做出来的技能会窄得只剩那一个场景。
- **路由表和分支表要有兜底行。** 写清「以上都不是」时怎么办。
- **既写清什么时候接手，也写清什么时候不接手。** 相邻技能能处理的情况给一条明确的移交行。
- **命令里每个参数和占位符都要说清值从哪来。**
- **只写你实际打开过的文件、实际跑过的命令。** 没跑的写「未验证」。
- **判「有没有人接」要 grep，不限定目录。** 限过范围的零命中只说明这次没搜到那里。
- **问用户之前先把级联算完。** 「把 X 搬去 Y」可能强制改名、强制改调用方；算不出来就说算不出来。

交给用户之前派一次冷读：一个 subagent，只给它那一个文件和读者手上保证有的东西，让它报出照着执行不了的每一句。不给上游原文、不给设计理由、不给同批的其他文件。

## 产出文档的技能

在「开始写」那一句点名 `readable-docs`；写完派 `claim-checker` 核对。

## 只允许人触发的技能

同时设两处：`SKILL.md` 的 `disable-model-invocation: true` 和 `mmw-v2/skills/<名>/agents/openai.yaml` 的 `policy.allow_implicit_invocation: false`。只设前者，Codex 会把这个技能从模型可见列表里整个过滤掉。

## 机械校验的边界

校验脚本只判机器能直接判定的事实：语法、结构、路径、配置完整性、产物一致性。质量、方法、语义和完成度由技能和主 agent 判断。
