## Same concept, several names

- **The release manifest** is named three ways in the same skill's own text: "release manifest" in prose (`exe-release/SKILL.md`, `references/key.md`, `references/new-product.md`), "adapter" in the literal filename and every script's `--adapter` flag (`key.md`: "The filename and the `--adapter` flag every script below takes say `adapter`: both are literals the scripts read. Prose calls this file the release manifest."), and "钥匙" (key) throughout `scripts/release-flow.sh`'s Chinese comments and in `scripts/verify_key.py`'s docstring ("出包前把钥匙对着仓库核一遍") — the Chinese name matches the reference file's own name, `key.md`.
- **The release engine** is called "release engine" in the English prose of `references/driving.md` and `references/key.md`, and "引擎" throughout `scripts/release-flow.sh`'s Chinese comments (e.g. "引擎的分派依据", "引擎供的".
- **Host and runner neutrality**: the rule is stated once, in full, as `### Paths, tokens and host neutrality` in `mmw-v2/upstream/skills/productivity/writing-for-agents/SKILL-SET-REVIEW.md`, and is referred back to by the short Chinese label "host 中立" in at least four of this group's merge-notes (`tdd.md`, `improve-codebase-architecture.md`, `wizard.md`, `grill-with-docs.md`), each linking to `README.md#host-中立` rather than restating the rule.
- "Recommended answer" (manage-agents-md `SKILL.md` `## Ask the user`) and grilling's "推荐答案" (`mmw-v2/merge-notes/grilling.md`) name the same practice — a survey- or fact-derived suggested answer the user confirms or corrects — independently in two different skills. Not flagged as a naming problem: each skill states its own version of the same pattern consistently within itself.

## Same name, several concepts

- **"hook"** names three different things across this group's own text: (1) a host-run program `install.sh` registers (`tool-guard.py`, `turn-guard.py`), named "hook" in root `AGENTS.md`'s `## Commands` and `## Gotchas`; (2) a `build_hooks` callback point in the release pipeline, named "hook" throughout `exe-release/references/key.md` and `scripts/release_contracts.py`'s `ReleaseBuildHooks`; (3) the git commit-time hook `prek` runs, named "hook" throughout `code-checkers/references/git-hooks.md`. The three are unrelated mechanisms sharing one bare word inside this group's own reading.
- **"finding"** names two different things: (1) exe-release's build-failure diagnosis, carrying a tier, a root-cause fingerprint and a remediation (`scripts/diagnose_core.py`, `scripts/release_contracts.py`, `scripts/fix_dispatch.py`); (2) writing-for-agents' skill-set-review finding, an established problem in a skill's text or structure that is always fixed and carries no severity level (`SKILL-SET-REVIEW.md`, `REVIEWING-A-SKILL-SET.md`).
- **"manifest"** is milder but present: exe-release's "release manifest" (a packaging declaration, `exe-release/SKILL.md`) and code-checkers' "project manifest" / "dependency manifest" (`pyproject.toml`, `package.json`; `code-checkers/SKILL.md`) are different documents. Both skills consistently qualify the bare word with an adjective, so the risk is low, but a reader skimming both in one sitting could conflate them.
