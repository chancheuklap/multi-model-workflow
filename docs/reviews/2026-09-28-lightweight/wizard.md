# wizard


## 定稿（主 agent 复核）

**判断**：`wizard` 是生成"交互式配置向导"脚本的技能：agent 为一件要人动手的配置工作（例如在阿里云控制台开 AccessKey、再填进仓库）写一个 bash 脚本，人照着脚本一步步点、一步步粘贴。上游正文和模板都成立（"The delightful UX is already solved by template.sh … Your job is only to scope the procedure and author its stages" 是好的分工句）。三处修复都来自用户在 agentflow #594 的一次真实使用，改在本仓的副本里，各在 `mmw-v2/merge-notes/wizard.md` 记一条。不提交给上游作者（2026-09-28 用户已定）。

### 三处修复分别解决什么

1. **控制台路径过时，人找不到按钮（I1）。** agent 写向导时凭记忆写了阿里云控制台的点击路径，而控制台已改版（"OpenAPI 调用访问" 改名成 "使用永久 AccessKey 访问"），用户两次截图回来问该点哪里。修法：每一步除了点击路径，还写明这一步要达成什么（开哪个设置、设成什么值、拿到哪个密钥），路径变了人仍能按目的找到控件；凭记忆写的路径要标注出来。
2. **中文文案让脚本在第 2 步直接崩溃（I2）。** 向导脚本里写了 `"区域：$REGION，下一步"` 这种中文句子。本机 macOS 自带的 `/bin/bash` 是 3.2 版，它会把紧跟在 `$REGION` 后面的全角逗号当成变量名的一部分，于是报"变量未定义"并退出。本会话已复现：`/bin/bash -c 'set -u; REGION=cn; echo "区域：$REGION，下一步"'` 输出 `REGION�: unbound variable`，退出码 127。语法检查（`bash -n`）和 `shellcheck` 都查不出来。修法：要求所有变量写成 `${REGION}` 这种带花括号的形式。
3. **一个没用到的颜色变量引出了误改（D1）。** 模板 `template.sh` 第 17、19 行定义了 `RED` 但从来没用。`shellcheck` 因此报警告，agent 为了消掉警告，去改了模板里标明不该手改的公共部分。修法：删掉这个变量。

## B. 灵魂

### 保留，勿删

- `SKILL.md` 第 8 行 `A **wizard** is a bash script that walks a human … tedious to do by hand and tedious to re-explain to an AI every time.`：一句话讲清为什么要做成脚本而不是把步骤写进聊天。agent 靠它判断这件事值不值得做成 wizard。
- `SKILL.md` 第 10 行 `**Your job is only to scope the procedure and author its stages.** … that consistency is the point`：这就是 MMW 那条"脚本做确定的事、文字写判断"的分工，而且把理由（一致性）也说了。
- `SKILL.md` 第 12 行 `A wizard is ephemeral by default`：定下产物的寿命，挡住 agent 顺手把一次性脚本提交进仓库。
- `SKILL.md` 第 18 行 `Read the repo first, don't ask cold`，以及第 20 行 `every secrets.* / vars.* reference is a value the wizard must produce`：前者是态度，后者是判断"值齐了没有"最准的一条依据。
- `SKILL.md` 第 29 行 `never invent steps that may not exist`，以及第 31 行 `a stranger could follow`：这是 wizard 质量的核心标准，下面缺口 B1 在它的基础上补。
- `SKILL.md` 第 37 行 `keep a stage to one focused task so nothing the human needs scrolls away`：把一条排版规则和它的理由（`stage` 会清屏）绑在一起，agent 才不会把几件事塞进一个 stage。
- `SKILL.md` 第 43 行 `Don't run it end-to-end yourself: it opens browsers and blocks on human input. Trace it statically instead`：给了不跑的理由和替代的检查方法。在无人值守的场景里，这句尤其重要。
- `SKILL.md` 第 44 行 `so the next person runs the script instead of asking an AI`：交代这份产物的下游读者是谁。
- `description` 的 `Don't invoke this for steps the agent can perform itself.`：这是整个技能的边界。上游 CHANGELOG 原话是 "Work an agent can do, an agent should do"。

### 缺口与补充草稿

- **B1**，位置：`SKILL.md` `### 2. Map each stage's journey`，接在 `never invent steps that may not exist.` 之后。
  缺什么：技能只要求写出点击路径，没告诉 agent，真正面对控制台的是人，而且控制台改版比 wizard 重写快；路径失效时人手里该有什么可以依靠。
  证据：在 #594 那次，agent 凭记忆写了阿里云 OSS 和 RAM 控制台的路径，既没查文档，也没在 wizard 里标出哪些是凭记忆写的。用户跑到第 2 个 stage 时回来说「这一步不够详细，根据截图单独教我」，建 RAM 用户时又说「这一步又不同」（新版控制台把 `OpenAPI 调用访问` 改成了 `使用永久 AccessKey 访问`）。两次都要 agent 对着截图重新讲解，这正是技能想省掉的"给 AI 再讲一遍"。事后 agent 在提交 `bffc6d60f` 里改了 wizard 文案。
  补上之后，agent 写出的每一步会带上"这一步要达成什么"，凭记忆写的路径也会在 wizard 里标出来，人遇到改版可以自己找到对应的控件。
  > The human, not you, meets the live dashboard, and dashboards are redesigned more often than wizards are rewritten. With each click path, say what the step must achieve (the setting and its value, the permission granted, the key revealed), so a human facing a renamed or moved control can still find it. A path you wrote from memory rather than from current docs gets a `note` in the stage saying so.

  注：这是改上游原文。它在本用户的真实使用里造成过返工，但问题是普遍的，不是 MMW 独有。可以在本仓补并在 merge-note 记一条，也可以只提给上游（后者属于对外公开发布，由用户决定）。

## 脚本

`template.sh` 没有过度防御：`open_url` 的四路回退、`gh` 缺失或未登录时的回退、`_clear` 在非终端下什么都不做，都是正常输入能走到的情况（不同操作系统、没装 `gh`、输出被管道接走）。我在 scratchpad 里把库部分（第 1–180 行）单独拿出来，用本机 `/bin/bash` 3.2.57 跑过：数组为空时 `finish` 返回 0，`write_env` 反复写同一个键时是覆盖而不是追加，`ask` 回车时保留旧值。三项都正常。

- **S1（模板瑕疵，已造成一次越界编辑）**：`template.sh` 第 17 行定义了 `RED`，第 19 行在无色分支里也定义了，但整个库从没用过它。`SKILL.md` 第 41 行要求 `run shellcheck if available`，于是每一份生成出来的 wizard 都会报 `SC2034 (warning): RED appears unused`（在本仓对模板本身跑 `shellcheck -S warning` 已复现）。#594 那次，agent 为了消掉这条警告，在生成的 wizard 第 2 行插了 `# shellcheck disable=SC2034,SC2029`。这一行落在 `STAGES` 标记以上，也就是 `never hand-edit it` 的库区。建议删掉两处 `RED` 赋值（改动 1 行），或者只提给上游。删掉后没有功能损失：库里没有任何地方读它。
- **S2（观察，不建议改）**：`set_var` 成功时不记入任何列表，所以 `finish` 的总结不列 GitHub variable；跳过时写进 `SKIPPED` 的文字也不像 `set_secret` 那样带上手动补做的命令。没有使用证据表明这造成过问题，上游原文，不提。
- **S3（观察，不建议改）**：同一个键 `write_env` 两次，`WRITTEN_ENV` 会记两遍，总结里显示成 `FOO FOO`（scratchpad 实测）。纯显示问题。

## 上游原文在本工作流里让 agent 做错的（单独列出）

- **U1（可复现，影响本用户每一份中文 wizard）**，位置：`SKILL.md` `### 3. Author the wizard`。
  问题：stage 文案里写 `$VAR` 时，只要后面紧跟一个全角字符（例如 `$REGION（`），脚本就会在 `set -u` 下以 `REGION�: unbound variable` 退出。#594 那次，用户跑到 Stage 2/9 时就是这样中断的。
  原因：我在 scratchpad 里复现了，但条件和当时那个 agent 说的相反。本机 `/bin/bash` 3.2.57（`#!/usr/bin/env bash` 在本机解析到的就是它，这台机器上没有 Homebrew bash），在 `en_US.UTF-8` 和 `zh_CN.UTF-8` 下会把多字节字符的第一个字节并进变量名，在 `C` 下反而正常。那次 agent 的诊断是"非 UTF-8 locale"，这个诊断是错的，但它的修法（改成 `${VAR}`）是对的，用户随后走完了 9 个 stage。
  `SKILL.md` 第 4 步规定的检查（`bash -n`、`shellcheck`）都拦不住这个问题，那次两项都通过了；而技能又明确不让 agent 端到端跑。所以唯一能起作用的是写作时的一句话。
  建议在第 37 行那段 `Hold the bar …` 之后补一句，并在 merge-note 的 `### SKILL.md` 下记一条：
  > Write every variable inside stage text as `${NAME}`, never `$NAME`: when a non-ASCII character follows the name (a full-width bracket, CJK text), bash 3.2, still the default on macOS, reads part of that character as the name and the wizard dies under `set -u`. `bash -n` and `shellcheck` do not catch it.
- **U2**：见 B1（控制台改版）。
- **U3**：见 S1（`RED` 未使用，诱使 agent 改库区）。
