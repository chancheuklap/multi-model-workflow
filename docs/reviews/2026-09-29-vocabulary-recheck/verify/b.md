## Notes

- **Two renames touch one sentence.** Rows 8 and 9 both edit `docs/contexts/tickets/CONTEXT.md:123` ("The contract, design-system and acceptance tickets ... are not interface tickets"). Applied together it reads "The contract, design-system and critical-flow tickets a screen contract also produces are not page tickets."
- **Upstream location vs upstream text.** Of the four terms the task flagged as upstream, only `seam` and `agent brief` are upstream's own words. `stance` is in `SKILL-SET-RULES.md`, which MMW wrote (`mmw-v2/merge-notes/writing-for-agents.md`). The `visual` argument text is MMW-added (`mmw-v2/merge-notes/wait-what.md`). Neither carries a merge cost.
- **Polarity of "negative control" (for the ui-acceptance verifier).** In laboratory usage, a sample known to give a positive result, which proves the assay can detect, is a *positive* control. An oracle pass that must report a planted difference is that kind of pass. Whether "negative control" (`docs/contexts/ui-acceptance/CONTEXT.md:249`, kept on 2026-09-28 as "established ... used in its sense") is in fact the established software-testing term, or a false friend, was not settled here. It belongs to the ui-acceptance slice.
- **`interface` in its bare UI sense.** Row 8 fixes the ticket name only. Bare "interface" in the user-interface sense ("an effort with an interface", `to-spec/SKILL.md:22`; "the interface takes no fake data", **static guards**) stays ambiguous with the module and HTTP senses. It is not a proposal in this group.
