# Review and Integration

这个上下文定义产物如何被独立审查、finding 如何被判定，以及结果分支如何进入任务分支。

## Language

**审查**：
针对一个固定产物和指定视角进行的只读缺陷检查。产物作者不得在自己的上下文中担任审查者。
_Avoid_: 自检、验证

**审查视角**：
一轮审查中一组互不替代的判断范围，例如设计内容审、项目一致性审或独立终审。
_Avoid_: 审查者实例、评分维度

**固定点**：
一轮审查开始时锁定的提交 SHA 或文档版本。该轮 finding 只针对这个版本成立。
_Avoid_: 当前 HEAD、浮动分支

**finding**：
审查者发现的、有具体影响并带目标版本出处的实际缺陷。设计选择、纯品味和无证据猜测不是 finding。
_Avoid_: 建议、候选、评分项

**处置**：
主 agent 验证 finding 后写入审查记录的机器可扫结论。只有 `accepted` 可以驱动当前轮返工。
_Avoid_: 审查者 verdict

**`accepted` finding**：
主 agent 已验证成立，而且应在当前轮修复的 finding。

**`rejected` finding**：
主 agent 验证后判定不成立或源于审查者误读的 finding 候选。

**审查记录**：
保存固定点、审查者原始报告、逐条验证证据和处置的任务内文件。审查记录不进入 Wiki。
_Avoid_: spec、终审结论摘要

**合同门**：
所有实现 ticket 合入任务分支后，主 agent 对跨 plan 合同是否在代码中兑现的机械验证关卡。
_Avoid_: final 终审、人工审批关卡

**final 终审**：
所有实现完成并通过合同门后，对任务分支整体执行的第五道审查。它包括对照终审、独立终审与编码规范审。
_Avoid_: 每张 ticket 审查、用户验收

**合并集成审**：
多条结果分支合入任务分支后，对组合行为、合同和冲突取舍执行的第六道审查。
_Avoid_: 单分支 final 终审

**结果验证**：
集成前按结果分支名、报告 HEAD、实际 HEAD 与基点确认报告和 Git 状态一致的检查。
_Avoid_: 只读报告、自述通过

**结果集成**：
通过 `git merge --no-ff` 把已验证结果分支合入当前任务分支，并保留提交历史的动作。
_Avoid_: squash、直接合入默认分支
