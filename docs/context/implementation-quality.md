# Implementation Quality

这个上下文定义 bug 诊断与测试先行开发的质量判据。它不重新决定 spec 已确定的行为或 seam。

## Language

**tight loop**：
可以稳定运行、快速反馈并在缺陷存在时变 red 的最小诊断循环。
_Avoid_: 手工猜测、宽泛测试套件

**red**：
测试或可观察反馈因目标缺陷或尚未实现行为而失败的状态。red 必须对应真实目标行为。
_Avoid_: 任意失败、环境故障

**green**：
最小实现使当前 red 行为通过，同时相关回归保持通过的状态。
_Avoid_: 整体完成、无审查缺陷

**TDD 循环**：
围绕一个行为按 red、green 的顺序推进并保持验证可见的实现循环。重构与最终审查不属于这个循环。
_Avoid_: 先实现后补测试

**回归测试**：
在拥有目标行为的层上重现并阻止同一缺陷再次出现的测试。修复与回归测试必须属于同一行为改动。
_Avoid_: `fix_*` 测试文件、覆盖率占位测试

**correct seam**：
能够运行真实缺陷形态并覆盖触发链的测试 seam。过浅、无法重现真实调用关系的 seam 不正确。
_Avoid_: 最方便的单元测试位置

**seam**：
(authoritative: [seam](./codebase-design.md))

**mock**：
替代真外部系统、并只模拟当前测试所需合同的测试 adapter。进程内依赖和可用本地替身优先使用真实实现或本地 adapter。
_Avoid_: 任意内部对象替身、调用次数测试

**质量门**：
测试进入仓库前必须全部满足的资格线与禁止形态。质量门是合入条件，不是建议。
_Avoid_: 测试风格建议
