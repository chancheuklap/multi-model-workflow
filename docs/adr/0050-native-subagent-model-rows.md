# 原生子代理的型号与强度由它那一步点名的行决定

MMW 只在正在执行的步骤点名时派宿主的通用子代理，用该步骤点名的子代理行决定型号与思考强度。行登记在 dispatch 技能的 `roles.json` 的 `subagents` 段，每行按宿主记录配置。每个会话角色和每个子代理行的型号与强度只存进 `~/.mmw/models.json`，只通过 `models.py` 改。派遣前用 `models.py subagent <行> <宿主>` 查值，具体值带进派遣调用，`inherit` 不传，沿用宿主的继承行为。这次没有生成任何子代理定义文件。

## 派遣调用已经能带型号与强度

[0015](0015-no-custom-subagents.md) 删除定义文件的理由今天仍然成立。提示词正文由技能给出，只读约束写在子代理读取的文字里，不需要按宿主生成定义文件并维护软链。要单独设置型号与强度，也不需要恢复那套组装系统。

[#1025](https://github.com/chancheuklap/multi-model-workflow/issues/1025) 的 `## Sources` 记录了派遣接口的依据。Claude Code 从 2.1.292 起，派遣调用可直接带型号与强度。2026-10-14 的 Codex 0.162.1 实测显示，`spawn_agent` 参数含 `model` 与 `reasoning_effort`，父会话派出的子会话采用了指定的型号与强度。

`roles.json` 的 `subagents` 段登记 `review-axis`、`reader`、`default` 三行。子代理行没有会话角色那样的 `default` 启动配置，三行的初始型号与强度均为 `inherit`。名为 `default` 的子代理行用于步骤明确点名该行，或步骤点名派子代理却未点名行的情形。没有步骤点名的派遣不使用任何行，也不派子代理。

## Considered Options

- 所有子代理固定跟派它的会话使用同一型号。否决。主人无法单独调整审查维度的成本，而派遣接口已经支持单独设置。
- 恢复宿主专用的子代理定义文件。否决。型号与强度可直接传入派遣调用，生成文件、软链与同步检查没有必要。
- 让派遣步骤直接写具体型号与强度。否决。配置会散落在技能文字中，不能由主人在一个文件里调整。

## Consequences

- 0015 关于不交付子代理定义文件的决定不变。它关于子代理只能用父会话型号、单独换型号需要另设入口的限制不再成立。
- 主人可通过 `models.py config subagent` 改一行，下一次点名派遣就读取新值，不影响 reviewer 等会话角色。
- 每个点名的派遣都派新的子代理。worker 仍为它那一次审查修正保留会话。
