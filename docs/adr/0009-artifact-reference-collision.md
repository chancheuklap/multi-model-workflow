# 撞名由生产方当场列父目录发现，重新取名，不进机械校验

产物引用的第四项类别内细分由生产它的技能当场取名，两件产物取到同一个名字时四项全部相同，解析出同一条路径，后写的覆盖先写的，前九个决定里没有一条规定这种情况。现在改为：生产它的技能在写第一个文件之前列一次目标路径的父目录，目标已经存在就重新取一个承载差别的名字，取不出来时加序号兜底，全程不问用户也不报告。理由是父目录里现有的兄弟目录就是这一刻已被占用名字的完整集合，列一次就能得到，不需要任何注册表文件；而机器看得见「这条路径已存在」，看不见「上一次那件产物是不是同一件事」，所以这件事只能由取名的那一方在取名的那一刻做。

## 会撞的只有两处

- 同一次交付里两次 research 取到同一个主题名。research 主题是类别根之下唯一一个顶层当场取的名字（`mmw/skills-src/mmw-research/MAIN.md:82,88`）。
- 同一棵 prototype 树里两个变体组取到同一个 `问题 slug`（`mmw/skills-src/mmw-prototype/UI.md:36`）。

其余类别的类别内细分不会撞：spec 是固定文件名 `spec.md`；plan 的两位编号由 `/mmw-to-tickets` 成批分配（`mmw/skills-src/mmw-to-tickets/SKILL.md:107`）；ADR 编号由 `mmw domain adr-next` 分配，并发时先写 `draft-<ticket 编号>-<短名>.md`；leaf 与 `.out-of-scope/` 是一概念一文件，同名即同概念；审查记录是四道关卡固定名，集成记录已有「同一天第二轮加序号」规则（`mmw/skills-src/mmw-review/SKILL.md:77`、`mmw/skills-src/mmw-integrate/SKILL.md:79`）。

`/mmw-research` 没有「接着上一次那份 research 继续写」的入口，`/mmw-prototype` 的第二轮是原地修改不新建目录（`UI.md:16,83`）。因此「路径已存在」在这两处不表示同一件产物的第二轮。ADR `0001` 的「同一个名字第二次做时覆盖原文件」讲的是 spec，spec 的类别内细分固定，不进查重范围。

## Considered Options

- **由 `mmw artifact path` 查重。** 否决。它同时服务读取侧，读取侧问的时候路径本来就该存在，所以它没法把「已存在」当成错误；而且按 ADR `0005` 它无副作用、不建目录，查到空也预留不了。
- **由机械校验发现。** 否决。ADR `0007` 已经把产物存在性和类别内细分的命名恰当性列入「明确不校验」；把「路径已存在」当成撞名去报错，会让每一次正常的新一轮迭代都红。
- **不发现，接受覆盖。** 否决。这正是本决定要挡住的后果。
- **发现之后停下来问用户。** 否决。用户选择自动处理。代价是撞名这件事不会有人知道，见 Consequences。
- **按类别名枚举覆盖范围（「research 和 prototype 要查」）。** 否决。类别数据放在产物落点数据里，枚举写法要求新增一个类别时同时改技能正文，按性质判定不用改。
- **跨交付主题名也唯一。** 否决。产物引用第二项是工作名，路径自带命名空间；强行唯一只会逼出不承载信息的名字。

## Consequences

- 规则按性质判定：类别内细分当场取名的类别，写第一个文件之前查一次；固定文件名、由分配器成批给号、一概念一文件的类别不查。这条性质要在产物落点数据里逐类标一位，否则技能无从判断自己该不该查。
- 重新取名之前先读已存在那件产物的索引，确认这次要答的确实是另一个问题。产出的是 `artifact-inventory` 与 `artifact-consumers` 这种名字，不是 `artifact-inventory` 与 `artifact-inventory-2`。序号只作兜底。
- 撞名不向用户报告，也不写进交回内容。后果是同一次交付里出现带序号的目录时，没有任何记录解释它为什么带序号。这是本决定接受的代价。
- agent 靠两层知道要查重，缺一层都会回到覆盖。第一层是 `mmw artifact path` 的输出：解析出属于当场取名这一类的类别时带一行提醒。第二层是技能正文在取名那一步写一句。只做第二层会重蹈 ADR `0005` 否决过的毛病，把「哪些类别要查重」复制进每份技能正文；只做第一层会漏掉不跑命令直接拼路径的 agent。
- 并发会话的撞名靠 Git 合并冲突暴露，不另加机制。两个会话在各自任务 worktree 里各写一件同名产物，各自列父目录时都看不到对方，合回时 Git 对「两边都新增同一条路径、内容不同」判 add/add 冲突。Wayfinder decision ticket 各有自己的范围段 `issue-<编号>`，真会撞的只剩同一张 ticket 派生出两条分支。
- 不进机械校验，ADR `0007` 不改。这是行为层规则，与 ADR `0006` 的「下游读不到该有的那一节就停下报缺」同类。代价是一个不跑命令、也不看技能正文的 agent 仍然会覆盖掉别人的 research，没有任何机械层挡它。
- 性质标记的字段名与取值、`mmw artifact path` 那行提醒的字面、技能正文那一句的字面及其出现位置、「读已存在那件产物的索引」在没有索引文件的类别上具体读什么、序号兜底的形状，都留给 spec 阶段。本决定只定机制。

## 与 aidlc-workflows v2 的对照

| aidlc 的做法 | 本决定 | 关系 |
| --- | --- | --- |
| Collision policy：`"Two stages must not declare the same canonical name in their"`（`docs/research/mmw-artifact-wiring/issue-20/aidlc-v2-artifact-wiring/report.md` 第 2 节） | 不照搬全局唯一 | aidlc 的 canonical name 就是全局标识，路径从名字反推，所以必须全局唯一。MMW 的产物引用带工作名，路径自带命名空间 |
| `"The registry is computed, not written."`（同上，第 8 节） | 照搬 | 已被占用名字的集合是当场列父目录算出来的，不写成任何注册表文件。aidlc 拿 `produces[]` 算，MMW 拿父目录算 |
| 概念重叠时拆成两个不同的 canonical name，磁盘文件名允许相同（同上，第 2 节） | 照搬 | 就是本决定的「重新取一个承载差别的名字」 |
| 机械校验只校声明层引用完整性（同上，第 11 节） | 有这个机制，本次不照搬到撞名上 | aidlc 能在声明层查重，是因为它有 `produces[]` 这份声明可查。MMW 的类别内细分不进任何声明层，只在运行时产生，没有可校的声明 |
