# 界面 QA 绑设计系统的格式规范，不绑生成它的工具

界面 QA 的 A3（设计系统 token 越界）与 B1（设计系统规则违反）需要一份机器可读的设计系统作为判据。我们把这两种检查项押在 DESIGN.md 这份格式规范上，而不押在任何一个生成它的工具上：目标仓库有这份文件就能跑，用什么工具写的、写它的工具还在不在，界面 QA 都不关心。

## Considered Options

调查过四个第三方的 DESIGN.md 生成工具，全部否决，理由是同一条：它们都从**渲染后的页面**逆向抽取当前值（无头浏览器或抓 URL）。这会把当前的缺陷固化成标准。这不是推测——我们对目标仓库现有的 `DESIGN.md` 跑过官方格式校验，67 条 finding 里有三条是对比度不足，其中主按钮的白字配琥珀色只有 1.93:1，而 WCAG AA 要 4.5:1。逆向抽取会把这三条写成「标准就是这样」，此后 A3 判得越准越糟。

因此技能在设计系统文件不存在时**提议建一份**，内容来自 intake 问卷与 MMW 已有产物，建完立刻转只读，此后永不再写。

## Consequences

这份规范当前的 `version` 字段就是 `alpha`，官方明确标明可能有破坏性变更。爆炸半径是可控的，这是选择依赖它的前提：规范出现破坏性变更时受影响的只有 A3 与 B1，其余七种检查项不受影响。

格式校验器的版本一度钉死在依赖声明里，这一条已被 [ADR 0004](./0004-design-system-trust-comes-from-lint.md) 推翻：改为与设计系统作者共用同一条不带版本号的调用，在同一台机器上解析到同一份。
