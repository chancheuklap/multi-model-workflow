# 工作名与任务分支名是两个值

MMW 原来有两个名字管产物落点：普通任务用一个值同时当任务分支名和产物目录名，Wayfinder 用两个互相独立的值。合并成一个概念「工作名」时，我们让它与任务分支名解耦——工作名标识产物归哪次交付，任务分支名标识改动在哪条线上。原因是一项 Wayfinder effort 有多条任务分支（每张 decision ticket 一条），用分支名当产物名会把同一项 effort 的 research、prototype 和 spec 散进多个目录，互相找不到。

## Considered Options

**用任务分支名当工作名**（否决）。它看着更省事：只有一个值，`mmw task state` 一跑就读到，不需要额外的存放位置。否决理由只有一条，但足够——它在 Wayfinder 场景直接散架。这个选项以后还会被重新提起，因为它的成本在普通任务上完全看不出来。

## Consequences

- `mmw task new` 和 `mmw task bind` 增加工作名参数，`mmw task state` 增加工作名输出位。工作名因此有了唯一的机械读取点，技能不再各自判断入口。
- 会话不在任务工作树里（`mmw task state` 返回 `local` 或 `outside`）时，没有地方存工作名。因此任何要往仓库写文件的技能必须先建任务工作树，不保留「用临时名字只写 scratch」的做法。
- 工作名的边界是一次交付：从默认分支新开任务工作树取新值，从已有任务工作树分叉的分支继承父分支的值。
