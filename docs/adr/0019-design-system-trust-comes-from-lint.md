# 设计系统文件可不可信，由校验结果定，不由来源定

ADR 0015 把界面 QA 的 A3 与 B1 押在 DESIGN.md 这份格式规范上，理由是四个第三方生成工具都从渲染后的页面逆向抽取当前值，会把当前的缺陷固化成标准。那条理由成立，但不完整：**缺陷不是逆向抽取独有的，官方自己发布的文件一样带着它。**

六家公开发布 DESIGN.md 的公司，取回来跑官方校验器：Vercel 零 error 零 warning；Nuxt 零 error 但 169 条断引用；Mintlify 零 error，typography 写成了数组以致属性名变成 `0`、`1`、`2`；Atlassian 29 个 error、445 个 warning，其中 11 条对比度低于 WCAG AA，还有 203 条引用指向不存在的 token，以及一句「没定义 primary 色，agent 会自动生成关键色」的警告；Clerk 与 Resend 挂着 `design.md` 的文件名，内容根本没有 YAML，不是这个格式。

所以判据的准入不看它从哪来，看它自己过不过得了校验。三档，封闭：

| 校验结果 | 判定 | 允许 |
| --- | --- | --- |
| 没有 YAML，不是这个格式 | 拒收 | 当场说明，不做别的 |
| error 大于零 | 只能参考 | 可以看写法，不许当 A3 与 B1 的判据，不许改名成产品自己的 DESIGN.md |
| error 为零 | 可用 | 可以当范本，也可以作为编纂的起点 |

warning 不参与分级，原样报出来由人判断——它说的是判据质量，不是格式合法性。

外部取来的文件与产品自己的 DESIGN.md 分开存放，旁边记来源：取自哪、哪天取的、许可、取回时的校验结果。这些是别人的品牌资产，参考写法与整个搬成自己产品的设计系统是两件事。

这一段不写成代码。取一份文件是一条 `curl`，跑校验是一条命令，三档是一条判断规则；写成脚本只是把一条规则藏进一个没人会去读的文件里。

设计系统不存在时委派谁去建，同时改掉：从 `pbakaus/impeccable` 换成 `ibelick/ui-skills@create-design-md`。ADR 0015 要求建完立刻转只读，而 impeccable v4 在 redesign 场景下会替换 DESIGN.md，行为与那条相反。新委派对象反过来：更新时比对新旧两版，恢复被误删的已接受决策，且 lint 与 export 都通过之前不允许返回文件。

## Considered Options

**信任官方来源，取回来直接当判据**，否决。Atlassian 那份 29 个 error 就是反例：判据自己引用着 203 个不存在的 token，A3 判得越准越荒谬。「官方」描述的是发布者，不是文件质量。

**继续委派 impeccable**，否决。它是审美工具，追求的是大胆和独特；DESIGN.md 在它的流程里是可替换的输入，而不是要守住的判据。两个目标不兼容。

**为取外部文件写一个管理技能**，否决。设想过的四件职责逐条查完一件不成立：取文件是 `curl`，过闸是一条 `lint`，钉版本是依赖声明里一行，判定产品归属新委派对象自己就做了，只读边界与下游接线属于界面 QA 那一侧。没有剩下的东西支撑一个技能。

**从社区 DESIGN.md 站点取**，否决。那类站点收录的是社区创作与逆向抽取的产物，且不标注校验状态——正是 ADR 0015 划出的那条线。人工当灵感看不受此限。

**把三档分级写进机械校验**，否决。三档的输入是校验器的输出，判定是一条一句话的规则；技能正文写得下的东西不该变成一个要维护的脚本。

## Consequences

规范当前仍是 alpha，官方明确标注可能有破坏性变更。爆炸半径与 ADR 0015 写的一致，加一处：A3、B1 两种检查，以及这里的三档分级。其余七种检查不受影响。

界面 QA 的依赖声明里，「设计系统作者」那一条的来源从 GitHub 稀疏检出改为 skills CLI 管理的 `~/.agents/skills/`。它不再是 npm 包也不再是仓库检出，因此依赖检查要单独判它的 `SKILL.md` 在不在——按包名回读安装器输出的老办法会把它永远判成已装，直到委派时才当场失败。
