# 回合守卫只拉起看门进程、不拦回合；看门进程对一条没 ack 的叫醒只提醒一次，不再报读不到 tracker

回合守卫 `turn-guard.py` 在每个 host 的回合结束时，对每个有开着的 watch 的仓库调一次 `watchdog.py arm`，然后放行。它不再拦主 agent 的回合，也不再拦没交答案的 brief 会话。看门进程的「等主 agent」提醒只针对已送达、`--nudge` 秒（默认 1800）还没 ack 的叫醒，每条叫醒只提醒一次。`relay not reading` 与「读不到 tracker」两种提醒删掉，中继重启时重送全部未 ack 叫醒的 `forget_deliveries` 删掉，`--silence` 删掉。主人的决定见 #1437。

## 要修的是什么

0021 把「看门进程不健康、还有票被占着时不让主 agent 的回合结束」定为第一层的一部分。`guard.log` 记了 2009 次回合结束，只拦过 4 次：一次主 agent（2026-09-15，TLS 故障，重新拉起也修不好），三次 Codex 上的 brief 会话（2026-10-19）。这些会话之后都由看门进程发现：`worker.lost`、丢失的 brief、空闲会话。「等主 agent」提醒在叫醒刚送达时就发，之后每 1800 秒再发：2026-10-29 它把主 agent 已经读过的 #1426 叫醒又报了一遍。两种读不到 tracker 的提醒留存 14 条，全是网络故障；中继在读恢复后会把自标记以来的事件全部重读（0008）。76 次中继启动里，`forget_deliveries` 一次也没重送过。

## 定下来的

- **第一层只剩重新拉起。** 拉起是幂等的，看门进程健康或没有开着的 watch 时什么都不做，所以任何会话的回合结束都可以调它。
- **回合守卫保留判断会话身份的函数。** `reply-check.py` 用它们跳过 brief 会话和主 agent，这些函数不随拦截一起删。
- **丢失的叫醒由年龄提醒兜住。** 送达后 30 分钟没 ack 就提醒一次；不再按「送达即提醒」，也不再按中继重启重送。
- **读不到 tracker 不提醒。** 故障期间的事件在读恢复后照常成为叫醒；中继进程本身死掉仍报 `relay down`。
