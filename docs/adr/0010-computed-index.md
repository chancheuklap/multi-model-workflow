# 索引由命令当场算出，仓库文件是它顺手写下的副本

> `/mmw-start` 已取消。消费 spec 索引的是 `/mmw-to-spec`。任务树由用户用宿主打开，agent 只在已有的树上创建任务分支。下面正文里的 `/mmw-start` 与「建任务分支」是当时的读法。

ADR `0001` 与 `0007` 各定了一份自动生成的索引文件（`docs/specs/README.md` 与 `docs/adr/README.md`），由一条 CLI 命令全量重建。现在改为：索引的权威形态是命令当场计算，agent 一律读命令输出；仓库里那两个文件是同一次运行顺手写下的副本，不是权威。没有一个需要谁记得去跑的重建动作——读的动作本身就是重建。理由是「谁在什么时机重建」这个问题没有可靠答案：MMW 装在别人的仓库里，那边没有 `bash mmw/test.sh`，而 `mmw doctor` 要人主动跑，日常开发没人跑它，所以任何「事后发现索引过期」的机制都发现不了。

## Considered Options

- **完全不写文件，只输出到标准输出。** 这是 `awslabs/aidlc-workflows` v2 的做法，原文 "The registry is computed, not written."（`docs/research/mmw-artifact-wiring/issue-20/aidlc-v2-artifact-wiring/report.md` 第 8 节）。否决理由是 MMW 有一条 aidlc 没有的消费方：MMW 是给多个仓库使用的工具箱，装到别人的仓库之后，那边有不通过 agent 阅读的人；他们在 GitHub 网页上打开 `docs/adr/` 只看得到九个文件名。aidlc 是单一工作流引擎，读者全部经引擎进入，没有这一类。
- **保持 `0001` 与 `0007` 的原读法：文件是权威，由生产者技能在写完新内容后重建。** 否决。它保留一个可以被忘记的动作，而忘记之后没有任何机制发现。`AGENTS.md` 给机械校验划的线里包含「生成产物一致性」，所以「重新算一遍与文件比对」这道校验本身合法；否决它的理由不是不合法，是跑不到——它只能挂在 `bash mmw/test.sh` 上，而那套测试只覆盖 MMW 自己这个仓库。
- **提交时由 git hook 自动重建。** 否决。这个仓库没有装任何 git hook（`git config core.hooksPath` 是默认值，`.git/hooks` 下只有 `.sample` 样例），`mmw init` 也不安装 hook。要用它就得新造一套 hook 安装机制。
- **命令默认写文件，另给一个只读开关。** 否决。多一个要 agent 记住的参数，而「要人记住」正是本决定否掉的那一类机制。

## Consequences

- 命令只在算出的内容与文件现有内容不同时才写。绝大多数时刻两者一致，命令跑完工作区不脏。真的产生未提交改动，说明这个仓库刚加了 ADR 或 spec，那本来就是该提交的东西。这一条是必要的：MMW 有几处流程要求工作区干净才继续，`/mmw-wayfinder` 建任务分支那一步就是。
- 这条命令有写副作用。ADR `0006` 规定 `mmw artifact path` 无副作用、不建目录，那条规定不变；本条说的是另一条命令，写副作用是它的设计的一部分，不是 `0006` 的例外。
- 仓库文件的新鲜度是「最近一次有 agent 读过清单的那一刻」。它承担的唯一职责是给不运行命令的读者看，不承担任何 agent 行为。
- `AGENTS.md` 里「读取 `docs/adr/` 下与本次范围相关的 ADR」这句话改为先跑清单命令、再读相关的那几份。那句话位于 `MMW-DOMAIN-CONTEXT` 管理段（`AGENTS.md:98-116`），由 `mmw domain sync` 写入，接口是现成的。spec 索引那一端不需要等价钩子，它的消费方是 `/mmw-to-spec` 与 `/mmw-start` 的技能正文。
- plan 不做索引。没有任何技能会问「这个仓库里有哪些 plan」；`worker` 从 tracer bullet ticket 进入，ticket 里写着产物引用，这条路不经过索引。
- 元数据块保留，与本决定选哪种形态无关：两种形态都从元数据块取数据。ADR 元数据块的唯一消费方是索引计算；spec 与 plan 元数据块另有消费方，也就是 `0007` 加的产物引用字段与它的解析校验。
- 本决定修改 `0001` 第 17 条与 `0007` 第 22 条中「仓库文件是权威、由命令重建」的读法。两条原文的其余部分不变。
- 命令的名字、子命令形状、清单字段、两份文件的正文格式、`AGENTS.md` 那句话的确切措辞，以及判断「内容有变化」的比较方式，全部留给 spec 阶段。本决定只定机制。
