### Authoring or modifying a skill

**You own the skill's voice.**

1. Use the [writing-for-agents](../../writing-for-agents/SKILL.md) skill to shape the skill, then the [create-skill](../../create-skill/SKILL.md) skill to draft it. Where the two differ, writing-for-agents decides.
2. Validate the skill: frontmatter has `name` and `description`, referenced files exist, cross-skill links resolve.
3. Test cases if structural. Skip if subjective.
4. Run **Opening a PR**.

Tell it to do the thing and skip the reason. Explain only when the rule is confusing without one. Match tone to scope. Point at structural sources (types, READMEs, config) per the [principle-encode-lessons-in-structure](../../principle-encode-lessons-in-structure/SKILL.md) principle skill. A workflow you keep hitting but isn't captured → propose a new skill.

**Reply:** summary of the skill, key design decisions, validation notes.
