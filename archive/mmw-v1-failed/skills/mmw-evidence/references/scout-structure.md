# `scout`：查代码结构

**谁读**：任务名是「查代码结构」的 `scout`。题目问的是模块边界、接缝、数据流。

下面六个词是全部，指同一样东西时从头到尾用同一个，换词就对不上。

| 词 | 指什么 |
| --- | --- |
| 模块 | 有接口和实现的任何东西：一个函数、一个类、一个包、一条跨层的切片 |
| 接口 | 调用方为了用对它必须知道的全部：类型签名，加上不变量、调用顺序约束、错误模式、必需配置、性能特征 |
| 实现 | 模块内部的代码本体 |
| 接缝 | 能在别处改变行为而不必改这里的位置——接口所在的地方 |
| 适配器 | 坐在接缝上、满足那个接口的具体东西 |
| 深 / 浅 | 深＝大量行为藏在小接口后面；浅＝接口几乎和实现一样复杂 |

三个判据，用来把看到的东西变成一条说得出出处的事实：

- **删除测试**：设想删掉这个模块。复杂度随之消失，它就是一个穿透层；复杂度在 N 个调用方那里重新出现，说明它承担了真实职责。
- **一个适配器是假接缝，两个才是真接缝**：只有一种实现在那里，这条接缝是设想出来的，并没有真正变化的东西。
- **依赖是注入的还是自己创建的**：模块在内部 `new` 依赖，它的接口就无法测试；依赖从参数传入，接口就是测试面。

写一个模块的依赖时点明是哪一类，四类是全部：

| 类 | 什么样 |
| --- | --- |
| 进程内 | 纯计算、内存里的状态，不碰 I/O |
| 本地可替身 | 有本地替身可以代替：PGLite 代替 Postgres、内存文件系统代替磁盘 |
| 远端但自家的 | 自己的服务，隔着一层网络：微服务、内部接口 |
| 真外部 | 管不着的第三方：Stripe、Twilio 这类 |

查完照角色文件那三节回：事实、小结、缺口。
