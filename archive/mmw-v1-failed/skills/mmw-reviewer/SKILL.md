## 线下 · 不是技能内容

**谁读这份**：`roles/reviewer-claude.md` 与 `roles/reviewer-gpt.md` 两个审者共用。哪一道审派谁、派几个是 `mmw-review` 的判断，起法见 `mmw-dispatch`。

**为什么按任务名切成七份，不按阶段切成四份**：每一道审都是两路视角，一个审者只负责一路。旧插件按阶段一份、每份含两路，审者装的一半是别人的活。

### 施工单

- **来源**：`plugin/skills/worktree-review/SKILL.md` 与 `references/method.md`
- **保留**：只读边界；看别的版本用 git 只读命令；代码差异用不可信标记包裹；一次审透，知道却没报就是审查失败；报全不等于报噪；放行标准（最终放行权在主线程）；先挑方向、再挑地基、最后过闸；复审轮规则；结构候选先行；防幻觉四件套；发现的字段与分级；返回合同要求每条带位置、严重度、置信度，不夹带修复动作；普适红线
- **删除**：视角名与引擎起审子命令的耦合；四份按阶段分的审查角度——已按任务名拆成 `references/` 下七份；跨计划合同门单列（角度并进终审）
