# MMW 重建 · 规格与生长记录

新插件不改造旧插件。它在一个新目录里从空白长出来，旧的 `plugin/` 原地不动继续可用，直到新的跑通一轮真实任务。

本文件是新插件的规格来源，随重建逐层生长。每层定完写进这里，之后写代码只照这里，不再回到讨论。配套的可视化面板与本文件同步更新，那里画形状，这里给精确值。

## 怎么一起干活

**一次一个技能。**动手前先说清：改哪一份、参考哪些材料、打算怎么写，等我确认。要扩大范围（新建目录、加脚本、改结构）同样先说，等确认。

**三处同步生长**：artifact 画形状、对话里直白说方案、这份文档记精确值。三处任一处改了，另两处跟着改——artifact 与文档不一致时，以文档为准，但不一致本身就是缺陷。artifact 要多用总结与图表，但不许为了少写字丢掉细节。

**汇报讲具体的东西，不讲数字。**「改了 6 个文件」没有信息。要说：改了哪个文件、为什么改、原理是什么、效果是什么。不用比喻，不预设我记得任何代码细节。用词精确——「让脚本从参数生成这句话」这种句子里，到底是一句话、一个参数还是一个变量，说清楚。

**不许提「先做最小版本跑通」。**旧 plugin 每一步都能跑通，问题只是太重。

## 反复犯的错

这几条是这次重建里已经出现过的，每一条都由我发现、而不是自己查出来的。下一次动笔前逐条对照。

**凭空想象。**不参考已有材料就自己编：编一个用户没要求的判断表、编一个宿主字段、编一套流程。判据很简单——**写进去的每一句都要能指回旧 `plugin/`、`vendor/mattpocock-skills/` 或宿主实测的某个具体位置。**指不回去的就是编的。

**一读旧材料就把删掉的东西搬回来。**读旧 `plugin/` 是为了取方法，不是为了照抄机制。凡是本文件写了「删掉」「取消」「没搬的」的东西，在旧材料里再遇到都不算缺口——场景预设、结论词、值守档、越界检查、步账、状态字，看见就绕开。**动手补一个「缺口」之前先在本文件里搜一遍，确认它不是被明确删掉的。**

**假装做过。**写「逐条比对过」「读完了」而实际没打开文件，是最严重的一种。没读就说没读。

**引用一份外部技能，只读了它的 `SKILL.md`。**`diagnosing-bugs` 底下有 `scripts/hitl-loop.template.sh`，`codebase-design` 底下有 `DEEPENING.md` 与 `DESIGN-IT-TWICE.md`——我没打开过，却把「没摘的」清单写得像通读过。**动笔写「摘了什么、没摘什么」之前，先 `ls -R` 那个技能目录，每个文件都打开。**上游把材料沉进支撑文件，正是因为那部分展开了讲；只读入口等于只读了目录。

**搬上游的时候把它自己标了分量的地方降了级。**`diagnosing-bugs` 用整段话说 Phase 1「就是这份技能本身，其余都是机械劳动」「花不成比例的力气在这里」，我搬成了一句「判断这个 bug 能不能稳定复现」——主动造回路变成被动判断题。**上游用加粗、用「this is the skill」这类话标出来的重心，搬过来必须还是重心。**要改分量得说明为什么，不能顺手压平。

**断言某个角色做不到某件事，却没读过它的角色文件。**我以「取证只读」为由砍掉了上游十种造回路的办法，可只读的意思只是写不了盘，`scout` 打 curl、比对命令输出、读提交历史全都做得到。**说「他做不了」之前，先打开 `roles/<角色>.md` 看 `write` 那个参数到底管住了什么。**真正做不到的划出去，做得到的留下。

**戳一下动一下。**指出一句改一句，不拿同一把尺子把整份重扫。指出「先说交付再说怎么干」，就只调那一处，不去查同一份里还有几处前向引用。**每接到一次指正，先把它抽象成一条判据，再拿这条判据扫完当前这份文件的每一节。**

**抄完一份再抄另一份。**两份来源要同时在眼前对着写，不是先照 A 写一版、再照 B 改一版——那样只会来回删改，永远收不了口。

**为不存在的威胁造机制。**给工人设可写路径白名单、给正常改动判违规、造一套反规避层——工人拿计划写代码，没有动机去改设计文档。**判据：这个机制拦的是谁、他为什么会那么干。**答不上来就不要造。

**角色混乱。**你说这是我最经常犯的错。症状是技能正文里的「你」指谁没写死——一会儿指主线程、一会儿指被派出去的工人、一会儿指读这份文件的任何人；派发提示词里整段引用别处的文字，那段里的「你」跟着换了人也不改。**每写一步先答四问：这一步是谁在干、他要读什么、他要做什么、他要把东西输出到哪。**四问答不齐就是没写清。伴生的一种是拿自己脑子里的上下文当读者的上下文——我知道所以以为他也知道，于是该给的不给。

**明知读者是两类，还合成一份让他们自己认领。**`mmw-evidence` 里造信号是主线程的活、收回执是主线程的活，我却把它们留在同一份正文里，靠一句「这是主线程的活，`scout` 跳过」交代。**读者身份在进门时就已知的，直接一类读者一份文件**，重复几张表也认。这是角色混乱的同一个病根换了张皮。

**切文件时不算上下文这笔账。**按读者拆完，我把主线程那三件活又焊回了一份 200 行的巨石——来收一下回执的主线程，被迫连造信号那四十行一起装进上下文。**技能是渐进加载的：`SKILL.md` 人人都装，`references/` 谁用到谁才打开。**所以每开一份文件先问：读它的那个代理，这一步用不用得上里面的每一节；用不上的另开一份。这条跟「长度按内容判」是同一把尺，只是量的是别人的上下文，不是我的篇幅感。

**长度按内容判，不按行数判。**一份技能写到 30 行被你说随意，写到 130 行被你说臃肿，两次的病根是同一个：拿行数当目标。**判据只有一条——这句话读它的那个代理这一步用不用得上。**用得上就留，写到两百行也留；用不上就删，三十行也嫌长。

**越过当前进度做后面的事，或者为极端边缘情况造机制。**这一层要什么就做什么，下一层的事下一层做。想加的东西如果只在一种很少见的情形下才有用，那就先不加——真撞上了再加，比现在就把它写进去便宜。

**手上有 `Edit` 却去写 Python 脚本改文件。**多一层间接、断言挂了整批替换全不落盘、还看不见改前改后。**改文件就用 `Edit`。**

**在真仓库、真机上跑验证动作。**第一次是在主仓库直接跑开任务脚本，建了工作树、建了分支，脚本还替我提交了一个改动，全部得手工回滚。第二次更隐蔽：安装脚本的沙盒靠一个环境变量指路，而 Bash 工具的环境变量不跨调用留存，第二次调用时那个变量已经空了，脚本回退到真实仓库路径、读到真实的宿主目录，在用户的个人技能目录里装了二十七条软链。**任何会写盘的验证一律在临时目录里跑：整段验证放进同一次命令调用，并且把 `HOME` 也一起指到沙盒——只指仓库路径不够，脚本读得到宿主目录就写得进去。**

**引了官方文档的一句话，没核它管的是哪个场景。**插件根占位符那条写进规格时引的是官方替换表里一行「技能与角色内容里都会替换」，看着完全对得上；漏掉的是同一份文档另一句「它指的从来不是个人配置目录」。我们的技能是软链进个人技能目录的，占位符在那里根本不生效，整条规格是错的。**引一句话之前先读完它周围那一节，确认我们的用法落在它管的范围内。**这不是「没查文档」，是查了半句。

**把该给读者的东西藏起来，把不该给的堆上去。**提示词内容藏进 shell、格式规则藏进脚本，读技能的人永远找不到。反过来，历史记录、设计理由、禁令、反例堆进技能正文，读的人用不上。**站在这份文件的读者角度：他眼前只有这一份，他要知道什么。**

**把这份文件里的说法搬进插件。**「九格」「格」「第几层」「施工单」「线上线下」都是重建期这边的说法，插件里没有这些词，读技能的代理也从来没读过这份文件。插件里只有阶段名和技能名。

**不做穷尽检查，或者查了不修。**同一类问题在一个地方被指出后，不去查别处有没有同样的；查出来了又只列成清单交给我，等我发话。改完一处先 grep 全仓有没有同样的写法，**扫出来的当场一起修**。只有两种情况才停下来问：改动会变动产品语义，或者要动的东西属于还没轮到的那一层。「这份技能还挂着施工单」不是理由——事实性缺陷（路径找不到、角色指错、指代落空）跟方法论填没填完无关，看见就修。

**让代理去猜命令怎么敲、文件在哪。**写「自己调 `mmw-back` 回探路」，代理得先猜「探路」是不是这条命令收的参数；写「这份技能自带的 `scripts/…`」，它拿不到能跑的路径。**要它敲什么就把整条写出来（`/mmw-back 探路`），要它读什么就给能直接用的路径（`~/.mmw/scripts/…`）。**口水话既多花 token 又留下一次猜。

**自造一个名词就当读者已经懂了。**正文里写「连挡路关系」，代理并不知道这四个字落到纸面上是写什么——那个记法 `等：<挡它的决策名字>` 只藏在另一份文件的骨架注释里，而每个会话都读 `SKILL.md`，不一定会打开那一份。**技能里出现的每个自造说法，第一次用就当场兑现成代理照着能写出来的字**；兑现不了的说明它只是我脑子里的概念，删掉换成动作。这是「让代理去猜命令怎么敲」的同一个病：那次猜的是参数，这次猜的是写什么字。

**改完不看邻格。**把起图搬进 `map.md`，上面那张表的表头还写着「骨架」，而那份文件已经不只有骨架了。**每改一处就把指向它的地方全看一遍**——表头、目录说明、线下区里解释它的那段。

**捡芝麻丢西瓜。**只改被指出的那一处，不管这个改动有没有让规格、artifact、相邻技能失效。**每次改完问一句：这次的改动让哪份文档过期了。**
